# E03-B：共享资源冲突下的多头关系协调（预注册）

状态：设计阶段；尚未实现、运行或验证。  
基线来源：E03-A `b6606ae754e2e46af6953fe4a7faddf388e7e8a1`。  
隔离原则：本实验使用独立分支，不改写 E03-A，也不修改其他 AI 正在使用的 E02 分支。

## 1. E03-A 留下的关键缺口

E03-A 的三个目标成员集合为：

- (0, 2, 5)
- (2, 5, 7)
- (0, 4, 7)

它们的特征并集恰好是 5 个，而共享预算也是 5。因此，即使三个输出头完全独立地选中真实关系，独立解也必然满足预算。已报告的 30/30 seeds 独立解满足预算，并不是协调器有效的证据；它说明原任务没有制造活跃的资源冲突。

E03-B 不把“协调器必须赢”作为设计前提。它只制造一个可检验的必要条件：在冲突组中，独立最优候选的并集可能超过预算；同时候选空间中仍可能存在可行联合解。若数据和候选池没有产生这种情形，该 seed 必须计为“未形成有效冲突”，不能从统计中悄悄剔除。

## 2. 研究问题与可证伪假设

**主问题：** 当多个输出头各自选择局部最优关系会争用共享特征预算时，联合协调是否能在相同候选池、相同 Gate 信息和相同计算预算下，提高预算可行性，并减少相对于可行 Oracle 的性能损失？

预注册假设：

- H1（冲突存在）：冲突组中，独立局部最优解违反共享预算的比例显著高于无冲突控制组。
- H2（可行解存在）：在冲突组中，存在至少一个满足预算的联合候选组合；若不存在，该 seed 不用于声称协调收益，但仍计入可行性报告。
- H3（协调质量）：全局联合选择相对独立后修复、逐头贪心和随机可行选择，在锁定 Test 的总效用及最差头效用上具有可重复优势。
- H4（无冲突控制）：当独立局部最优解本来满足预算时，协调器不应显著损害总效用或单头效用。

任何一项未达到预注册标准，都应报告为未支持，不得改写假设或只展示有利 seeds。

## 3. 实验组

### A. 冲突组

- 8 个二值特征、3 个输出头。
- 每个头由独立抽样的二阶/三阶非连续或连续成员集合生成隐藏规则。
- 目标成员集合在生成时受约束：独立真实成员并集通常大于预算，但头之间允许部分共享。
- 候选语言、候选排序和 shortlist 规则与 E03-A 保持同一实现；首轮保留每头训练排名前 8 的候选。
- 预算首轮扫描 4、5、6；不允许只报告最容易制造冲突的预算。
- 不人为把真实候选从 shortlist 删除，也不根据 Test 结果调整目标集合。

### B. 无冲突控制组

- 数据生成、头数、噪声、候选语言和 Gate/Test 样本量保持一致。
- 目标成员并集不超过预算，使独立局部最优解在结构上有机会直接满足预算。
- 用于检测协调器是否因联合搜索或评分机制引入不必要损害。

### C. 冲突强度扫描

至少报告三档：轻度（独立解略超预算）、中度、重度（明显超预算）。冲突强度按独立解特征并集超额数定义，而不是按最终测试表现定义。

## 4. 对照算法

所有方法共享完全相同的每头候选池、训练排序、Gate 样本、Gate 查询次数上限和锁定 Test：

1. **Independent-top1**：每个头独立选择 Gate 分数最高的候选；不施加预算，作为冲突诊断基准。
2. **Independent-then-repair**：先独立选择，再以预注册的最低 Gate 损失替换策略修复超预算；不得查看 Test。
3. **Greedy-joint**：按边际 Gate 效用/新增特征成本逐头选择，至少轮换头顺序，报告顺序敏感性。
4. **Global-joint**：在相同 shortlist 上枚举预算可行组合，最大化预先定义的联合 Gate 目标；同分规则固定。
5. **Random-feasible**：从所有可行联合组合中按固定随机种子抽样，建立可行解质量基线。
6. **Oracle-feasible**：仅用于合成实验上界。Oracle 可访问生成器真值，但不得用于训练/选择算法；明确标记为不可部署上界。另报告基于 Gate 的可行最优值，不能把 Oracle 与可部署算法混为一谈。

若 shortlist 8^3 的穷举可行，Global-joint 计算预算应明确记账；其他方法也要报告候选评估数和 Gate 查询数，避免只给协调器更多信息。

## 5. 数据隔离与指标

- Train：生成候选和训练排序。
- Gate：调参/候选选择/预算协调。
- Test：结构、算法、阈值全部锁定后只评估一次；Test 不得反馈到任何选择过程。
- 使用至少 30 个预先固定 seeds；若统计功效不足，追加 seeds 的规则必须在看 Test 前写明。
- 报告每个 seed、每个头的成员恢复、完整规则恢复、Test accuracy、联合效用、最差头效用、特征并集大小、预算违反率、可行联合解存在率、协调计算量。
- 报告冲突组与控制组分层结果、配对差值、95% bootstrap 区间；同时保留失败 seed，不只报告均值。
- 公开配置、数据生成版本、代码 commit、seed 列表、数据/配置 hash 和完整原始 JSON。

## 6. 主要失败模式与防作弊约束

- **冲突不足：** 若 Independent-top1 不超预算，计入冲突发生率，不把该 seed 伪装成冲突实验。
- **无可行解：** 明确报告不可行，不让 Global-joint 通过放宽预算或删头“获胜”。
- **候选池截断偏差：** 同时报告 shortlist 4/8/16 的敏感性；候选池不足时不得将失败归因于协调算法。
- **目标泄漏：** 目标成员与真值只允许 evaluator 使用；协调算法输入不得包含隐藏目标。
- **Test 泄漏：** Test 仅由最终锁定脚本读取；禁止按 Test 表现选择预算、种子或超参数。
- **不公平计算：** 报告每种方法的候选打分次数、Gate 样本访问量、联合组合评估数和运行时间。
- **只展示成功案例：** 所有 seeds 和全部实验组必须输出，失败、未冲突、不可行都要保留。

## 7. 通过标准（待代码实现前固定）

只有同时满足以下条件，才可声称 E03-B 支持“共享资源冲突下联合协调有收益”：

1. 冲突组中独立解预算违反率明显高于无冲突控制组；
2. 冲突组中有足够比例的 seed 存在预算可行联合解；
3. Global-joint 在锁定 Test 的联合效用上优于 Independent-then-repair、Greedy-joint 和 Random-feasible，且配对 95% 区间支持该差异；
4. 最差头效用没有通过牺牲单一输出头换取总分提升而发生不可接受的下降；
5. 无冲突控制组不出现系统性损害；
6. 候选池大小和预算敏感性结果不推翻主结论。

阈值、最小效应量和统计检验在运行正式 Test 前，由独立审阅者确认并记录在配置中。若未事先固定这些数值，只能称为探索性结果。

## 7.1 锁定统计判据（在实现和正式 Test 前固定）

为避免“显著/足够/不可接受”等词在看完结果后被重新解释，首轮正式实验采用以下固定判据：

- 固定 seed：冲突组和控制组分别使用 `3000..3029`，每个 seed 在两组中配对；不得因结果不利而替换 seed。
- 主指标：每个 seed 的三头平均 Test accuracy；辅助指标为最差头 Test accuracy、精确成员恢复率和精确规则恢复率。
- 冲突操纵有效：冲突组 Independent-top1 预算违反率至少 70%，控制组不高于 10%；两组违反率差至少 60 个百分点。未达标时报告操纵失败，不进入“协调有效”结论。
- 可行性：冲突组至少 80% seeds 必须存在预算可行的 shortlist 联合解；其余 seed 保留并计入不可行率。
- 主效应：Global-joint 相对 Independent-then-repair、Greedy-joint、Random-feasible 三个对照的配对 Test accuracy 差值，均须达到至少 +0.02 绝对值；每个差值的 95% 配对 bootstrap 区间下界须大于 +0.01。
- 多重比较：三项主比较使用 Holm 校正，双侧家族错误率 0.05；bootstrap 固定 10,000 次，重采样单位为 seed，不能把同一 seed 的三个头当作独立样本。
- 最差头保护：Global-joint 相对每个可部署对照的最差头 accuracy 差值，95% 配对区间下界不得低于 -0.02。
- 无冲突非劣：控制组 Global-joint 相对 Independent-top1 的平均 Test accuracy 差值，95% 配对区间下界不得低于 -0.01。
- 稳健性：shortlist 4/8/16 与预算 4/5/6 全部报告。主结论以 shortlist=8、预算=5 为主分析；其余只作预先声明的敏感性分析，不得挑选最有利组合替代主分析。
- 缺失/异常：任何 seed 运行失败都按失败记录并公开原因；不得静默删除。除非代码或数据损坏有独立、与结果无关的证据，否则不得重跑替换。

若主效应未同时达到效应量、区间和 Holm 判据，只能报告未支持或探索性结果。所有阈值在正式 Test 解封前保持不变。

## 8. 当前结论边界

本文件只是实验预注册，不代表 E03-B 已实现或取得结果。E03-A 目前只证明有限合成布尔任务中的并行候选生成与非连续关系恢复可行；它没有证明全局协调优于独立选择。E03-B 的目的正是把“协调是否必要、是否有收益”变成一个可失败的实验问题。
