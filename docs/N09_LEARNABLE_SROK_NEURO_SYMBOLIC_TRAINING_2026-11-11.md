# N0.9：可学习稀疏关系组合器与神经—符号协同训练协议

日期：2026-11-11  
状态：研究设计草案；尚无神经模型实现、训练结果或性能结论。  
上游：N0.8 SROK-0 确定性内核。  
目标：把可学习能力逐步引入 SROK，而不破坏可审计性、硬约束、安全拒答和预算可控性。

## 0. 核心决定

N0.9 不直接训练一个端到端黑箱来替代 SROK-0。采用分层的神经—符号协同结构：

1. 神经观察编码器：把输入观察编码为带类型、属性、上下文和证据来源的节点表示。
2. 可学习角色检索器：根据 Operator/Role 查询，为每个角色产生候选节点分数与召回列表。
3. 确定性结构求解器：在候选池上执行角色唯一性、类型、标签、时间和其他硬约束，并在明确预算内枚举候选。
4. 神经联合评分器：对完整角色绑定结构进行联合评分，显式建模不可由独立节点分数相加表达的交互。
5. 证据校验与提交边界：硬约束、来源校验、冲突处理和状态提交仍由确定性组件执行；神经网络不能覆盖硬约束。
6. 证据驱动更新：只有经过 evaluator 揭示的有效反馈，才可进入 learner 更新路径。

SROK-0 保留为永远可运行的确定性基线和回退路径。N0.9 的目标不是证明神经模块更好，而是找出哪些可学习替换在相同数据、搜索预算和评估器下带来可重复增益。

## 1. 最小计算图

输入 ObservationSet + OperatorSpec
→ NodeEncoder
→ RoleConditionedRetriever(role, context, operator)
→ Top-K typed role pools
→ SROK constrained assignment enumerator
→ JointStructureScorer
→ Constraint/Evidence Validator
→ CandidateSet + SearchReport + Provenance

### 1.1 NodeEncoder

输入字段至少包括：
- 原始观察或其外部编码引用；
- node_type、属性、时间范围、来源和可信状态；
- 可选的领域/任务上下文；
- 证据 ID 与数据版本。

输出：
- 连续向量；
- 类型与属性的显式结构字段；
- 不确定性/缺失标记；
- 原始证据引用。

不得把证据来源、测试标签或 evaluator 私有字段编码进 learner 可见特征。缺失值必须显式表示，不能静默填成“否”。

### 1.2 RoleConditionedRetriever

对每个角色 r，计算：
score(node, r, operator, context)。

建议先使用轻量双塔/MLP 评分器：节点向量与角色/算子向量做投影、双线性匹配或小型交互网络。不要在第一版引入大型 Transformer 编码器，以免无法判断收益来自组合机制还是预训练规模。

检索器必须输出：
- 每个角色的排序候选；
- 每个候选的分数；
- 被类型/标签硬过滤的原因；
- Top-K 截断信息；
- 正确角色节点是否进入池的 recall 统计。

类型、必要标签和授权范围优先作为硬过滤；可学习分数不能把不兼容节点重新放入池中。

### 1.3 结构求解器

继续复用 SROK-0 的角色池与预算报告，不另造第二套组合引擎。

求解阶段必须执行：
- 角色唯一性与互斥；
- 类型/标签/时间/作用域约束；
- 完整组合硬约束；
- 最大扩展数与候选上限；
- 可重放的稳定排序；
- 证据 ID 去重和 provenance 聚合。

第一版只允许神经检索器改变候选池排序，不允许它修改硬约束语义。候选池截断是主要召回瓶颈，因此必须单独报告 retrieval recall@K 与最终 exact match，不能只报告最终准确率。

### 1.4 JointStructureScorer

对完整角色绑定结构计算：
E(candidate) = sum(role_scores) + interaction_score(candidate)。

interaction_score 必须看到完整角色绑定及必要上下文，才能学习三元及更高阶协同。它不能只把各节点分数重新相加。

第一版采用小型 MLP/低秩张量交互或显式角色交叉特征；按参数预算与计算预算比较。若采用 pairwise interaction，必须增加真正需要三元及以上交互的任务，避免模型通过成对捷径完成全部任务。

任意联合评分器不具备可采纳的上界时，当前 best-first 搜索不保证全局 top-k。可选解决路线：
- 学习器仅重排有限候选，再明确报告候选召回边界；
- 为联合能量设计 admissible upper bound；
- 对小规模实例使用精确 branch-and-bound/oracle；
- 研究约束传播与 anytime 搜索。

不得把“搜索到的 top-k”写成“全局最优 top-k”，除非证明条件成立。

## 2. 训练目标与监督信号

按阶段训练，不在第一轮混合所有目标。

### L1：角色检索监督
- 每个 role 的正例节点与类型相容的 hard negatives；
- sampled softmax / pairwise ranking / listwise ranking；
- 报告 Recall@K、MRR、候选池覆盖率；
- 按实体、关系模板和领域分组留出。

### L2：结构级监督
- 完整角色绑定 exact match；
- 结构级 listwise ranking；
- 对错误角色交换、缺失角色、重复角色和错误成员设置 hard negatives；
- 评分器须区分“成员相同但角色错配”的结构。

### L3：高阶协同监督
构造保留二元投影的高阶必要任务。正负样本的成对统计尽量匹配，只有正确的多角色联合结构能区分标签。
比较：
- 节点分数相加；
- pairwise scorer；
- ternary/higher-order joint scorer；
- 正确角色绑定；
- 角色置换与高阶分组扰动。

### L4：校准与拒答
- 不完整证据、候选并列、分布外结构和预算耗尽；
- 训练/校准 UNKNOWN、ABSTAIN 或 NEED_MORE_EVIDENCE；
- 报告 risk-coverage、selective accuracy、ECE/Brier；
- 不允许为了降低拒答率而把不确定预测强制变成确定结论。

### L5：增量学习
通过 E09 prequential 协议：先提交预测，再由 evaluator 揭示观察，最后更新 learner。更新后记录模型版本、结构版本、证据引用和受影响候选。
不得使用训练集生成器的隐藏标签直接更新，也不得让 learner 访问测试答案。

## 3. 易象与类象先验的接入边界

易象不能被简化成“六十四卦 ID Embedding”，也不能作为不可撤销的硬规则。

建议将其拆成可检验的算子候选：
- 对偶/互补关系；
- 相反/制约关系；
- 位序与角色位置；
- 条件与时位；
- 状态转移/卦变；
- 多阶段变化；
- 类象对应与结构保持映射；
- 五行关系作为带方向、带条件的关系假设。

每种算子都必须有输入类型、输出类型、前置条件、后置条件、证据来源和失败状态。类象映射只提出候选，不自动证明因果或本体同一。

必须比较五组：
1. 无易象先验；
2. 随机置换先验；
3. 通用类型/关系先验；
4. 易象派生算子先验；
5. 反向或错误映射先验。

所有组匹配参数量、候选预算、训练数据和搜索预算。只有易象先验在 held-out 结构、跨领域迁移和反例测试中稳定优于对照，才可认为有增量价值。

## 4. 强制基准矩阵

### 4.1 任务族
- 简单属性合取：仅作 sanity check；
- 非相邻组合：组合跳过无关元素；
- 角色绑定：同一成员集合、不同角色映射；
- 高阶必要：二元投影无法区分；
- 离路径约束：答案依赖不在目标路径上的证据；
- 多路径汇合：需要合并独立证据路径；
- 规则族 OOD：测试规则模板不出现在训练集；
- 对象不相交 OOD：测试实体不出现在训练集；
- 领域迁移：源域训练、目标域测试；
- 动态机制：上下文/动作/状态改变后结构应改变；
- 欠定与冲突：必须拒答或请求区分性证据。

### 4.2 对照系统
- SROK-0 确定性基线；
- 仅节点分数相加的检索+组合；
- 强二元关系网络；
- pairwise GNN/超图模型；
- N0.9 神经检索 + 确定性求解；
- N0.9 神经检索 + 联合评分；
- 可选的参数量/计算预算匹配 MLP 与 Set/Graph 模型。

不得把不同训练数据、候选池规模或搜索预算的结果直接比较为架构胜负。

### 4.3 高阶归因干预
至少包含：
- 原始高阶角色结构；
- 保留二元投影、破坏高阶分组；
- 角色置换；
- 随机高阶重连；
- 强二元加权/多步传播基线；
- 高阶冗余任务与高阶必要任务分开。

若高阶模型在破坏高阶信息后仍保持大部分优势，应优先调查低阶捷径，而不是宣称高阶认知成功。

## 5. 数据隔离与评估可信性

- generator、learner、evaluator 分离；
- 规则族/模板/实体/领域分组切分，不做纯随机样本切分；
- 测试实例可在训练完成后由独立 evaluator 在线生成；
- evaluator 私有标签不进入 learner DTO；
- 预测提交先于标签揭示；
- 每次实验记录 commit、数据生成器版本、种子、配置、预算和模型权重摘要；
- 失败、拒答、候选遗漏和预算耗尽都必须保留；
- CI 通过只证明代码测试通过，不等于模型能力或统计优势成立。

## 6. 资源与性能报告

每个实验至少记录：
- 参数量、训练步数、训练耗时；
- 节点数、角色数、候选池大小、扩展数；
- 检索 Recall@K、结构 Exact Match、角色 F1；
- 候选数、预算耗尽率、UNKNOWN/ABSTAIN 率；
- p50/p95 延迟、吞吐、峰值 RSS/显存；
- 每个正确结构的计算成本；
- 证据更新后的局部重算比例。

主要优化目标不是单一准确率，而是质量—计算—记忆三维 Pareto 前沿。

## 7. 进入神经训练的门槛

### 可启动小型模块训练
1. SROK-0 测试与 CI 结果已核实；
2. 独立 evaluator 和 learner 输入边界可验证；
3. 训练/验证/测试按结构模板隔离；
4. 至少一个高阶必要任务与强二元 hard baseline；
5. retrieval recall 与最终结构准确率分开测量；
6. 所有实验可由 commit、seed、manifest 复现。

### 可声称模块有效
1. 多种子配对实验；
2. 预注册主指标和多重比较处理；
3. 高阶扰动归因；
4. 对象、规则模板、领域至少两种 OOD；
5. 不以增加预算或降低拒答换取表面准确率；
6. 结果在独立复现实验中保持。

### 不属于本阶段
- 不训练大型语言模型；
- 不宣称替代 Transformer；
- 不宣称开放世界语义理解已解决；
- 不把有限域 oracle 结果外推为真实世界因果发现；
- 不把易象先验的拟合效果解释为传统理论已被证明。

## 8. 推荐实施顺序

1. 冻结 SROK-0 API 与报告结构，补充属性/时间/作用域约束测试。
2. 建立可执行的结构数据生成器与独立 evaluator。
3. 实现 RoleConditionedRetriever，先只训练检索器。
4. 测量 Recall@K—预算曲线，确定可接受的候选池大小。
5. 在固定候选池上训练 JointStructureScorer。
6. 加入角色交换、pairwise-preserving hard negatives 和高阶归因干预。
7. 接入 E09 预测—揭示—更新协议。
8. 最后再试易象算子先验和跨领域类象迁移。

## 9. 当前结论

N0.9 将研究重点从“再增加一个认知模块”转向“逐个替换确定性内核中的可学习决策点”。

第一个真正值得训练的模型不是完整 CPG-EI，也不是语言模型，而是一个小型的、角色条件化的结构检索器。它的任务边界清晰，训练信号可构造，召回率可测量，并能直接接入现有 SROK-0。

只有当检索器和联合评分器在强对照、结构 OOD、高阶归因和固定预算下取得可复现增益，才继续扩大到完整神经认知工作空间。

本文件是研究协议，不代表实现、CI、训练或性能结果已经完成。
