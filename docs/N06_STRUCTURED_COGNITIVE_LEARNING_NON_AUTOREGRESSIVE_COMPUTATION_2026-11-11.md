# N0.6：结构化认知学习与非自回归内部计算

日期：2026-11-11  
状态：研究设计 / 叠加于 ZPCM N0.5；不是已训练模型或性能结论。  
上游：PR #176，N0.5 head `a5ace19e27928c0e20f490ea478650a825ae937f`

## 0. 研究问题与结论先行

N0.6 研究模型如何在语言生成之前形成、组合、比较和修订内部认知结构。

本阶段不把“非自回归”简化成并行预测更多 token，也不把某一种现成架构直接认定为最终答案。建议研究一个分层混合架构：

**Typed Relational Latent Workspace (TRLW)：类型化关系潜在工作空间**

它以有限数量的结构槽位、关系超边、假设分支和可学习算子为计算对象；通过稀疏关系消息传递、共享参数的循环状态更新、全局约束能量评估和候选分支选择，进行有界的内部计算。最后才由语言解码器把经过验证的认知结构表达成文本。

TRLW 是待验证的研究提案，不是已证实优于 Transformer 的架构。

## 1. 研究边界：四类路线不能混为一谈

### A. 非自回归文本生成
一次预测多个 token 或对整段文本迭代去噪。优点是并行；困难是离散文本的全局一致性、少步采样质量和误差修复。

### B. 潜在空间迭代推理
中间计算保留为连续状态，不必把每一步写成 token。可以通过循环模块增加 test-time compute，但潜在状态可解释性和训练稳定性仍需研究。

### C. 结构化组合推理
中间状态是有类型的实体、关系、角色、约束和程序模块。可以显式跳过非必要元素、重用子结构和维护多条候选路径。

### D. 非 Transformer 主干
例如状态空间、递归网络、图网络、能量模型或其他算子网络。它们改变信息传播和计算成本，但并不自动解决组合泛化、记忆、学习目标或认知一致性。

N0.6 的主轴应是 C；B 提供连续状态迭代，D 提供可替换计算内核，A 主要用于最终语言表达。不要因为采用扩散或 GNN 就宣称已经得到新认知架构。

## 2. 研究证据与启示

代表性工作提供了可借鉴的部件：

1. Diffusion-NAT 将离散扩散去噪与非自回归文本生成结合，展示了并行恢复 token 的路径，但其主要计算对象仍是文本序列。
2. Energy-Based Diffusion Language Models 使用全序列能量模型改进离散扩散近似，并提出并行重要性采样；提示全局能量评估可以作为候选结构的评分机制。
3. NeurIPS 2025 的 Scaling up Test-Time Compute with Latent Reasoning 通过循环深度在潜在空间增加测试时计算，展示了不必把额外推理全部转成更多 CoT token 的方向。
4. NeurIPS 2025 的 CaDDi 通过整条生成轨迹条件化，缓解仅依赖当前状态的离散扩散 Markov 假设限制，强调历史状态可回看和修订。
5. Findings EMNLP 2026 的 Latent Recurrent Thoughts 研究小型循环推理器反复修订连续潜在状态，再交给冻结 LLM 解码。
6. EMNLP 2026 的 TYLER 研究类型化潜在算子以及何时调用、调用哪种计算、分配多少预算。
7. ICML 2026 的 compositional generalization 研究强调可复用原子技能与路由机制的组合学习，提示训练必须覆盖新组合而不只是模仿完整轨迹。

这些成果支持“潜在迭代、全局能量、类型化算子、组合模块、预算控制”的研究动机，但没有任何一篇直接证明 TRLW 有效。

## 3. TRLW：类型化关系潜在工作空间

### 3.1 核心计算对象

一次认知任务不建立无限长 token 序列，而建立有界工作空间：

`W = (S, R, H, C, P, M)`

- `S`：typed slots，实体、属性、事件、状态、目标等潜在槽位；
- `R`：typed relations / hyperedges，关系、角色和多元关系；
- `H`：hypothesis branches，多条候选解释/计划；
- `C`：constraints，时间、角色、范围、因果、逻辑和权限约束；
- `P`：provenance，来源与版本引用；
- `M`：operator memory，已学得的可复用局部计算模块。

每个 slot 保存：
- 连续表示向量；
- 离散类型分布或类型 ID；
- 来源引用；
- epistemic state；
- 局部置信/不确定性向量；
- 生命周期与任务作用域。

关系不是普通 embedding 拼接，而包含端点、角色、方向、时间、极性、基数约束和证据引用。需要支持超边，以表达多前提关系。

### 3.2 稀疏关系交互

只让相关节点和关系交换消息。候选边由检索、类型兼容、类象算子或学习型路由器提出；硬约束先过滤明显非法边。

每轮计算成本目标从稠密全连接的 (O(N^2d)) 转向稀疏近似 (O((N+E)d))，其中 N 是活动槽位数，E 是活动关系数。此为计算目标，不代表任何具体实现已达到该复杂度或速度。

不能把所有历史节点放入 W。ZPCM 负责持久化；N0.5 检索与 Context Compiler 选择本轮活动子图；TRLW 只处理活动工作集。

### 3.3 循环状态更新

用共享参数的迭代算子更新状态：

`W_{t+1} = F_θ(W_t, Q, B_t)`

其中 Q 是任务约束，B_t 是当前计算预算/控制信号。

每轮可以：
- 更新槽位表示；
- 新增或删除候选关系；
- 分裂或合并假设分支；
- 修改关系角色；
- 请求更多证据；
- 标记不确定或停止。

迭代深度由 MCRL 分配。循环次数不是固定“思考 token 数”，而是受任务价值、残余约束和资源预算控制。

### 3.4 多候选分支

候选不是多个完整答案文本，而是多个结构状态：

`H = {h₁, h₂, …, hₖ}`

每个分支共享只读证据和底层表示，分支差异只保存 delta，避免复制整个工作空间。

分支操作：
- fork：在关键假设或映射不同处创建分支；
- refine：对分支局部状态迭代更新；
- compare：使用共同约束与反证比较；
- merge：仅合并兼容且可追溯的结构；
- prune：依据硬约束、支配关系和预算剪枝；
- preserve：保留高价值但未决分支。

禁止仅按模型自评分淘汰候选。剪枝必须记录原因，支持恢复或审计。

## 4. 全局能量与约束求解

为每个候选结构定义可分解能量：

`E(h|Q) = E_type + E_relation + E_temporal + E_scope + E_provenance + E_contradiction + E_complexity + E_prediction`

能量项解释：
- type：类型与角色兼容性；
- relation：关系模式匹配；
- temporal：时间顺序和有效期；
- scope：对象、空间、任务和权限范围；
- provenance：来源质量及相关性；
- contradiction：与已验证事实冲突；
- complexity：不必要假设与结构复杂度；
- prediction：候选对可检验观察的预测能力。

硬约束不应只转成软惩罚。违反不可放宽的硬约束时，候选应拒绝或隔离。能量只用于可比较候选的排序和优化，不直接等同于事实概率。

可研究两阶段求解：
1. 确定性约束求解器执行类型、时间、权限、版本和逻辑硬约束；
2. 学习型能量模型对剩余可行候选排序，配合反证和校准数据训练。

## 5. 易象 / 类象如何进入模型计算

易象不能成为每个节点附加的八卦类别，也不能把古典术语强行一一映射到现代算子。建议将其作为一组**可学习、可组合、可被反例修正的结构变换假设**。

| 概念 | TRLW 中可学习的结构操作 | 学习约束 |
|---|---|---|
| 取象 | 从观察提取关系角色与不变量 | 保留来源和遗漏 |
| 类象 | 跨域结构对齐 | 关系保持与差异辨识同时训练 |
| 变 | 局部状态/关系变换 | 条件触发、变前变后版本 |
| 互 | 从内部关系重组子结构 | 允许非相邻选取 |
| 错 | 对照或极性翻转 | 明确变换轴与不变量 |
| 综 | 视角/方向重组 | 检验可逆性和信息损失 |
| 应 | 远距离角色呼应 | 跨位置一致性约束 |
| 时 | 时间阶段和窗口变换 | valid-time 与先后关系 |
| 位 | 角色、层级和位置约束 | 角色类型及结构位置 |

每个算子由 `OperatorSpec` 描述：
- 输入/输出类型；
- 可变维度；
- 保持不变量；
- 适用条件；
- 反例条件；
- 复杂度；
- 参数版本；
- 训练来源与验证结果。

先学习结构变换是否有用，再研究传统术语是否能为变换族提供有效归纳偏置。不可预设每个术语都必须成为一个独立神经模块。

## 6. 非相邻组合与组合泛化

必须把“跳过中间元素”写进训练任务，而不是只在推理阶段开放组合器。

训练样例应包括：
- 从 `a,b,c,d,e` 选择 `a,b,c,e`；
- 从两个不同关系簇中选取互补角色；
- 从不同会话和时间段选取同一对象的有效证据；
- 组合两个已学模块解决训练中未出现的结构；
- 允许一个节点不参与，且模型需要解释为何跳过；
- 对相似但错误的组合生成反例。

训练集划分必须按组合结构、角色映射和关系模板隔离，避免相同组合只换表面实体而泄漏到测试集。

## 7. 学习目标：从下一个 token 扩展到结构状态

N0.6 不是简单废弃 token prediction。语言生成仍可保留自回归目标，但认知主干增加以下训练目标：

1. **结构恢复**：从部分遮蔽/损坏工作空间恢复实体、关系和约束。
2. **关系预测**：预测缺失关系、角色和方向。
3. **结构对比**：区分有效结构与最小反例。
4. **组合泛化**：把已学算子组合成未见过的推理结构。
5. **状态转移**：预测观察到来后哪些槽位/关系应该更新。
6. **多路径维护**：训练保留多个解释，避免单路径过早坍缩。
7. **来源归因**：识别共享祖先和重复证据。
8. **反事实区分**：预测不同假设下哪些观察会不同。
9. **停止控制**：学习何时继续计算、检索或停止。
10. **语言对齐**：把最终结构准确解码为语言，不让流畅度替代正确性。

联合损失可先定义为：

`L = λ₁L_reconstruct + λ₂L_relation + λ₃L_constraint + λ₄L_contrastive + λ₅L_composition + λ₆L_transition + λ₇L_provenance + λ₈L_counterfactual + λ₉L_budget + λ₁₀L_language`

各项权重需通过消融实验确定，不应预先固定。

## 8. 训练策略：先模块覆盖，再组合探索

建议分三阶段：

### Stage A：原子算子覆盖
学习基础关系抽取、角色识别、时位约束、局部结构变换和证据归因。确保每个基础模块有足够覆盖。

### Stage B：结构组合训练
随机或课程式组合已学模块，训练未见过的路径、非相邻组合、关系方向变化和跨域类象。测试集必须保留真正未见的组合模板。

### Stage C：结果监督与探索式优化
使用可验证结果、环境反馈或约束满足情况优化候选生成和路由策略。允许多条候选路径并行探索；对失败分支保留失败原因，避免只模仿成功轨迹。

不建议一开始就用模型自生成的推理轨迹训练自己，容易放大同源错误。优先用可执行约束、合成结构任务、真实标注关系和外部可验证结果。

## 9. 动态计算与停止策略

每次迭代由控制器选择操作类型：
- UPDATE_LOCAL：局部关系更新；
- EXPAND：增加候选结构；
- SPLIT：分裂假设；
- MERGE：合并兼容结构；
- VERIFY：执行约束和证据检查；
- RETRIEVE：请求新证据；
- COUNTEREXAMPLE：寻找反例；
- STOP：停止并输出当前状态。

控制器估计每个动作的预期收益、成本和风险。停止条件包括：
- 关键约束已满足且验证完成；
- 剩余候选被支配或无区分价值；
- 新一轮计算预计收益低于成本；
- 需要外部观察；
- 预算耗尽；
- 任务本身欠定或存在不可消解冲突。

系统必须区分 SOLVED、PARTIAL、UNDERDETERMINED、CONFLICTED、BUDGET_EXHAUSTED。

## 10. 普通计算机与低内存设计

N0.6 的性能目标不是把所有候选同时放在 RAM。建议：
- 活动槽位数量设硬上限；
- 关系按稀疏邻接和分块存储；
- 分支采用 copy-on-write / delta；
- 只缓存热算子和热关系；
- 低优先级候选可落盘；
- 循环更新共享权重，不复制多套模型；
- 使用小型路由器决定哪些关系需要激活；
- 采用渐进式计算，随预算扩大活动子图；
- 对长期状态只保存必要的潜在索引与可重建投影；
- GPU 不可用时采用小批量 CPU 路径。

必须分开测量模型权重、活动状态、分支 delta、索引缓存、临时张量、KV cache、峰值 RSS/PSS、磁盘 IO 和能耗。结构化工作空间不是免费的，也可能因关系数量增长而爆内存。

## 11. 与 Transformer 的关系：明确实验，不先验站队

至少建立以下对照：

A. 自回归 Transformer + CoT；  
B. 自回归 Transformer + N0.5 Context Compiler；  
C. 离散扩散文本生成；  
D. 连续潜在循环推理 + 语言解码器；  
E. 图/关系结构推理 + 语言解码器；  
F. TRLW：类型化工作空间 + 循环状态更新 + 全局约束能量 + 多候选分支；  
G. TRLW 去除易象算子先验的消融版本。

相同数据、训练预算、参数规模和推理预算下比较。不能只比较 token/s；要同时报告正确率、OOD 组合泛化、推理延迟、峰值内存、能耗、候选多样性和错误恢复能力。

## 12. 核心实验与验收

### 结构能力
- E1：非相邻元素组合，能从候选集选出必要子集；
- E2：组合未见过的原子算子；
- E3：关系角色反转与视角转换；
- E4：时间和位置约束；
- E5：同一观察多种解释并行保留；
- E6：新增证据后局部修订，不重算无关分支；
- E7：发现共享来源，不重复计证；
- E8：识别循环自证；
- E9：生成对抗候选与最小反例；
- E10：在欠定任务中拒绝过早收敛。

### 资源能力
- E11：活动工作集达到上限时安全降级；
- E12：分支 delta 不导致全量复制；
- E13：不同预算下输出状态可解释；
- E14：中断后从 checkpoint 恢复；
- E15：CPU-only 与 GPU 路径结果一致性；
- E16：固定工作量下峰值内存、延迟和能耗可重复测量。

### 语言能力
- E17：结构输出转语言时不丢失关键限定条件；
- E18：语言解码不得新增未经验证事实；
- E19：结构正确而语言表达差、结构错误但语言流畅，必须分别计分。

## 13. 关键消融

1. 去掉类象算子先验；
2. 去掉全局能量，只用局部关系分数；
3. 去掉多候选分支；
4. 去掉非相邻组合训练；
5. 去掉 provenance 相关性；
6. 固定循环深度 vs 自适应深度；
7. 全量候选复制 vs delta 分支；
8. 仅连续潜在状态 vs 类型化结构槽位；
9. 仅语言监督 vs 结构结果监督；
10. 无反证训练 vs 对抗候选训练。

若易象先验没有在组合泛化、样本效率、鲁棒性或资源效率上带来可重复收益，就应删减或重构相关算子，不得为了理论完整性强行保留。

## 14. 失败判据

以下任一情况出现，都不能宣称新架构成功：
- 只提高并行 token 数，没有提高结构推理能力；
- OOD 组合性能不优于对照；
- 候选数量增加但多样性没有提高；
- 潜在状态无法稳定复现或无法定位失败原因；
- 全局能量把错误候选排在前面且无法校准；
- 类象算子只记住术语或表面相似；
- 内存消耗随候选分支数线性复制；
- 在相同准确率下延迟、内存和能耗更差；
- 结构正确率提高但语言解码频繁改变事实限定；
- 仅靠扩大参数量或训练预算获得提升。

## 15. 工程路线

- N0.6-A：TRLW 类型系统与中间表示 schema；
- N0.6-B：确定性稀疏关系工作空间原型；
- N0.6-C：非相邻组合器与候选分支 delta；
- N0.6-D：局部循环更新与全局能量排序；
- N0.6-E：易象算子参数化与对照消融；
- N0.6-F：结构学习数据集、组合泛化基准；
- N0.6-G：小模型训练、语言解码适配；
- N0.6-H：普通计算机压力测试，再评估移动端。

首个原型应先用确定性合成任务与小型可训练模型验证结构表示和组合能力。不要先训练数十亿参数模型。

## 16. 最终判断

N0.6 的核心不是发明一种“周易版 Transformer”，而是把计算对象从 token 序列提升到可学习的关系结构和候选状态。

最值得优先验证的组合是：

**类型化关系工作空间 + 非相邻组合 + 多候选分支 + 循环潜在更新 + 全局约束能量 + 自适应计算控制 + 延迟语言解码。**

易象类象提供结构变换先验，ZPCM 提供长期证据和状态，N0.5 提供任务工作集与上下文编译，N0.6 负责学习如何在这个工作空间中计算。

这是一条可实验、可证伪、可逐步工程化的路线；目前仍是研究方案，不能宣称已经训练出超越 Transformer 的模型。
