# 类象推论操作审计：辟、侔、援、推、效 v0.1

## 1. 研究问题

候选生成回答“两个观察记录在哪里相同/不同”；推论审计回答“研究者正在用哪一种论证动作，从哪些证据推出什么结论”。二者必须分离：匹配只是论证材料，不是推论许可证。

## 2. 《墨子·小取》的论证动作

《小取》先提出“以类取，以类予”，继而区分“效、辟、侔、援、推”，并紧接着警告这些论辩形式可能“转而危、远而失、流而离本”。项目将这些术语作为待记录的论证操作类型，而非天然有效的推理规则。

| 原典术语 | 原文界定要点 | 工程记录类型 | 主要风险 |
|---|---|---|---|
| 效 | 为之法、所效者所以为法 | STANDARD_COMPARISON | 标准不适用、标准来源不可靠 |
| 辟 | 举彼物以明之 | EXEMPLIFICATION | 例子不具代表性、关键条件不同 |
| 侔 | 比辞而俱行 | PARALLEL_FORM | 语句平行但对象关系/语境不平行 |
| 援 | “子然，我奚独不可以然也” | PRECEDENT_APPEAL | 先例与当前案情不具相关同类条件 |
| 推 | 以其所不取之同于其所取者予之 | CLASS_EXTENSION | 只抓住局部相同，忽略“所以然”差异 |

不同传本和注本的断句、字形、校改可能影响解释；本表是工程工作定义，不宣称解决全部训诂争议。对读《墨子·小取》传世文本、四部丛刊本及《墨子闲诂》。数字文本仅作检索入口，未做影印底本校勘前保留候选状态。

## 3. 核心区分：相同处、所以然、取类依据

《小取》提出“其然也同，其所以然不必同；其取之也同，其所以取之不必同”。对类象系统至少意味着：

1. 观察到的表面结果相同，不保证生成该结果的机制相同。
2. 取象时使用的相同特征，不保证该特征在两种对象中具有相同解释地位。
3. 推论必须显式声明共享依据、适用范围、已知差异和证据来源。
4. 对照差异不能自动等于反例；必须先定义该维度是否互斥、是否处于同一情境和观察尺度。

## 4. 工程审计契约

原型：prototype/yixiang_inference_audit.py

- 每条推论明确选择一个论证操作类型。
- 共享依据、推论 warrant、结论、适用范围、已知差异均需显式填写。
- 不同操作要求不同证据角色：辟/侔/推要求 source + target；援要求 precedent + target；效要求 standard + target。每个证据锚点必须关联到声明的证据引用集合；source/target 锚点还必须指向对应观察 ID。
- 缺失关键字段或证据角色时标记 BLOCKED。
- 结构完整时只标记 HUMAN_REVIEW，不存在自动 ACCEPTED。
- 结果明确声明：不证明结论为真、不验证因果、不证明类属、不允许全称推广。

该审计器只检查论证结构完整性和引用链的表层一致性，不检查古汉语句义是否正确，也不验证证据内容真实性、独立性和代表性。

## 5. 与现有模块的边界

观察 → 候选生成 → 对照证据 → 论证操作审计 → 竞争解释 → 主动观测 → 独立验证。

- 候选生成：比较已结构化观察。
- 迁移契约：检查迁移必要情境轴与条件变换证据。
- 本审计器：记录论证动作及证据角色、范围和差异。
- M3：竞争假设，处理多种解释。
- M5：选择能区分竞争解释的下一项观察。
- M8：在留出样例上评估机制，不以本模块自测代替能力证明。
