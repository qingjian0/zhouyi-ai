# 时空情境联合类象模型 v0.1

## 1. 研究问题

现有静态类象、动态状态转移和多元角色关系原型分别回答：
- 对象有哪些可比特征？
- 对象状态如何变化？
- 多个实体以什么角色共同构成关系？

但它们还不足以回答：同一关系在不同时间、位置、阶段和环境条件下是否仍然成立？

本模型把比较对象定义为一个有来源的“情境切片”，将状态、关系、时序、位置和条件并列表示，并分轴输出结果。

## 2. 古典文本入口与解释边界

《周易·系辞下》有“变动不居，周流六虚”“上下无常，刚柔相易”“唯变所适”等语句。可作为研究爻位、变化和适时问题的原典入口。参见：
- [《周易正义·系辞下》](https://ctext.org/wiki.pl?chapter=135943&if=gb&remap=gb)：经文与孔颖达疏并列，可观察唐代注疏如何解释六位、刚柔相易及变动。
- [《周易集解》相关段落](https://ctext.org/wiki.pl?chapter=783848&if=gb&remap=gb)：保存虞翻、侯果、韩康伯等不同注解见证，不能压平为单一解释。
- [《周易传义合订》说卦传](https://zh.wikisource.org/zh-hans/周易傳義合訂_(四庫全書本)/卷12)：保存朱子《本义》及后世按语，可作为后世解释层查缺材料。

必须区分经传原文、唐代注疏、汉代注家解释、宋明解释和现代工程假设。以上文本不能证明现代时空模型已经存在于古代。

## 3. 形式表示

一个情境切片：

S = (id, domain, step, position, stage, state, relations, context, evidence)

- state：对象状态特征；
- relations：带具名角色的多元关系；
- step：同一轨迹内的离散顺序；
- position：观察或结构中的位置标签；
- stage：阶段标签；
- context：环境与任务条件；
- evidence：可追溯来源。

比较两个情境时，调用方必须显式提供实体映射、必需条件键，并可独立指定是否要求位置、阶段一致。

## 4. 为什么不能压成一个总分

一个映射可能：
- 状态特征一致，但角色关系交换；
- 关系结构一致，但环境条件不同；
- 状态和关系一致，但所处阶段不同；
- 位置相同，但时序方向相反。

这些差异有不同含义，不应由一个加权平均分掩盖。因此原型分别报告：
- state_precision；
- relation_precision；
- context_match / context_mismatch；
- position_match；
- stage_match；
- reason_codes。

只有所有硬约束均满足且两侧证据齐备时才接受。精确相同只是当前基线；未来可加入显式声明的角色同义词、条件容差和尺度映射，但不得默认开放。

## 5. 代码与边界

实现：`prototype/yixiang_situated.py`。
测试：`tests/test_yixiang_situated.py`。

当前覆盖：
1. 状态、关系与条件同时匹配；
2. 角色交换拒绝；
3. 状态相似不能掩盖条件冲突；
4. 位置和阶段作为独立门槛；
5. 缺少证据拒绝。

当前不做：
- 从原始视频/文本自动抽取状态；
- 学习“时、位、势”的通用语义；
- 预测未来状态；
- 由关系对应推导因果；
- 把古代象数系统映射为自然科学定律。

## 6. 下一步实验

- 对照 A：仅静态属性；
- 对照 B：静态属性 + 二元关系；
- 对照 C：静态属性 + 多元角色关系；
- 对照 D：C + 时间顺序；
- 对照 E：D + 位置、阶段与条件门槛。

使用角色置换、条件冲突、阶段错配、时间反转、缺失实体、额外关系等反例，测量误接受率、误拒绝率、各轴诊断准确率和证据缺失时的拒绝能力。按源作品/领域分组留出，避免同源泄漏。

只有在独立测试集上优于简单基线，才考虑将此模块升级为 CPG-EI 核心机制。
