# 动态情境类象迁移门禁：实现说明 v0.1

## 目的

古典类象案例反复提示：同一物可能因主体而异用；同一目标可由不同路径达成；同一观察事实可能随参照系、时间、任务和环境改变其判断意义。

现有 situated prototype 已分别记录状态、角色关系、位置、阶段和环境上下文。本模块补充一个独立的、调用方显式指定情境轴的最小门禁，避免把所有情境字段藏在一个自由文本 context 中。

## 数据契约

每个情境包含：
- context_id；
- axes：唯一的名称—值对；
- evidence_refs：该侧证据引用。

建议情境轴包括：
- agent_capability：主体能力；
- task_or_goal：任务或目标；
- environment：环境；
- time_phase：时间阶段；
- observer_standpoint：观察立场；
- reference_frame：参照系；
- process_path：过程路径；
- outcome：结果；
- normative_basis：规范理由。

不是每个迁移都需要所有轴。调用方必须通过 required_axes 明确本次迁移真正依赖的轴。

## 裁决

- 两侧均有证据，且全部必需情境轴相同：SCOPE_SUPPORTED。
- 必需轴缺失：ABSTAIN。
- 必需轴值不同：ABSTAIN。
- 任一侧证据缺失：ABSTAIN。
- 字段畸形或轴重复：拒绝输入并抛出 ValueError。

SCOPE_SUPPORTED 只表示被选中的显式情境轴满足相等条件，不表示古典解释正确、因果关系成立或类比迁移已被事实证成。

## 为什么差异先 ABSTAIN，而不是直接 REJECT

例如视角不同，并不必然意味着关系不可迁移；可能存在可证明的坐标变换。主体能力不同，也可能存在经校准的能力映射。本原型没有推断这些转换的能力，因此采取保守策略：先暂缓，不擅自把差异解释为必然失败，也不猜测它可以被转换。

未来若增加显式轴映射，必须提供映射规则、映射证据、适用范围、误差界限与反例，并与“原值相等”路径分开评估。

## 与现有模块的关系

- yixiang_situated.py：继续处理整体状态、角色关系、位置、阶段和上下文的结构比较。
- yixiang_relation_taxonomy.py：继续负责关系族与证据/因果门槛。
- yixiang_analogy_validity.py：继续负责迁移关系、关键差异与反例审查。
- yixiang_contextual_transfer.py：只负责调用方选定的情境轴是否显式齐备并满足相等条件。
- M5：当情境轴缺失或冲突时，选择能区分竞争解释的观察。
- M8：覆盖主体、任务、环境、时间、视角、参照系、过程和结果之间的错配。

## 限制

这是透明规则基线，不是学习模型。它不自动识别文本中的主体、任务或时间，不从古文推断轴值，不判断轴是否应该相同，也不学习跨情境转换。调用方错误指定 required_axes，仍可能得到不适当的范围内支持。因此 required_axes 的语义必须由上游任务定义并审查。
