# RSDN-N2.1：组合状态学习与最小可证伪实验

日期：2026-11-11  
状态：实验规格，不是实验结果  
父研究：PR #158 RSDN-N2  
目标：验证关系状态编辑是否能通过组合式训练学到可迁移的状态约束，而不只是记住下一步变化。

## 0. 本轮最重要的新结论

仅训练“当前状态 + 当前观察 -> 下一状态”，不足以证明模型理解全局关系约束。

2026 年的研究《Do World Models Learn Global Understanding?》提出 monoid worlds 和 proof depth，发现多个架构在普通 next-state 训练下能拟合局部转移，却难以将学到的约束传播到未见转移；组合式训练通过隐藏中间状态、要求模型组合路径，可以显著改善约束泛化，但随着证明深度增加，泛化仍会下降。

这对 RSDN 有直接影响：

**不能只训练状态编辑预测。必须训练模型从多条局部变化中发现可组合约束，并将约束传播到未直接见过的状态编辑。**

这也是 RSDN 和简单事件分类器、GNN 消息传递的关键区分之一。该研究不是 RSDN 已成功的证据，而是对 RSDN 训练设计的约束。

参考：
- Do World Models Learn Global Understanding? https://arxiv.org/abs/2609.34058

## 1. 核心实验问题

E-N21 不回答“模型是否能预测训练分布中的下一状态”，而回答：

1. 模型能否从局部转移中归纳全局约束？
2. 能否把约束组合到从未见过的路径和关系组合？
3. 能否在隐藏中间状态时恢复正确的复合结果？
4. 推理链变长时，性能如何随 proof depth 退化？
5. 易象算子是否改善约束发现与迁移，而不只是增加训练集内拟合？
6. 模型能否指出缺少哪些前提，并拒绝无证据的状态编辑？

## 2. 三种训练范式，必须分开比较

### A. 单步 next-state 训练

输入当前状态 S 和动作/观察 a，预测 S' 或 ΔS。

`(S_t, a_t) -> ΔS_t`

这是必要基线，但不构成组合泛化的充分训练。

### B. 多步显式轨迹训练

输入连续状态/动作序列，预测多个后续状态。

`(S_0, a_0, S_1, a_1, ..., a_n) -> S_{n+1}`

模型可以利用中间状态，容易通过局部记忆完成任务，因此必须控制训练/测试路径重叠。

### C. 组合约束训练（核心）

提供若干局部转移规则或路径，隐藏部分中间状态，要求模型预测复合路径结果，并解释所依赖的约束。

`(S_0 -> S_1), (S_1 -> S_2), ..., (S_{k-1} -> S_k) -> (S_0 -> S_k)`

训练时对部分中间节点/状态做遮蔽，模型必须组合路径，而非复制答案。测试集使用训练中未出现的关系组合、路径长度和对象身份。

## 3. 合成世界：从可控规则开始

构造有限状态集合和操作集合。每个操作有明确的前置条件、状态变化和不变量。

最小操作族：
- IDENTITY：不变；
- INVERSE：存在明确逆操作时可恢复；
- COMPOSE：操作组合；
- COMMUTE：满足条件时可交换；
- PERIODIC：在定义域内周期变化；
- CONDITIONAL：只有满足条件才允许；
- ROLE_SWAP：角色互换；
- POLARITY_DUAL：显式对偶变换；
- DECOMPOSE / COMPOSE_HYPEREDGE：高阶关系拆分/合成。

每个世界实例随机生成：
- 对象和属性；
- 关系签名和角色；
- 操作定义；
- 作用条件；
- 一组训练转移；
- 隐藏测试转移；
- 最短推导证明及 proof depth。

规则世界的随机种子、生成器版本、规则清单和 oracle 输出必须落盘，确保可复现。

## 4. 关键数据划分

不可只随机拆分样本。采用五类 OOD 划分：

| 划分 | 训练/测试差异 | 测试目的 |
|---|---|---|
| Entity OOD | 测试对象 ID 全新 | 不依赖实体记忆 |
| Composition OOD | 操作单独出现过，组合未出现 | 组合泛化 |
| Path-depth OOD | 测试路径更长 | 深层约束传播 |
| Rule-combination OOD | 规则组合未见 | 全局规则推断 |
| Domain OOD | 对象和关系语义换域 | 结构迁移 |

每个测试样本记录最短证明深度 d、路径长度 k、可用证据数量、约束冲突数量。

## 5. 模型结构对照

至少比较：

1. Transformer sequence baseline；
2. GNN / relational message passing；
3. 小型 MLP + 显式状态特征；
4. 规则执行器（oracle 规则）；
5. RSDN transition proposer（不启用易象）；
6. RSDN + 易象算子；
7. RSDN + 随机算子；
8. RSDN + 通用可学习算子（容量匹配）。

必须额外设置参数量匹配和 FLOPs 匹配两种比较。规则 oracle 只作为上界，不得拿它与学习模型直接宣称公平胜负。

## 6. 输出不应只有答案

每个预测必须输出：
- 候选 Edit 集合；
- 依赖的前提关系；
- 使用的算子；
- 约束传播路径；
- 最短或近似 proof trace；
- 证据引用；
- 未满足前提；
- 置信校准；
- 是否应 ABSTAIN。

如果模型无法给出可核验的依赖路径，只能计入答案准确率，不能计入可解释推导成功率。

## 7. 评测指标

### 主指标
- Exact Edit Set Match；
- State Transition Accuracy；
- Constraint Generalization Accuracy；
- Composition OOD Accuracy；
- Proof-depth Accuracy 曲线；
- Counterfactual Consistency；
- Invalid Edit Rejection；
- NOOP / ABSTAIN Precision & Recall。

### 辅助指标
- 关系角色错误率；
- 过期关系误用率；
- 证据归属正确率；
- 平均推导长度；
- 候选数与有效候选比例；
- 峰值 RAM、延迟、FLOPs；
- 单位资源下的正确编辑数。

置信度使用 Brier Score / ECE 等校准指标；不得把相似度分数直接解释为概率。

## 8. 易象算子消融

所有易象算子必须在实验前冻结 schema 和版本，并声明预期保持/改变的不变量。

对每一算子组测试：
- 启用该算子；
- 禁用该算子；
- 使用随机置换算子；
- 使用容量匹配的通用可学习算子；
- 使用另一套传统解释版本（若存在）。

判断增益是否真实：
- 训练集收益不算；
- 易学术语数据上的收益不算通用迁移；
- 只在单一随机种子上的收益不算稳定；
- 需要在未见对象、关系组合和领域上复现；
- 同时检查错误类比率是否上升。

## 9. 反例与拒绝机制

必须加入下列 hard negatives：
- 两个操作表面相似但不可交换；
- 逆操作只在部分状态有效；
- 角色交换后因果/所有权语义变化；
- 时间逆序不等于因果逆转；
- 阴阳对偶不等于简单取反；
- 两个领域结构相似但关键关系不对应；
- 证明链缺少必要前提；
- 局部关系成立但全局约束冲突。

模型可以返回：
- VALID；
- INVALID；
- UNKNOWN；
- INSUFFICIENT_EVIDENCE；
- BUDGET_EXHAUSTED。

UNKNOWN 不可自动降格为 INVALID；预算耗尽也不可伪装成“无类象”。

## 10. 最小实验执行顺序

### E-N21-A：数据生成器与 oracle
先实现纯 Python 世界生成器、状态执行器、证明深度计算和数据导出。所有生成样本可由 oracle 重放。

### E-N21-B：单步 vs 组合训练
同一架构、同一参数量，比较 A/B/C 三种训练范式。

### E-N21-C：OOD 与 proof-depth 曲线
逐步增加路径长度和最短证明深度，报告曲线，不只报一个平均准确率。

### E-N21-D：易象算子消融
冻结算子版本后做严格消融，不允许边看测试集边修改规则。

### E-N21-E：资源测试
在桌面 CPU 和目标 Android 设备上测试；先验证算法，再测内存。记录每个推理步骤的候选数和活动状态规模。

## 11. 通过标准与失败标准

### 进入下一阶段的最低条件
- 生成器和 oracle 可重复运行；
- 训练/测试无实体、路径或规则泄漏；
- 组合训练在至少两个 OOD 划分上稳定优于单步训练；
- 结果跨多个随机种子复现；
- proof depth 增加时性能曲线透明；
- 易象算子增益优于随机算子且有跨域复现；
- 证据和状态版本可完整追溯。

### 失败条件
- 组合训练没有超过单步训练；
- 增益仅来自更多计算量；
- proof depth 增加后快速退化且没有可用拒绝机制；
- 易象算子不优于随机或通用算子；
- 输出答案正确但依赖链错误；
- 通过丢失证据或压缩状态获得虚假的内存优势。

## 12. N2.1 工程接口建议

先实现下列纯数据结构和确定性组件，不急于训练：

- `WorldSpec`：一个合成世界的完整规则定义；
- `StateSnapshot`：不可变状态版本；
- `TransitionRule`：操作、前提、效果、不变量；
- `EditSet`：一组无序或部分有序的状态编辑；
- `ProofTrace`：每个结果的依赖链；
- `OracleTransitionEngine`：确定性执行器；
- `DatasetSplitManifest`：划分规则和随机种子；
- `EvaluationRecord`：答案、证据、资源、校准和拒绝指标。

接口必须区分“真实观察”“合成世界真值”“模型推断”和“假设”。不要将合成 oracle 事实伪装成真实世界证据。

## 13. 当前决策

- 接受组合约束训练作为 RSDN 必测训练范式。
- 保留单步 next-state 训练作为基线。
- 增加 proof depth 作为核心难度变量。
- 将可核验依赖链作为独立指标。
- 易象算子必须接受随机先验和通用算子对照。
- 本文仅为实验设计，尚未运行实验，不能声称结果已成立。
