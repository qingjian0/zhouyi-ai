# E02-J：开放规则语言中的自主关系提出与验证（预注册草案）

状态：研究设计草案；尚未实现、运行或验证。  
基线：main `4a88879cc6d9b96b26b5dc893ea39f541c3cab75`。  
目标：测试系统能否从观测与反例中提出可执行的新关系表达式，而不是只在预先枚举的候选规则中挑选。

## 1. 要回答的核心问题

现有 E02-D 的识别结果依赖有限、预先定义的仿射模 3 假设类。即使覆盖率达到 100%，它回答的仍是“给定规则族能否被识别”，而不是“系统能否自主提出未知规则”。

E02-J 将候选生成与候选验证拆开，重点测试：

1. 系统能否提出训练数据中未直接出现的组合规则；
2. 能否组合已发现的原语，形成新的高阶关系；
3. 能否通过反例修正、拆分、合并或放弃关系；
4. 能否把学到的关系迁移到未见成员组合、未见环境和不同输入规模；
5. 在没有可证据支持的规则时能否拒绝猜测。

“自主”在本实验中的操作性定义：候选表达式由被测系统运行时生成；隐藏真值、候选全集和目标成员集合均不提供给系统。系统只能访问公开的类型/执行接口、训练观测和受预算约束的查询反馈。

## 2. 分层任务，避免把有限 DSL 伪装成开放发现

### Level A：已知原语、未知组合

提供有限、通用的原语接口（布尔运算、整数算术、比较、条件选择、索引/投影、集合操作），不提供完整候选列表。隐藏规则由这些原语组合生成，深度和成员跨度可变。

该层只证明组合程序合成能力，不应称为发现了新的基础原语。

### Level B：隐藏宏关系与可跳跃成员

隐藏规则包含可复用的高阶宏关系，输入成员可以非连续选取，例如索引集合 `{0,2,5}`、`{1,4,7}`。系统只能观察输入输出和查询反馈，需要自行提出成员角色、组合次序、条件或宏表达式。

训练阶段允许见到宏的局部实例，但锁定测试包含未见成员组合与新位置跨度。必须报告仅靠位置记忆的基线。

### Level C：机制迁移与未知原语族

使用多个生成机制族（例如有限域运算、状态转移、集合变换、带条件的关系组合），在训练时隐藏其中一部分机制族或组合模板。被测系统不得访问生成器代码或机制标签。

此层需要明确区分“从通用程序空间中重新表达已知机制”与“提出此前未提供的可复用宏原语”。若表达接口本身不允许新宏，不能声称发现了新原语。

## 3. 生成机制与数据隔离

- 由 evaluator 私有生成器生成规则、成员角色、参数、环境扰动和观测。
- Train：用于提出初始候选与学习原语。
- Query/Gate：系统可主动请求有限数量的输入输出或反例；每次查询计入预算。
- Validation：用于候选筛选和阈值校准。
- Locked Test：包括未见参数、未见成员位置组合、未见组合深度和环境迁移；系统提交冻结的可执行程序后才可评估。
- 生成器代码、隐藏规则、Test seed 和真值只由 evaluator 持有；模型日志不得泄漏这些内容。
- 同一隐藏规则需提供足够多样的表面实例，避免规则标签、样本顺序、文件名、ID 或缺失模式泄漏真值。

建议固定 4 个任务族、每族 30 个隐藏规则实例；具体规模先用开发集做功效分析，正式 Test seed 在预注册时锁定。不得在查看 Test 后改变任务族比例。

## 4. 被测系统接口

每轮系统提交一个或多个候选程序，每个候选必须包含：

- 可执行 AST / typed expression；
- 声明的输入成员与角色映射；
- 适用条件与环境范围；
- 预测输出；
- 置信度或证据等级；
- 复杂度/描述长度；
- 能推翻该规则的可检验反例条件。

系统可并行提出多个候选，但必须显式管理候选多样性、证据共享与冲突。不得把候选池由 evaluator 预先生成后再交给系统排序。

查询反馈分为：命中、反例、信息不足、接口无效。反例需提供最小或近似最小反例；是否采用主动查询策略作为独立实验变量记录。

## 5. 核心对照组

所有方法使用同一执行接口、同一观测数据、同一查询预算和同一计算预算：

1. **Finite-enumeration**：有限预定义 DSL 穷举，作为封闭候选空间上界。
2. **Random-program**：从允许的通用 AST 空间随机采样。
3. **MDL/program-synthesis**：按复杂度惩罚与观测拟合生成/选择程序。
4. **Evolutionary search**：变异、交叉和反例驱动的候选演化。
5. **Parallel-hypothesis system**：多个候选并行提出、独立验证、通过共享证据与冲突裁决综合。
6. **Autoregressive proposal control**：相同底层表达能力和预算，按序生成候选，用于检验并行组合机制本身是否带来收益。
7. **Oracle grammar upper bound**：仅作为不可部署的 evaluator 上界，清楚标记其访问了隐藏生成机制。

对照算法必须使用相同候选执行次数、总 token/操作预算、查询数与 Test 访问权限。若无法做到严格相同，应分别报告预算曲线，不用单点结果宣称架构优势。

## 6. 评价指标

主要指标：

- **Executable discovery rate**：在预算内提出至少一个可执行、非平凡候选的任务比例。
- **Exact rule recovery**：成员、角色、算子和参数均正确的比例。
- **Predictive generalization**：锁定 Test 上的准确率/损失。
- **Compositional OOD**：未见成员组合、非连续跨度、组合深度和环境迁移的表现。
- **Counterexample efficiency**：发现并修正错误候选所需查询数。
- **Calibration / abstention**：置信度校准、错误高置信率、适当拒绝率。
- **Description length**：等价程序按规范化 AST / MDL 计分，避免只用字符串长度。
- **Novel macro reuse**：新宏在未见任务中复用成功的比例。
- **Diversity and redundancy**：并行候选之间的结构差异、重复率及有效覆盖范围。
- **Cost**：运行时间、候选执行次数、查询次数、内存/算力。

必须报告每个任务族和每个 seed 的原始结果，不只给总体均值。对配对方法报告差值和 95% 置信区间。

## 7. 防止“伪自主发现”的审计

- 隐藏候选全集：不得向被测系统提供目标规则或候选清单。
- 生成器隔离：被测进程不可读取 evaluator 代码、隐藏文件、环境变量或 Test 数据。
- 标签攻击：使用 metadata-only attacker 检查 ID、顺序、缺失模式、长度和字段组合是否泄漏任务/规则标签。
- 记忆泄漏：训练/测试规则实例需按规则结构分组隔离，不能让同一规则的近重复实例跨 split。
- 位置记忆：对输入成员做随机置换，并要求系统给出置换等变或正确角色映射。
- 简单查表：加入随机参数和新组合，确保记忆训练样本不能直接通过。
- 规则等价：对语义等价 AST 规范化，避免把不同字符串误判为新规则。
- 反例纪律：若系统收到反例后只降低置信度而未改变预测，应计为未修复；若证据冲突，应允许 ABSTAIN。
- Test 防火墙：系统只能提交冻结产物，评估脚本不向系统返回 Test 逐样本信息。

## 8. 分析计划与结论边界

先在开发集完成接口、任务难度和功效分析，再冻结正式规则、seed、预算、算法超参数和统计判据。正式 Test 只运行一次。所有失败实例、超时、无效 AST 和拒绝回答都必须纳入分母。

结果必须按以下层次表述：

- 只在 Level A 成功：通用原语组合/程序合成能力，不是开放原语发现。
- Level B 成功：支持非连续成员组合与高阶宏关系发现。
- Level C 成功且能跨任务复用：才有证据支持机制迁移或新宏原语发现。
- 并行系统只有在相同预算下显著优于顺序提案控制，才能声称并行组合机制带来收益。
- 若仅预测准确但无法恢复可解释、可证伪的程序，只能称为黑盒拟合，不能称为关系发现。
