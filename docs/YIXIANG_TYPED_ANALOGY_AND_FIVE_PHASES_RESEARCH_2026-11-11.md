# 第三轮研究：八卦多维类象、五行历史分层与关系映射认知原型

日期：2026-11-11
研究阶段：原典章节、出土文献研究、现代类比认知理论对照
目标：将易象与类象推进为可实现、可反证、可评测的 CPG-EI 认知机制
状态：研究规格；尚非已实现功能

## 0. 本轮结论

本轮最重要的三项发现：

1. 《说卦传》的八卦意义是多维的：自然物象、性情/作用、家庭角色、时空过程、动物和器物等并存。八卦不是八个互斥类别，也不是一张固定标签表。
2. 五行与易卦的系统性融合有历史层次。不能将京房以后的纳甲、八宫、飞伏、五行配卦全部当成《周易》原始结构，也不能把后世方位图式反推为先秦唯一原义。
3. 现代结构映射理论与易学类象可以形成有价值的对照：真正有推理价值的类比，重点是关系结构及其系统性，而非表面相似。但类比推论通常是可撤销的假设，不是逻辑必然结论。

因此，CPG-EI 应实现“多视角结构表征 + 有类型的跨域映射 + 规则/证据竞争 + 反例驱动修订”，而不是把易学术语转成固定规则表。

## 1. 《说卦传》八卦意义至少有六个维度

《说卦传》不同章节提供不同类型的八卦描述。工程上应拆开存储，不能把所有条目都塞进一个 meanings 数组。

### 1.1 自然物象维度

| 卦 | 基本自然象 | 不应简化为 |
|---|---|---|
| 乾 | 天 | 所有高处或所有领导者 |
| 坤 | 地 | 所有柔弱、被动对象 |
| 震 | 雷 | 所有声音或所有突发事件 |
| 巽 | 风 | 所有流动或所有信息 |
| 坎 | 水 | 所有液体或所有危险 |
| 离 | 火、日 | 所有光亮或所有热量 |
| 艮 | 山 | 所有障碍 |
| 兑 | 泽 | 所有喜悦或所有口部对象 |

### 1.2 性情/作用维度

《说卦传》有“乾，健也；坤，顺也；震，动也；巽，入也；坎，陷也；离，丽也；艮，止也；兑，说也”。

这组词更接近作用方式或状态倾向，而非物体名称。建议映射到动态谓词，而不是名词标签：

- 乾：持续施力、健行、主动维持；
- 坤：承载、顺应、容纳；
- 震：触发、启动、扰动；
- 巽：进入、渗透、扩散；
- 坎：陷入、受限、穿行于风险；
- 离：附着、显现、照明/区分；
- 艮：停止、边界、保持；
- 兑：开放、交流、悦纳/表达。

这些是面向工程建模的候选释义，不是把古义唯一化。每个谓词必须关联原文和解释来源。

### 1.3 家庭角色维度

乾父、坤母，震长男、巽长女，坎中男、离中女，艮少男、兑少女。

这套结构表达的是父母与六子之间的生成/角色关系。不能直接把它当作生物学分类或现代性别理论。可抽取的计算概念是：

- 根节点/生成者；
- 子节点；
- 生成顺序；
- 同级/异类配对；
- 长、中、少的相对序位。

### 1.4 时空过程维度

“帝出乎震”章节把八卦与方向、时节、万物活动阶段联系起来：震为发生，巽为齐整，离为显现，坤为养育，兑为悦成，乾为阴阳相薄，坎为劳/归，艮为成终成始。

这一组不是八个静态物体，而是一个过程视图。可建模为状态转换图，但必须保留原典语境，不应假定所有领域都按这八阶段循环。

### 1.5 动物、器物、人体等广象维度

第八至第十一章包含马、牛、龙、鸡、豕、雉、狗、羊，以及车、弓轮、甲胄、手指、口舌、木、绳等类象。它们并不共享单一映射理由。每一项应当单独建立桥接说明：

- 原文条目；
- 所属章节；
- 传统注释；
- 取象维度；
- 解释者；
- 适用范围；
- 反例/不适用情境。

不能把现代讲解者补充的解释伪装成经文原文。

## 2. 类象的算法单位：Typed Analogy Bridge

建议把每条跨域映射建模为：

```text
AnalogyBridge {
  source_domain
  source_structure
  source_aspect
  target_domain
  target_structure
  mapping_type
  relation_alignment[]
  preserved_relations[]
  omitted_relations[]
  violated_relations[]
  scope_conditions[]
  predicted_consequences[]
  counterexamples[]
  evidence_refs[]
  tradition_or_theory
  confidence
  status
}
```

mapping_type 至少包括：

- morphology：形态/构型；
- function：功能；
- role：角色；
- relation：关系；
- dynamics：动态过程；
- spatiotemporal：时空位置/周期；
- conventional：历史约定/象征；
- interpretive：义理解释。

不得把这些类型压成一个无类型的 cosine similarity。语义相似、结构相似、因果相似和历史约定是不同证据。

### 2.1 映射评分

建议采用分项评分，而不是单一相似度：

- R：关系结构对应度；
- S：关系系统性（相互连接的高阶关系数量/质量）；
- C：因果/动态一致性；
- E：证据支持度；
- B：边界条件覆盖度；
- X：反例与冲突惩罚；
- A：额外假设成本。

原型阶段可用可解释的加权模型：

`score = wR*R + wS*S + wC*C + wE*E + wB*B - wX*X - wA*A`

权重必须通过任务验证集校准，不得预设为普适常数。低分不代表绝对无意义，只表示当前任务和证据下不宜采用。

### 2.2 必须执行的映射检查

1. 至少映射一组关系，而不是只映射一个对象属性。
2. 说明目标领域中哪些关系没有对应项。
3. 检查是否存在关键关系反转。
4. 生成至少一个可验证预测。
5. 生成至少一个可能推翻该映射的反例条件。
6. 与其他候选类象比较，不允许只展示最顺眼的一个。

## 3. 五行应作为独立、可插拔的关系系统

### 3.1 历史分层

研究资料显示，《周易》经传与五行系统并非从一开始就构成后世完整的纳甲体系。清华简《筮法》所见八卦方位与五行属性问题、两汉象数易学的发展、京房的八宫/纳甲/纳支/飞伏体系、宋代图书易学，都应分别标注历史层次。

尤其需要注意：

- 《说卦传》的方位/时序文本不能简单解释为五行相生序列；
- 京房体系将阴阳五行与八宫卦、干支、爻位等建立系统联系；
- 后世纳甲筮法又有长期发展，不能与京房原貌完全等同；
- 河图洛书黑白点图属于宋代易图史的重要发展，不可直接宣称为先秦既定图形算法。

### 3.2 五行不是五种物质标签

在算法上，五行至少包含多种不同关系：

- 相生：生成/支持关系；
- 相克：制约关系；
- 乘侮：失衡状态下的关系异常；
- 旺相休囚死：与时令相关的状态/势能模型；
- 方位、时节、颜色、数等：传统配属关系。

这些关系属于特定传统理论系统。不得直接等同现代物理元素、化学反应、能量守恒或实证因果。

### 3.3 插件化模型

```text
FivePhaseProfile {
  tradition_id
  historical_period
  element_set
  generation_edges[]
  control_edges[]
  abnormal_relation_rules[]
  temporal_state_rules[]
  correspondence_tables[]
  source_refs[]
  applicability
  known_disputes[]
}
```

不同流派的配置不能混合成一个隐式全局真理。对一个任务，如果五行配置没有明确解释增益，应允许整个插件不参与推理。

## 4. 爻位关系：Position-Relation Graph

六爻结构可抽象为六个有序位置与若干关系边。

### 4.1 位置属性

- position：1..6，自下而上；
- polarity：阴/阳；
- rank：初、二、三、四、五、上；
- zone：下卦/上卦；
- center：二、五为中位候选；
- parity_fit：阳居奇位、阴居偶位的传统得正判据；
- boundary：初、上为边界位置；
- transition：三、四为内外卦交界位置。

### 4.2 关系边

- correspondence：初四、二五、三上相应位置关系；
- adjacency：相邻关系；
- cheng：承；
- cheng乘：乘；
- same_polarity / opposite_polarity；
- host_relation：卦主与其他爻的关系（规则须按流派配置）。

### 4.3 重要限制

- 得正、得中、相应不是同一指标；
- 得正不自动等于吉；
- 不得正不自动等于凶；
- 爻位含义受卦体、卦时、爻辞、其他爻关系制约；
- 位置阶段是解释视角，不是现实身份的固定映射；
- 不同易学体例之间可能冲突，必须保留来源与竞争结果。

### 4.4 现代迁移

可以把爻位结构作为通用关系分析的候选模板：

- 阶段：启动、内部发展、临界、外部执行、主导、极限；
- 位置：系统中的层级、边界、中心、接口；
- 关系：支持、约束、响应、承接、压制；
- 状态：稳定、失配、过度、转换。

迁移时需要从任务数据学习阶段定义，不得把“初爻=开始、五爻=领导”硬编码到所有领域。

## 5. 现代认知理论对照：结构映射与概念整合

结构映射理论强调关系而非单纯对象属性，并以相互连接的高阶关系系统作为类比质量的重要依据。类比推理通常是可撤销的扩展推理，不是从相似性直接推出必然结论。

概念整合理论进一步指出，多个输入空间可以选择性投影到整合空间，并通过补全与展开形成输入中未显式给出的新结构。但新结构仍须回到证据中检验。

对 CPG-EI 的借鉴：

- 类象映射需要关系图，不只是向量；
- 多个来源视角可以共同参与；
- 整合空间可以提出新假设；
- 新假设应带生成轨迹和可检验预测；
- 反例可以回写并修正映射规则；
- 类比必须允许不成立、部分成立或只在局部成立。

## 6. 可执行原型：先做最小闭环，不要一开始实现完整易学

建议首个原型只支持：

1. 八卦三爻二进制结构；
2. 八卦多维语义候选；
3. 具类型的类象桥接；
4. 关系映射；
5. 竞争解释；
6. 反例与预测；
7. 证据溯源。

### 6.1 输入/输出契约

输入：
- observed_case：现实观察；
- target_task：当前任务；
- context：时间、领域、约束；
- available_evidence：事实与来源。

输出：
- candidate_views：候选结构视角；
- analogy_bridges：候选映射及桥接理由；
- competing_interpretations：竞争解释；
- predicted_observations：可验证预测；
- disconfirming_conditions：反证条件；
- confidence_and_uncertainty；
- provenance：完整来源链。

### 6.2 最小算法流程

```text
observe(case)
  -> extract_relational_graph(case)
  -> generate_candidate_views(case, context)
  -> retrieve_candidate_analogies(view, task_domain)
  -> build_typed_bridges(source, target)
  -> align_relations()
  -> detect_unmapped_and_conflicting_relations()
  -> generate_predictions_and_counterexamples()
  -> compare_interpretations()
  -> select / retain_multiple / abstain
  -> record_evidence_and_update_memory()
```

注意：这不是固定单向流水线。新证据可以回到观察层重新构造结构；不同投影可并行竞争；必要时可以不选任何类象。

## 7. 原型测试集：正例、部分例、负例

### T01：雷与突发系统事件（部分正例）
映射：短时间触发状态变化、扰动传播。
反例：若目标事件是长期缓慢累积、无明显触发点，则雷象映射弱。
验收：系统能指出映射维度及不对应之处。

### T02：风与网络信息扩散（条件正例）
映射：沿连接结构传播、扩散、局部状态被改变。
反例：点对点加密直连、中心控制的强制路由，不一定符合风的扩散结构。
验收：能比较风、道路、管道等替代类象，而非只接受风。

### T03：水与数据流（部分正例）
映射：受通道、边界、阻力、容量约束。
反例：数据可复制、可校验、可并发分叉，水流类比无法完整覆盖这些属性。
验收：显式记录数据与水的关键差异。

### T04：山与系统边界（条件正例）
映射：约束可达状态、形成边界。
反例：可动态配置、可绕过或自适应的软边界，不等同固定山体。
验收：区分硬约束和软约束。

### T05：仅凭外观的伪类比（负例）
两个对象颜色、形状相似，但功能、关系和动态机制均不对应。
验收：不得仅凭表面相似给出高分。

### T06：目标答案诱导（防事后合理化）
先给模型答案，再要求寻找能支持答案的易象规则。
验收：系统必须标记答案泄漏/事后选择风险，并用未见案例验证规则。

### T07：五行配置跨流派混用（负例）
输入不同历史时期、不同流派的五行配属表。
验收：系统不得静默合并，必须要求明确 profile 或并行比较。

### T08：位置误判（负例）
某爻得正但处于不利上下文，或失正但有中、有应。
验收：系统不得将单个得正标志直接等同吉凶。

## 8. 评测指标

- relational_alignment：关键关系对应准确率；
- systematicity：映射关系系统性；
- prediction_precision：映射预测精度；
- disconfirmation_recall：反证条件召回率；
- negative_transfer_rate：负迁移率；
- abstention_quality：应该拒绝时是否正确拒绝；
- cross_case_stability：跨案例稳定性；
- post_hoc_rule_selection_rate：事后挑规则比例；
- provenance_completeness：来源链完整度；
- compute_cost：推理时间与资源成本。

至少设置三组对照：
A. 普通语义相似度/RAG；
B. 结构关系映射；
C. 结构映射 + 易象多视角 + 解释竞争。

只有 C 在独立测试集上有稳定增益，才能证明易象机制对通用认知有额外贡献。若没有增益，应保留其文化解释功能，不强行将其设为核心推理机制。

## 9. 对 CPG-EI 主架构的修订建议

把“象数理类变”理解为互相作用的认知操作，而不是五个固定串联模块：

- 象：对观察对象进行多尺度、多视角结构表征；
- 类：跨领域建立可检验的关系映射；
- 数：为结构提供数量、序位、组合、约束和形式计算；
- 理：形成关系解释、规则假设和竞争模型；
- 变：对结构和状态做变换，探索可能路径。

它们可以并行、回环、互相修正。不同传统的具体规则作为可插拔 profile，而非不可更改的全局内核。

建议核心对象：
- ObservationGraph
- PatternView
- AnalogyBridge
- RelationMapping
- ConstraintSet
- InterpretationHypothesis
- TransformationTrace
- EvidenceRecord
- Counterexample
- ProvenanceChain

## 11. 本轮结论与下一轮工作

当前最值得投入的方向不是继续增加八卦类象条目，而是建立一套能证明“类象是否有用”的小型实验。

下一轮建议：
1. 明确八卦三爻的规范编码和多视角投影；
2. 逐项校对《说卦传》第七至第十一章原文，建立原文/注释/现代解释三层数据；
3. 定义互体、错卦、综卦、变爻、伏卦等算子的形式化规范和流派 profile；
4. 写一个不依赖大模型的确定性规则原型；
5. 用大模型生成候选桥接，但由规则检查器、证据检索和反例评测器约束；
6. 对比普通 RAG、语义相似度、结构映射和易象增强方法；
7. 通过实验结果决定易象模块在 CPG-EI 中的权重，而不是先验指定它必然有效。

最终原则：**易象可以成为 CPG-EI 的认知灵感与结构方法，但必须经过可执行定义、可追溯证据、可复现对照和失败案例，才能成为可信的工程能力。**
