# E13-C.2：有限状态转移与多步动态类象

日期：2026-11-11  
状态：有限确定性原型与证伪测试；不代表开放世界动力学学习

## 1. 为什么从单步升级

E13-C 单步机制 DSL 只表达一条干预到响应的规则。它无法区分：
- 一次响应相同、后续反馈却不同的系统；
- 周期、稳定、发散、状态锁定等轨迹形态；
- 中间状态改变后对后续响应的条件影响；
- 只在第二步或更晚出现的机制反例。

因此 E13-C.2 使用有限状态转移系统（Finite State Transition System, FSTS）作为最小可执行动态模型。

## 2. 数据模型

- `TransitionSystem`：有限状态变量、动作集合和确定性转移规则。
- `TransitionRule`：动作 + 完整当前状态 → 完整下一状态。
- `TransitionMap`：源/目标状态变量、状态值和动作的显式单射映射。
- `Trajectory`：初始状态与每一步转移形成的完整轨迹。
- `TrajectoryValidation`：逐步比较预测轨迹与目标系统独立执行的轨迹。

每条规则必须给全部状态变量赋值；相同动作和当前状态不能有两条不同下一状态。未定义转移返回 NO_TRANSITION，不允许补猜。

## 3. 双系统执行协议

1. 在源系统给定初始状态和动作序列。
2. 源系统滚动执行，生成完整状态轨迹。
3. 通过显式映射把每个源状态转换为目标域预测状态。
4. 独立地把目标初始状态映射到目标系统命名空间，并执行对应动作序列。
5. 比较轨迹长度及每个时间步的完整状态。
6. 任一时间步不一致，拒绝该候选；任一侧缺少转移则返回 UNKNOWN。观察轨迹不完整时，版本空间更新返回 `REJECTED_INCOMPLETE_EVIDENCE`，不得把缺失数据解释为所有候选都错。

动作序列在两个系统中通过显式 action map 对应。预测过程不读取目标系统的下一状态。

## 4. 反馈与动态结构

有限状态转移可以表达反馈：前一步的状态成为下一步规则的输入。周期、稳定状态、吸收状态和发散到有限边界状态均可在有限状态空间中编码。

但这不是连续时间动力学，也不自动识别真实系统中的反馈因果图。它只是让反馈行为可以被执行、预测和证伪。

## 5. 主动轨迹选择与版本空间更新

C.2 已接入 E13-B3-D 的 disagreement selector：候选映射对同一动作序列产生完整目标轨迹预测，选择候选轨迹分歧最大的动作序列。该选择过程不接收目标系统。执行选中的动作序列并取得独立目标轨迹后，再按轨迹摘要过滤候选版本空间。若观测轨迹不完整，拒绝更新；若完整观测排除所有候选，才报告 CONTRADICTION。

## 6. 证伪测试

- 多步周期轨迹完整保持。
- 第一转移相同、第二步开始反馈分歧：必须在确切时间步拒绝。
- 目标缺失转移：返回 UNKNOWN，不补造轨迹。
- 非确定性重复规则：契约拒绝。
- 状态变量赋值不完整：契约拒绝。
- 非单射状态值映射：契约拒绝。
- 缺失动作/转移：返回准确停止步数。

## 7. 当前限制

- 确定性、有限状态、离散时间；
- 每一步只执行一个动作；
- 状态变量和值的跨域映射由外部显式提供；
- 无连续变量、概率转移、观测噪声、并发动作、资源约束或干预副作用；
- 当前状态空间由规则显式列出，不做状态抽象或自动机制发现。

## 8. 下一步实验门槛

E13-C.3 再引入概率转移、观测噪声、动作成本和风险；在此之前不要把有限状态轨迹保持称为真实世界因果等价。

E13-C.4 应比较：
- 单步响应基线；
- 多步 FSTS；
- 随机/无先验映射；
- 易象候选变换（阴阳对偶、变爻、互体、错综、时位）；
并使用锁定 OOD 轨迹、硬负例和相同搜索预算。

如果易象变换不能改善轨迹迁移或区分效率，就应拒绝或降权该先验。
