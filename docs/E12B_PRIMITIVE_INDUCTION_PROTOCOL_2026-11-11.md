# E12-B：原始基元归纳与迁移证伪协议

日期：2026-11-11  
状态：[设计] 待实现、待执行；本文件不报告实验结果  
分支：research/e12-primitive-induction-2026-11-11

## 1. 研究问题

给定由潜在生成机制产生的复杂观测，系统能否在没有获得真实基元标签的情况下：

1. 发现可复用的潜在基元；
2. 将观测分解为基元及其关系；
3. 根据新证据合并、拆分或淘汰基元；
4. 将已归纳基元迁移到训练中未出现的组合；
5. 在证据不足或多个解释等价时拒绝过度确定的归纳。

这里的“基元”是任务相关的最小可复用解释单元，不预设其等于单个 token、单个属性或固定符号。

## 2. 核心假设与可证伪条件

- H12.1（可恢复性）：在生成机制可辨识、观测覆盖充分时，学习器可恢复与真实生成基元等价的分解。
- H12.2（组合迁移）：基元发现与组合规则学习分离后，未见组合泛化优于记忆型基线。
- H12.3（结构修订）：引入反例后，允许基元拆分/合并的系统比冻结字典系统更能修复系统性错误。
- H12.4（不确定性）：当观测不足以区分多个潜在分解时，系统应报告等价解释或弃权，而非虚构唯一答案。

若在多个随机种子、多个潜在世界和严格 OOD 划分下均无稳定增益，则对应假设不成立；不得以单个成功样例保留架构主张。

## 3. 数据生成：先保证可辨识性

建立受控的潜在世界生成器。每个世界包含：

- latent primitives：隐藏基元及其可观测属性；
- composition operators：有序、无序、角色绑定、互斥、条件组合等规则；
- observation renderer：将潜在结构渲染为可见特征；
- intervention：对一个基元或关系做受控替换；
- counterexample：专门区分竞争性解释的反例。

生成器必须导出 oracle 元数据，但训练阶段不得向学习器暴露基元 ID、真实分解或规则标签。

关键防泄漏约束：

- train/test 按组合结构和规则族切分，不按随机样本简单切分；
- 同一潜在对象的近重复渲染不得跨越 train/test；
- 生成器种子、世界 ID 和规则 ID 不得成为模型输入；
- oracle 只用于离线评分和可辨识性审计；
- 若两个潜在世界对当前观测完全等价，应标记为不可辨识，不计作学习器错误。

## 4. 实验组

A. Memorization：训练样本查表与最近邻，建立记忆基线。  
B. Flat learner：不显式建立基元结构的 MLP/线性模型。  
C. Fixed dictionary：使用预定义基元字典，不允许结构演化。  
D. Induction-only：允许发现基元，但不允许合并/拆分。  
E. Adaptive induction：发现、合并、拆分、淘汰均由证据和任务反馈驱动。  
F. Oracle decomposition：使用真实基元分解，作为可达性能上界，不视为可部署学习器。

所有学习器使用相同训练样本、相同信息预算，并尽可能匹配参数量与计算预算。记录无法严格匹配的差异。

## 5. 必须分开的评估任务

### T1：基元恢复

测量预测分解与 oracle 分解之间的等价匹配质量。允许基元 ID 置换；不能直接比较任意编号。

### T2：未见组合迁移

测试集使用训练阶段未出现的基元组合，但组成基元均在训练中出现。报告 exact match、precision、recall、F1。

### T3：未见规则族迁移

测试集引入训练中未出现的组合算子或关系角色。此项比 T2 更难，必须单独报告，不得混称为组合泛化。

### T4：反例驱动结构修订

先让系统形成一个错误但能解释训练样本的基元划分，再提供区分性反例。测量修订是否发生、修订是否局部、旧任务是否出现灾难性退化。

### T5：不可辨识性与弃权

构造观测不足或存在多个等价解释的样本。测量系统是否识别不确定性、是否给出多个候选分解，以及错误自信率。

### T6：分布漂移

逐步改变基元频率、属性噪声和组合分布，观察结构是否稳定，是否过度频繁地创建或拆分基元。

## 6. 核心指标

- Primitive recovery：置换不变的基元匹配 F1 / variation of information；
- Composition OOD：exact match、micro/macro F1；
- Rule-family OOD：按规则族分别统计；
- Revision quality：反例修复率、无关结构改动率、旧任务遗忘率；
- Calibration：Brier score、ECE、错误自信率、弃权覆盖率；
- Efficiency：候选基元数、结构编辑次数、推理延迟、峰值内存、计算量；
- Stability：跨随机种子均值、标准差和最差分位数。

不能把弃权样本简单当作错误，也不能只报告已回答样本的准确率；必须同时报告覆盖率和选择性风险。

## 7. 结构演化的最小操作语义

候选基元结构只允许四种显式编辑：

- CREATE：由重复且可复用的证据模式提出新基元；
- MERGE：两个基元在区分性任务上不可区分，且合并不损害预测时提出合并；
- SPLIT：一个基元内部存在稳定、可复现且能被干预区分的子群时提出拆分；
- RETIRE：长期无效、冗余或被更好解释替代的基元进入淘汰候选。

每次编辑必须附带：支持证据、反例检查、影响范围、置信度、回滚点。没有证据的编辑不得执行。先记录提案，再由验证器决定接受、拒绝或延期。

## 8. 易象研究接口：不提前绑定答案

阴阳、四象、八卦、卦变与五行在本实验中只作为可选的结构先验候选，不作为 oracle 标签。

必须比较：

1. 无易象先验；
2. 仅加入一般互补/对立关系先验；
3. 加入状态转化先验；
4. 加入完整候选易象映射；
5. 打乱映射或随机置换的负对照。

只有在相同数据与预算下，候选先验在预注册任务上稳定优于无先验及负对照，才可声称存在增益。传统概念与潜在变量的对应关系必须允许被数据拒绝。

## 9. 运行与报告纪律

- 每个配置至少 5 个种子；关键结论建议 20 个以上。
- 先冻结生成器和划分，再运行模型。
- 记录代码 commit、配置、种子、运行环境和原始指标。
- 同时报告均值、标准差、置信区间和失败案例。
- 不允许从测试集反馈修改规则后再把同一测试集当作独立验证集。
- 本协议本身属于 [设计]；只有实际运行并保存可复现数据后才能标记为 [结果]。
