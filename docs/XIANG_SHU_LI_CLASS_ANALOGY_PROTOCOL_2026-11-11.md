# 象—数—理—类象：CPG-EI 可检验认知协议

日期：2026-11-11  
状态：研究协议 / 待实验；不是已验证的性能结论  
归属：CPG-EI v1 表征研究层  
原则：传统概念提供候选结构，不提供免检真理

## 1. 研究目标

把“象数理”“取象比类”“卦变”“三进制状态”等思想转成可执行、可证伪的计算假设。核心不是把传统术语直接改名为神经网络模块，而是研究三类信息如何协作：

- **象（Xiang）**：对对象、事件、状态、位置、变化和关系形态的结构化观察。
- **数（Shu）**：状态数量、离散/连续坐标、组合空间、编码、约束、计数与运算。
- **理（Li）**：跨观察保持的关系、不变量、条件、机制候选和状态转移规律。
- **类象（Analogy by structure）**：在两个领域之间寻找部分、带类型、保留关系角色的结构映射，并用新证据检验迁移是否成立。

四者不是同义词，也不应压成一个“易学 embedding”。

## 2. 象、数、理的计算分工

### 2.1 象：结构化观察，而非表面标签

象层输出带来源的观察对象与关系候选，例如：

- 对象及其属性、状态、位置、方向、时间；
- 事件及其参与者、顺序、前置条件和结果；
- 局部形态、对称、互补、包含、相邻、相对位置；
- 变化前后的差异及可观测轨迹。

象层允许多种视角描述同一对象。视觉相似、词语相似或符号同名只能产生候选，不能直接证明两个对象同类。

### 2.2 数：显式状态空间与组合约束

数层负责回答“有哪些可能状态、组合和约束”，包括：

- 状态基数 K 与每个变量的取值域；
- 编码基数/位宽 R；
- 因子分解、组合阶数和稀疏超边；
- 计数、模运算、对称群、置换和状态转换；
- 搜索空间规模、预算、可辨识性和剩余假设数。

必须区分**语义状态基数**和**机器编码基数**。三值语义可编码为两位二进制；六位二进制可索引 64 种状态。编码不同不代表表达能力天然不同。

### 2.3 理：可检验的不变量与机制候选

理层不存放不可质疑的“定理表”，而是存放带范围的候选约束：

- 关系保持：映射前后的关系角色、方向、符号、顺序是否一致；
- 条件规律：在何种前提下成立，哪些条件改变会使其失效；
- 状态转移：输入状态、动作/条件与结果之间的可检验关系；
- 约束冲突：哪些证据不能同时成立；
- 反例边界：已知在哪些对象、环境或时间范围内失效。

“理”必须能产生可预测的差异。仅能事后解释、不能区分竞争假设的规则，不算已识别机制。

## 3. 类象的形式化：部分关系保持映射

给定源领域结构图：

`G_s=(V_s,R_s,F_s)`

和目标领域结构图：

`G_t=(V_t,R_t,F_t)`

一个类象候选定义为：

`M=(f_V,f_R,\phi,\Omega,E^+,E^-)`

其中：

- `f_V`：源对象/属性到目标对象/属性的部分映射；
- `f_R`：源关系到目标关系的映射；
- `\phi`：允许的变换，如方向翻转、尺度变化、角色重命名；
- `\Omega`：映射的适用范围与前提；
- `E^+`：支持该映射的证据；
- `E^-`：反例、冲突和失败条件。

### 3.1 关系保持约束

若源领域存在关系：

`r_s(a,b,c)`

映射后不能只检查 `a,b,c` 的外观相似，而要验证：

`r_t(f_V(a),f_V(b),f_V(c)) \approx f_R(r_s)`

这里的“约等于”必须由预先声明的关系类型兼容规则定义，不能在观察到结果后临时放宽。

对有向关系，必须保留角色位置；对无序关系，才允许置换不变。对状态转移，还需检验：

`f_V(T_s(x,u)) \approx T_t(f_V(x),f_U(u))`

即映射是否与变化过程相容，而不只是静态形态相似。

### 3.2 类象的四级证据

1. **表象候选**：特征或形态相似，尚无关系验证。
2. **结构候选**：对象与关系角色可以对齐，但可能存在竞争映射。
3. **关系验证**：在独立 Gate 上通过关系保持和反例测试。
4. **迁移验证**：在未见对象、未见场景或新状态转移上仍能预测。

只有第 4 级才允许称为跨域迁移成功。前三级分别保留其状态，不可统称“发现类象”。

## 4. 象—数—理协同闭环

推荐的数据流：

```text
Observation / provenance
        |
        v
XIANG: parse objects, events, positions, relations
        |
        v
SHU: enumerate state spaces, factorization, constraints
        |
        v
LI: propose invariants, conditions, transition rules
        |
        v
Analogy candidate generator
        |
        v
Identifiability + counterexample search
        |
        v
Commit -> independent Gate -> Reveal
        |
        v
Candidate lifecycle / revision / transfer
```

协同规则：

- 象层提出“可能对应什么”；
- 数层计算“有哪些状态和组合仍然可能”；
- 理层检验“哪些关系在什么条件下保持”；
- 类象模块提出跨域映射；
- E09 管理预测—反馈证据；
- E12-A6 管候选结构生命周期；
- E12-A20 管有限域精确推演与因子图消息传递；
- E03 负责多个竞争映射的仲裁；
- CSL 负责依赖失效和重验证，不复制生命周期状态机。

任何一个层都不能绕过独立 Gate 或锁定测试。

## 5. 周易、太玄、阴符应拆成正交实验因素

不能直接比较“周易模型”和“太玄模型”，因为它们可能同时改变状态基数、编码、关系先验、观察策略和记忆更新。至少拆成以下因素：

| 因素 | 可操作变量 | 必要对照 |
|---|---|---|
| 语义状态基数 | K=2 / K=3 / K>3 | 容量匹配的任意 K 状态模型 |
| 编码基数 | 二进制 / 三进制 / 混合编码 | 同语义状态、不同编码 |
| 状态分解 | 六位结构 / 三值结构 / 无结构 | 随机分解、可学习分解 |
| 关系先验 | 互补、层次、生成/制约候选关系 | 随机置换、反向关系、无先验 |
| 转移先验 | 卦变式稀疏状态变化 | 通用有限状态转移学习器 |
| 观察策略 | 主动测量、时机/位置条件 | 均匀随机、UCB、信息增益 |
| 更新策略 | 证据触发的修订/退化/合并/分裂 | 冻结、批量重训、无门控更新 |

周易的阴阳、四象、八卦、六十四卦可作为不同层次的二元结构假设；太玄三值结构作为 K=3 的状态假设；阴符经相关思想主要作为动态观察、时机、条件变化和策略更新假设。不要把三者分别简化成“二进制、三进制、动态算法”，它们都还需要明确的计算变量和任务定义。

## 6. 预注册实验矩阵

最小实验至少包含以下组别：

- B0：无传统结构先验；
- B1：随机同容量编码；
- B2：可学习状态编码；
- B3：固定二元结构先验；
- B4：固定三值结构先验；
- B5：可学习关系先验；
- B6：象—数—理联合候选生成与验证；
- B7：打乱符号名称但保留结构；
- B8：反向/错误先验压力测试。

所有组别必须匹配训练数据、参数规模、总计算预算、候选数量和 Gate 访问成本。若无法匹配，必须报告差额并限制结论。

### 6.1 任务族

1. **表象扰动**：表面特征变化但关系结构不变，测试是否过度依赖外观。
2. **关系近邻反例**：对象相似但关键关系角色改变，测试是否错误类比。
3. **角色置换**：关系成员顺序变化，区分有向与无向关系。
4. **状态基数迁移**：从二元状态迁移到三值或更高基数状态。
5. **机制迁移**：相同关系结构在不同对象/场景中实例化。
6. **动态迁移**：在未见状态转移和条件变化下预测结果。
7. **先验反转**：人为让传统候选先验与数据相反，检验系统能否拒绝或修订先验。

### 6.2 指标

- 结构映射精确率/召回率；
- 关系角色保持率；
- 反例发现率和错误类比率；
- 未见对象、未见场景、未见机制的迁移准确率；
- coverage、selective accuracy、abstention；
- 校准误差与置信区间；
- 搜索节点数、候选数、总计算量、wall-clock、内存；
- 结构复杂度、修订次数和错误修订率。

统计单位应是独立世界/episode/seed。不能把同一世界中的多个相关查询当作独立样本。所有失败、弃答和预算耗尽都进入分母。

## 7. 必须加入的反例与停止条件

以下情形必须拒绝或降低类象状态：

- 表面相似但关系角色不一致；
- 映射依赖目标领域的 evaluator-only 信息；
- 多个映射在现有 Support 上观察等价；
- 关系在 Gate 中不保持；
- 仅在同一对象或同一来源实例中有效；
- 反向先验比原先验更符合证据；
- 新条件使原转移规律失效；
- 搜索预算不足以排除竞争假设。

禁止从卦名、爻位、五行标签或三值编码直接推断现实因果。传统关系只能作为候选先验，必须允许随机化、反转、学习和弃用。

## 8. 与当前工程接口的连接

当前 CPG-EI DTO 可承载候选引用、scope、grammar version、definition digest、证据引用、结构 lineage、推理状态和预算。下一版 representation adapter 还需要显式表达：

- `representation_family`：zhouyi / taixuan / yinfu / generic；
- `semantic_cardinality`：实际状态基数；
- `encoding_radix` 与 `encoding_width`；
- `factorization_schema`；
- `relation_prior_id` 与 prior provenance；
- `mapping_scope`、`role_alignment`、`allowed_transformations`；
- `counterexample_refs` 与 `validation_status`。

这些字段不应塞进不透明的字符串或仅靠文件名推断。建议在 MTS-0 通过后定义版本化的 `RepresentationSpec` 和 `AnalogyMapping` DTO。

## 9. 实施阶段

- **XSL-0：协议** — 定义 RepresentationSpec、AnalogyMapping、关系保持验证器和失败状态。
- **XSL-1：小规模精确验证** — 通过 E12-A20 穷举小型源/目标结构映射，生成可复核 oracle。
- **XSL-2：候选生命周期** — 用 E12-A6 管理表象候选、关系候选、验证、挑战、修订和退役。
- **XSL-3：证据治理** — E09 commit-before-reveal，分离 SUPPORT / GATE_DEV / GATE_FINAL / LOCKED_TEST。
- **XSL-4：多种子 OOD** — 独立对象、来源实例、场景和关系角色迁移。
- **XSL-5：主动观察** — 研究阴符启发的观察策略能否在等预算下减少不确定性。
- **XSL-6：连续表示** — 仅在离散结构实验可信后接入神经编码器和多模态输入。

## 10. 当前结论

象—数—理—类象可以成为 CPG-EI 的重要研究框架，但它的计算价值必须落实为可检验的结构表示、关系映射、状态运算和动态规律。它不是给模型增加一套神秘符号就会自动产生智能。

最关键的判据是：**能否在表面特征变化、对象替换、关系置换和新场景下，保留真正有效的结构关系，同时识别并拒绝错误类比。**

在此之前，项目只能说建立了研究假设和实验协议，不能宣称传统易学结构已经提升模型智能。
