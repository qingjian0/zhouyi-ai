# E09-B0.3：增量合取索引实验

日期：2026-11-11  
状态：研究原型；需要 CI/本地测试验证。  
基础：E09-B0.2 Prequential Runner。

## 假设

对固定 arity 的合取 DSL，新观测只可能影响与该观测匹配的模式。若每个变量可选择“约束为观测值”或“忽略”，单条观测只匹配 (2^d) 个模式，而完整候选空间为 (prod_i(|D_i|+1))。

因此可以维护模式充分统计量，不必在每次更新时重扫全量历史样本或枚举完整模式空间。

## 实现

`prototype/e09_incremental_learner.py` 实现：
- 每个输入赋值的标签集合；
- 每个被观测匹配的模式的总支持数与分标签支持数；
- 新的唯一输入只更新 (2^d) 个模式；
- 同一输入同标签重复出现不重复计数；
- 同一输入出现冲突标签时，撤销先前唯一标签对 (2^d) 个模式的贡献，并将该输入隔离；
- 预测仅接受支持数达到阈值且所有匹配证据标签一致的模式；多标签冲突时拒答。

更新成本以 `incremental_pattern_updates` 记录。该计数是逻辑索引写入次数，不等于 wall-clock、CPU 指令或内存峰值。

## 复杂度

令变量数为 d，域大小为 `|D_i|`：
- 传统全空间枚举候选规模：`product(|D_i| + 1)`，每个标签分别检查。
- 本实现每条新唯一输入：恰好 `2**d` 个模式计数更新。
- 预测：至多 `2**d` 个匹配模式查询（当前原型在每个模式上扫描已存 label 统计，后续可优化为模式到标签的倒排索引）。
- 内存：与实际出现过的匹配模式及输入数相关；最坏仍可能随观测数增长。

## 重要边界

这是有限合取 DSL 上的真正局部充分统计量更新，不是通用神经网络增量训练，不是开放世界概念发现。它也不是 E09 现有 greedy-cover learner 的完全等价替代：它保留全部安全模式，不执行全局贪心覆盖。因此必须以独立评测臂呈现，不能直接宣称准确率或结构压缩优于 batch baseline。

## 必须完成的对照实验

1. 同一数据流、同一 reveal 顺序、同一预测时点：冻结模型 / batch refit / 增量索引。
2. 预注册随机种子、变量数、域大小、min_support、标签噪声和漂移方式。
3. 报告 prequential accuracy、coverage、abstention、冲突隔离数。
4. 同时报告模式更新数、全量候选评估数、训练历史扫描数、wall-clock 与峰值内存。
5. 加入反向数据顺序、标签冲突、概念漂移和域外输入。
6. 与 greedy-cover baseline 比较时，单独报告模型表达差异（全安全模式 vs 贪心子集）。

## 可证伪条件

- 若增量索引在相同预算下没有降低更新成本，则不支持局部更新效率假设。
- 若其 prequential 风险或拒答率明显恶化，则不能以速度优势掩盖质量下降。
- 若冲突撤销、重复样本或顺序改变导致状态不一致，则原型不合格。
