# E13-B3：有限候选发现与独立验证

## 研究问题

B2 要求显式提供跨领域映射假设。B3 研究系统能否在一个明确定义、有限且可审计的假设空间中提出候选，并将候选生成与候选验收分离。

## 当前实现

`prototype/e13_b3.py` 从源/目标图 schema 枚举：
- 实体类型的 injective 映射；
- 同元数关系 schema 的 injective 映射；
- 每个源关系的具名角色排列；
- 调用 B2 `validate_bridge` 做独立结构验证。

上下文键映射必须由调用者显式提供。不会从相似名称猜测上下文含义。

## 输出语义

- `COMPLETE`：有限搜索空间已完整枚举，至少有一个通过结构验证的候选；所有通过者都保留。
- `NO_VALID_CANDIDATES`：搜索完整结束，但没有候选通过。
- `NO_CANDIDATES`：schema 角色语义不受支持。
- `BUDGET_EXHAUSTED`：预算内无法完整搜索；返回空候选列表，防止将部分枚举误认为完整结果。

每个候选保留唯一 ID、来源、理由和映射内容。多个有效候选不按启发式分数强制压成唯一结果。

## 关键边界

1. 这只是有限 schema 级枚举，不是开放世界语义发现。
2. 验证只检查 B2 编码的结构约束，不证明物理因果或机制等价。
3. 当前角色排列搜索复杂度随目标角色排列数增长；预算是硬限制。
4. 候选排序、主动区分观测、反例反馈和跨轮版本空间更新尚未实现。
5. 枚举器仅支持具名有序角色；未知/无序角色保持拒绝。
6. 需要防止 evaluator 泄漏：候选生成只能使用公开 schema/context mapping，不能读取隐藏标签。

## 下一步实验

- E13-B3-A：小图穷举正确性，对照独立 brute-force oracle。
- E13-B3-B：候选数、运行时间、内存与预算耗尽曲线。
- E13-B3-C：多个结构等价候选的歧义保留。
- E13-B3-D：反例查询选择：寻找使候选预测分歧最大的输入。
- E13-B3-E：隐藏标签隔离与 OOD 负迁移测试。

本模块尚未证明自动类象能力；它提供可复现的有限候选搜索基线。
