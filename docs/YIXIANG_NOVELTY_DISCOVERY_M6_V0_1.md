# M6 残差驱动的新象提议与版本治理 v0.1

## 1. 目标与边界

M6 处理 M3/M4/M5 之后仍未解释的结构残差：当已有类象无法解释一组反复出现的观察时，提出可供审查的新结构候选。

当前原型的输入是**已经人工或上游程序标注的残差案例**。它不从原始古文、图像、传感器或自然语言自动抽取残差，也不宣称已发现客观新规律。

“新”只表示该精确 typed signature 不在调用者提供的 known_signatures 中；它不意味着整个知识库、全部古籍或现实世界中从未出现过。

## 2. 残差案例表示

每条 ResidualCase 保存：

- residual_id、observation_id：残差与原始观察的可追溯标识；
- domain：材料所属领域；
- signature：由 (dimension, relation, value) 构成的类型化结构签名；
- context：时空、尺度、阶段、位置等情境键值；
- evidence_refs：支持该残差记录的来源引用。
- evidence_lineage：每个 evidence_ref 对应的来源独立性组（`(evidence_ref, independence_group)`）；未声明时独立性为 UNKNOWN，不能满足多来源门槛。

签名要求排序、字段非空且不重复，以确保确定性分组。不同维度或关系类型不因表面词汇相似而合并。

## 3. 候选生成

原型按完整 typed signature 精确分组，并采用显式门槛：

- 至少两个不同 observation；
- 默认至少两个领域；
- 默认至少两个不同的显式来源独立性组；多个 URL、镜像、转录或转载若来自同一底本/转引链，只计一个组；缺少 lineage 映射不计为独立来源；
- 已知签名排除；
- 任何输入不完整或重复 ID 均拒绝处理。

候选对象保留 evidence_ref → independence_group 的完整映射及去重后的独立组列表；同一 evidence_ref 在不同残差中若被赋予冲突组，直接拒绝。结果按支持案例数、领域数和稳定候选 ID 排序。当前不计算伪精确的“新颖度概率”，也不把频次直接当作真实性。调用方提供的 known_signatures 同样必须满足类型、排序和唯一性约束。

不同签名不做模糊聚类。后续如引入近似聚类，必须显式报告距离定义、阈值敏感性、错误合并风险和反例。

## 4. M3/M4/M5 的衔接

- **M3**：提供竞争解释、证据层、反例与未决状态。残差不能只因不符合当前胜出假设而被删去。
- **M4**：检查残差是否由条件变化、关系反转或干预边界造成；条件未知不能伪装成结构异常。
- **M5**：优先提出能区分“测量噪声、缺失条件、分布变化、真实结构缺口”的下一项非干预观察。
- **M6**：仅在重复、跨域且具备可追溯证据的残差达到门槛后，提出新结构候选。

建议的闭环：

`竞争解释 → 预测 → 主动观测 → 残差 → 噪声/条件/分布检查
→ 候选结构 → 独立留出验证 → 人工审查 → 版本化`

## 5. 版本与回滚

候选初始状态为 PROPOSED。只有显式审查调用才能产生 ACCEPTED 或 REJECTED 新版本；旧版本保持不可变。回滚也创建一个新版本，状态回到 PROPOSED，并记录父版本与原因。

当前原型只提供候选版本记录，不提供多人签名、数据库事务、权限管理或自动发布。调用方必须持久化每个版本，不可只保存最新版本。

## 6. 防止自证与数据泄漏

1. 生成残差的模型、原始观察和证据来源必须可追溯；每条 evidence_ref 必须映射到一个来源独立性组，才能计入多来源门槛。
2. `independence_group` 是调用方声明的来源谱系标识，不是程序对文献学独立性的自动认证；需人工核验版本、底本和转引关系。
3. 领域/作品/版本/主体应在数据切分前分组；同源转录或同一轨迹不能分散到训练与留出集。
4. 候选生成阶段使用的 evidence_refs 不得再次被称为独立留出验证。
5. 需要新来源、不同主体或独立数据集复现，才可提升证据等级。
6. 已知类象的例外条件、缺失条件和标注错误优先排查，不能为了增加新象数量而拆分。
7. 接受候选必须记录审查者、理由、适用范围、反例与失败标准。
8. 新象不能自动成为新的先验或覆盖旧类象；旧版本及其有效范围必须保留。

## 7. 验收指标

后续完整实验至少报告：

- 候选精确率：人工审查后保留的比例；
- 新结构复现率：独立留出数据中的复现比例；
- 误创建率：噪声、条件缺失或分布变化导致的伪新象比例；
- 发现延迟：从首次残差到稳定候选的样本/观测数；
- 回滚率及回滚原因；
- 相对“仅 M3/M4/M5、不启用 M6”的增益；
- 计算、标注和人工审查成本。

不得只报告候选数量或训练集拟合提升。

## 8. 当前实现

- `prototype/yixiang_novelty.py`：精确签名分组、跨域/多来源门槛、确定性候选 ID、显式审查版本和回滚版本；只有不同的显式来源独立性组才计入独立证据门槛。
- `tests/test_yixiang_novelty.py`：覆盖跨域重复残差、已知签名排除、门槛不足、审查不可变性、回滚和缺失证据。
- 当前状态是透明规则基线，不是学习型新象发现系统；需在 CI 和真实独立数据上验证后再扩大能力。
