# RSDN-N2：可学习关系状态动力学研究设计

日期：2026-11-11  
状态：研究设计与可证伪实验规格；不是已训练模型，也不是性能结论  
基线：ZNCA 当前研究分支 head `3e7bc3d52d5286635213b6f2029aa426aeb5f72f`  
分支：`research/rsdn-n2-learnable-relational-dynamics-2026-11-11`

## 0. 本轮结论

RSDN 不应被实现成“把 Transformer 的 token 换成图节点，再做一遍 GNN 消息传递”。

本轮提出的核心计算对象是**关系状态变化（Relational State Edit）**：

- 认知状态不是一个必须整体重算的向量，而是有来源、类型、时间和版本的关系状态集合；
- 学习目标不只是预测下一段 token 或下一张图，而是预测在给定观察、动作、条件下，哪些事实应新增、修订、限定、撤回或分支；
- 变化预测必须同时给出影响范围、证据需求和不确定性；
- 多个候选变化可以并行提出，但只有经过约束和证据检查的变化才能进入已接受状态；
- 易象算子作为有明确定义和版本的候选结构操作参与计算，不是预先写死的真理，也不是给节点贴八卦标签。

因此，RSDN-N2 的最小研究目标不是“造出一个大模型”，而是验证：**关系状态编辑是否能成为一种可学习、可组合、可局部更新、可跨域迁移的认知计算原语。**

## 1. 研究边界与已有工作的关系

近期结构化世界模型已证明对象与交互关系可以共同学习。FIOC-WM 将对象和交互结构纳入统一世界模型；Dyn-O 研究对象中心状态及动态相关/无关因素；Causal-JEPA 使用对象级潜变量遮蔽预测，迫使模型利用周围对象与交互信息进行预测。

这些工作提供重要基线，但不等同于 RSDN。RSDN 的差异化假设是把**带证据来源的状态编辑、关系角色变换、类象迁移、分支版本和验证状态**作为一等计算对象。

参考：
- FIOC-WM, NeurIPS 2025: https://proceedings.neurips.cc/paper_files/paper/2025/hash/8187faaf6759ef6d4e93293339bc656e-Abstract-Conference.html
- Dyn-O, NeurIPS 2025: https://papers.nips.cc/paper_files/paper/2025/hash/b03b9ec80fc599bb5161746edff0f322-Abstract-Conference.html
- Causal-JEPA, ICML 2026: https://proceedings.mlr.press/v306/nam26c.html
- Systematic Reasoning About Relational Domains With GNNs: https://arxiv.org/abs/2407.17396

**不可越界的结论：**这些论文不证明 RSDN 已经优于 Transformer/GNN，也不证明易象先验天然有效。RSDN 必须在相同数据、参数量、训练 FLOPs、推理预算和硬件下接受对照实验。

## 2. 统一状态模型

定义一个带版本的认知状态：

`S_t = (O_t, R_t, H_t, C_t, T_t, E_t, D_t)`

- `O_t`：对象、实体与属性状态；
- `R_t`：二元关系；
- `H_t`：高阶关系/超边，参与者可有有序角色；
- `C_t`：作用条件、约束、范围和上下文；
- `T_t`：时间有效区间、事件顺序和版本；
- `E_t`：证据、来源片段、支持/反证和来源独立性；
- `D_t`：派生依赖 DAG，记录哪些状态由哪些观察、规则和推断产生。

状态中每条断言必须携带 epistemic status：
`OBSERVED | INFERRED | HYPOTHESIS | DISPUTED | REFUTED | RETRACTED`。

观察和推断不能覆盖彼此。撤回推断不删除原始事件；新证据可以修订推断，但必须保留父版本和 provenance。

## 3. 核心输出：关系状态编辑

定义 Edit：

`e = (op, target, payload, scope, valid_time, evidence_refs, confidence, parent_version)`

其中 `op` 仅允许明确的有限集合：

| 操作 | 含义 | 约束 |
|---|---|---|
| ADD | 新增对象、关系、条件或事件 | 必须有来源或明确标为假设 |
| UPDATE | 修订可变属性或状态 | 保留旧版本与变更原因 |
| QUALIFY | 增加条件、范围、时间或例外 | 不得悄悄扩大原断言 |
| RETRACT | 撤回推断/假设 | 不删除原始观察 |
| BRANCH | 创建竞争解释或反事实状态 | 不污染已接受主状态 |
| LINK_EVIDENCE | 关联支持、反证或独立证据 | 不把相关性当独立证据 |
| NOOP | 明确不改变状态 | 允许拒绝更新 |

一次转移不是重建整个状态，而是预测一个稀疏编辑集合：

`ΔS_t = {e_1, e_2, ..., e_k}`

`S_{t+1} = Apply(S_t, Accept(ΔS_t, Evidence, Constraints, Budget))`

Apply 必须是可审计、可回滚、可重放的确定性状态转换。学习模型只提出候选编辑，不直接写入权威事件账本。

## 4. RSDN-N2 模块分解

### 4.1 Observation Grounder

将文本、图像、音频和工具结果转换为带来源的观察候选。保留 source span、时间戳、模态、抽取置信和歧义。它不能自行将模型推断升级为事实。

### 4.2 Relation Inducer

发现对象之间可能存在的关系和角色：
- 关系类型候选；
- 角色语义与方向；
- 高阶参与者；
- 作用条件；
- 时间顺序；
- 置信区间与未知项。

不要默认所有关系都是二元边；例如“某人通过某工具在某时间把某资源从 A 交付给 B”需要多个有语义角色的参与者。

### 4.3 State Encoder

把活动子图编码为稀疏局部状态。编码应区分：
- 对象身份；
- 对象属性；
- 关系类型；
- 角色身份；
- 关系发生的条件和时间；
- 证据质量与来源谱系。

置换对象 ID 不应改变关系语义；但交换 donor/recipient 等语义角色应改变状态。

### 4.4 Operator Bank

算子不是任意神经层的别名。每个算子有独立 schema：

`Operator = (id, version, input_schema, preconditions, transform, invariants, scope, inverse, evidence_policy)`

第一组算子：
- `IDENTITY`：恒等；
- `ROLE_PERMUTE`：显式角色置换；
- `RELATION_INVERSE`：关系逆变换，仅在定义域允许时；
- `TIME_REVERSE`：时序反转，不能自动解释为因果逆转；
- `POLARITY_DUAL`：极性/阴阳对偶，不能简化为参数交换；
- `DECOMPOSE`：高阶关系分解；
- `COMPOSE`：关系合成；
- `MUTUAL`：提取整体结构内部的局部关系；
- `CROSS_DOMAIN_MAP`：跨域部分映射。

错、综、互、变、阴阳对偶必须是语义不同、版本不同的算子。传统解释体系应带来源与版本；不将现代工程定义冒充古籍原义。

### 4.5 Transition Proposer

输入当前局部状态、最新事件、目标、约束及可用算子，输出多个候选编辑集合。模型可以使用小型 MLP、状态空间单元、稀疏关系网络或混合模型；架构选型由对照实验决定。

候选不是自由生成的任意图，而是类型化 Edit 集合。候选之间允许：
- 不同解释；
- 不同关系角色；
- 不同时间范围；
- 不同类象映射；
- 不同预测路径；
- 明确的 NOOP / ABSTAIN。

### 4.6 Constraint & Evidence Verifier

验证器分成硬约束和软证据：
- 硬约束：类型、角色数、关系签名、时间逻辑、身份约束；
- 软证据：支持强度、来源独立性、历史预测表现、反例覆盖；
- 校准：预测置信是否与实际正确率匹配；
- 预算：超出时间/内存/搜索预算必须返回 BUDGET_EXHAUSTED，而不是伪装成无结果。

硬约束失败的候选直接拒绝；软证据不足时保留为 HYPOTHESIS，不可升级为 OBSERVED。

### 4.7 Branch Scheduler

对候选状态采用共享只读父状态 + 稀疏 delta 的方式。分支之间不复制整个历史图。每个分支有独立版本、编辑列表、资源预算和证据账本。合并时必须检测冲突，不能简单覆盖。

### 4.8 Realizer

从被接受的结构化状态和 Action Plan 生成语言、代码或工具调用。表达器可替换；替换表达器不应改变已经选定的事实和推理结果。

## 5. 学习目标：学习状态变化，而不是仅学习状态相似

建议分阶段训练，先单任务再联合训练。

`L = λ_edit L_edit + λ_role L_role + λ_trans L_trans + λ_inv L_invariant + λ_cf L_counterfactual + λ_ana L_analogy + λ_cal L_calibration + λ_budget L_budget`

### 5.1 编辑集合损失 `L_edit`

目标是预测真实编辑集合。使用操作类型分类、目标对象/关系定位、参数回归或分类、编辑集合匹配损失。由于预测编辑顺序通常不重要，不能简单用逐项序列交叉熵作为唯一监督；可使用 bipartite matching / set prediction。

### 5.2 角色语义损失 `L_role`

对同一关系进行实体 ID 置换时，语义保持；对 donor/recipient、source/destination 等角色交换时，除非算子明确允许，否则应预测语义变化或验证失败。

### 5.3 状态转移损失 `L_trans`

给定前态和观察/动作，预测稀疏状态变化。评估变化集合 precision/recall/F1、精确编辑匹配率，以及多步 rollout 后状态漂移。

### 5.4 不变量损失 `L_invariant`

对合法变换保持不变量，对非法变换识别违反项。不要把所有变换都当增强数据；每个变换需明确哪些属性应保持、哪些应改变、哪些未知。

### 5.5 反事实损失 `L_counterfactual`

构造“若某对象不存在/角色互换/条件改变/事件未发生，状态会怎样”的配对样本。模型必须改变受影响的编辑，而不应无条件复制原结果。

### 5.6 类象迁移损失 `L_analogy`

训练源域与目标域之间的部分结构映射。正例不仅有对应关系，也要有明确的不对应关系和映射范围。负例包括：
- 表面词相似但关系不一致；
- 角色相反；
- 条件不满足；
- 时间结构冲突；
- 高阶关系被错误拆成二元关系；
- 应返回 NO_ANALOGY 的案例。

### 5.7 置信校准损失 `L_calibration`

使用 Brier score / calibration error 等独立评估置信校准。置信度、相似度、能量值和概率必须是不同字段，不得互相冒充。

### 5.8 资源预算损失 `L_budget`

在固定延迟、内存、候选数量和局部子图规模预算下，学习优先保留最有区分价值的候选。不能鼓励无界扩展候选树。

## 6. 易象算子如何成为学习机制

易象不是“八个类别 embedding”。建议采用**结构先验 + 可学习参数 + 证据验证**三部分：

1. 结构先验：为阴阳、爻位、上下卦、错综互变定义版本化、可测试的变换结构；
2. 可学习参数：学习某个结构算子在具体任务、领域和上下文中的适用概率及效果；
3. 证据验证：检查算子应用前后的不变量、预测结果、反例和适用范围。

每次调用都输出：
`(operator_id, input_state, candidate_output, invariants_expected, scope, evidence, validation_status)`

对同一数据集必须至少运行：
- 无易象先验；
- 易象算子启用；
- 随机结构先验；
- 同容量可学习通用算子；
- 传统解释配置 A/B（如使用不同流派语义）。

如果易象启用后没有稳定增益，或只在含有易学术语的数据集上提升，不得宣称它提供了通用认知优势。

## 7. 训练数据与评测任务

### 7.1 三层数据

**A. 可控合成关系世界**
- 对象、属性、二元关系和超边；
- 显式状态编辑；
- 条件、时间和反事实；
- 可生成任意长度的组合关系链；
- 生成时保留 oracle 状态与 oracle 编辑集合。

**B. 真实事件流**
- 公开、许可清楚的事件序列或工具交互轨迹；
- 观察、推断、纠错、撤回、冲突；
- 原始证据与派生状态分离；
- 不用语言共现伪造因果标签。

**C. 易象/类象语料**
- 古籍原文、注释、流派和现代解释分开标注；
- 每条解释保留出处、版本、上下文；
- 传统解释作为研究对象和候选算子来源，而不是现实世界事实标签；
- 允许互相冲突的解释并存。

### 7.2 必测基准

| 基准 | 主要能力 | 失败表现 |
|---|---|---|
| Relation Binding | 关系角色绑定 | donor/recipient 混淆 |
| Sparse Edit Prediction | 稀疏状态更新 | 无关节点被改写 |
| Higher-order Relations | 超边和多角色 | 降维成错误二元边 |
| Temporal Validity | 时间条件 | 把过期关系当当前事实 |
| Counterfactual Edit | 反事实变化 | 条件改变但结果不变 |
| Compositional OOD | 未见组合 | 记忆训练模板 |
| Depth OOD | 更长推理链 | 链长超训练分布就崩溃 |
| Cross-domain Analogy | 跨域迁移 | 表面相似导致错误类比 |
| No-Analogy | 拒绝类比 | 被迫给出错误映射 |
| Provenance Audit | 证据追溯 | 无法定位原始来源 |
| Branch Merge | 多分支冲突处理 | 覆盖或污染主状态 |
| Memory Recovery | 中断恢复 | 丢失状态版本/编辑 |

数据划分必须同时做 entity-disjoint、relation-combination-disjoint、domain-disjoint、time-disjoint 和 depth-OOD，避免相邻样本泄漏。

## 8. 强基线与消融矩阵

必须比较：
- Transformer encoder + edit decoder；
- GNN / relational message passing；
- object-centric world model；
- 规则/符号状态编辑器；
- RSDN 去掉易象算子；
- RSDN + 易象算子；
- RSDN + 随机算子；
- RSDN 去掉证据验证；
- RSDN 去掉分支机制；
- RSDN 只用向量记忆；
- RSDN 结构记忆 + 向量召回。

控制参数量、训练样本、训练 FLOPs、候选数、推理步数、检索预算、设备和量化精度。报告均值、方差、多个随机种子和置信区间。

## 9. 移动端与百万级历史的资源设计

RSDN 不承诺将 1M 历史全部放入 RAM，也不承诺固定 O(1) 查询。资源分层：

- 原始事件：磁盘 append-only；
- 结构状态：持久化、版本化、索引化；
- 活动子图：RAM 中有硬预算；
- 候选编辑：限制候选数、编辑数和分支深度；
- 模型参数：独立量化与加载策略；
- 来源片段：按需读取，不常驻全文。

每次更新的工作集只包含新增事件、被触发的依赖和有限活动子图。全库查询、全量重建和全局统计仍需按实际规模计费。

建议设备评测：
- 4GB / 6GB / 8GB RAM；
- 历史规模 10K / 100K / 1M / 5M / 10M 事件；
- 记录 PSS/RSS、索引大小、活动子图大小、每次更新延迟、查询延迟、磁盘 IO、峰值内存、功耗、温度、恢复时间；
- 内存压力时优先丢弃可重算候选缓存，不丢弃事件账本和来源谱系。

“1M 有效历史可检索”与“1M 原生注意力上下文”必须分别报告。

## 10. N2 的最小可证伪实验

### E-N2-01：编辑预测能否学到真正的状态变化
- 数据：可控合成事件流；
- 训练：只看短链；
- 测试：更长链、未见关系组合；
- 对照：Transformer、GNN、规则系统；
- 指标：精确编辑匹配、状态一致性、rollout 漂移。

### E-N2-02：角色绑定是否稳定
- 对对象 ID 做随机置换；
- 对语义角色做交换；
- 测试模型是否区分无意义 ID 变化和真实语义变化。

### E-N2-03：类象能否跨领域迁移
- 训练领域和测试领域对象完全不重叠；
- 测试结构关系迁移；
- 加入表面相似但结构不匹配的 hard negatives；
- 允许输出 NO_ANALOGY。

### E-N2-04：易象算子是否带来独立增益
- 无先验、易象先验、随机先验、可学习通用算子对照；
- 同参数量、同训练预算；
- 在未见领域测试，而不只测易学文本。

### E-N2-05：局部更新是否降低移动端工作集
- 逐步扩大事件账本；
- 固定局部任务和活动子图预算；
- 对比全图重算、普通 GNN 全图传播、RSDN 增量更新；
- 记录峰值内存、每次更新延迟、IO 和恢复正确性。

### 失败判据
出现以下任一情况，不得声称 N2 成功：
- 仅合成任务有效，真实事件流没有增益；
- OOD 深度增加后快速崩溃；
- 易象先验效果不优于随机先验；
- 结构状态和来源谱系不一致；
- 为降低内存而丢失精确事实定位；
- 多候选机制只增加计算，没有提高决策质量；
- 与强基线等预算比较没有可重复优势。

## 11. 研发交付顺序

1. 冻结 State / Edit / Evidence / Operator schema；
2. 写纯 Python 确定性 Edit Engine；
3. 构造合成关系世界生成器和 oracle；
4. 写评测器与基线；
5. 训练最小 Transition Proposer；
6. 接入 XSL 部分映射和拒绝类比；
7. 接入 YXO 版本化算子；
8. 做移动端存储、增量索引和资源测试；
9. 只有完成前述证据后，才扩展多模态和更大模型。

## 12. 本阶段决策

- **接受为研究假设：**以关系状态编辑为学习目标。
- **接受为接口原则：**模型提出候选，确定性验证器控制状态提交。
- **接受为记忆原则：**共享父状态 + 稀疏 delta + provenance。
- **接受为易象原则：**算子显式、版本化、可消融、可拒绝。
- **暂不决定：**底层采用 GNN、SSM、MLP、能量模型或混合结构；由相同预算实验选择。
