# E02-I：证据门控的关系结构演化

## 研究问题

关系被发现后，系统能否在后续数据窗口中识别成员增减、规则变化和关系消失，并在不被单次噪声诱导的前提下更新结构？

## 实验设计

- 每个时间窗口重新从训练数据发现候选，不把隐藏成员、规则或变化时刻传给发现器。
- 候选规则沿用 E02-H 的有限语言：8 个二值特征上的 2/3 元子集完整真值表。二元候选以 Gate 准确率门控；三元候选还必须超过最佳二元真值表基线至少 0.05。
- 每个窗口使用独立训练集与 Gate 集；Gate 只负责候选确认。每个实验 5 个窗口，20 个种子/场景，共 120 个实验。
- 关系变化必须连续两个窗口得到相同的新结构签名，才允许 RECONFIGURE。
- 单个 Gate 失败只触发 DEGRADE；连续两个失败才触发 RETIRE。
- 锁定测试数据不参与候选搜索或结构决策（本阶段先以独立 Gate 确认结构状态）。

## 六种预注册场景

1. stable：成员与规则不变。
2. member_add：关系从二元成员增加为三元成员。
3. member_remove：关系从三元成员减少为二元成员。
4. rule_change：成员不变，规则真值表取反。
5. transient_rule_change：规则仅在一个窗口反转，随后恢复原规则。\n6. disappear：关系信号消失，标签成为独立随机变量。

## 状态迁移

| 当前证据 | 结构动作 | 含义 |
|---|---|---|
| 首次有效候选 | CREATE | 建立关系 |
| 与当前签名相同 | KEEP | 保留当前结构 |
| 首次观察到新签名 | HOLD_PENDING | 暂存，不改变持久结构 |
| 连续确认相同新签名 | RECONFIGURE | 创建新版本并替换旧版本 |
| 首次 Gate 失败 | DEGRADE | 降低当前关系状态，不删除 |
| 连续 Gate 失败 | RETIRE | 退役关系 |

## 主要指标

- 稳定关系误重配置率；
- 单窗口瞬态变化误重配置率；
- 成员增加/减少的重配置召回率；
- 同成员规则变化的重配置召回率；
- 消失关系的退役召回率与延迟；
- 每次状态变化前所需确认窗口数；
- Gate 准确率、成对基线差值、候选搜索成本。

## 证伪标准

- 稳定场景频繁重配置：状态机对噪声过敏。
- 变化场景长期不重配置：系统无法跟踪结构演化。
- 消失场景不退役：旧关系无法遗忘。
- 变化只在单个窗口出现就触发重配置：重复确认机制失效。

## 限制

这是有限布尔规则空间上的合成实验；变化类型与两窗口确认策略均预先定义。它不是开放世界关系演化，也没有学习变化机制本身。候选生成仍是穷举子集与真值表搜索，不是开放式创造关系。
