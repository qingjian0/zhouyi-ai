# M12 条件约束的多路径类象竞争审计 v0.1

## 1. 研究问题

M11 将关系放进时间轨迹；M12 进一步处理一个共同起点到共同目标之间可能存在的多条解释/行动路径。核心问题不是“哪条路径看起来最像”，而是：哪些路径在相同目标与明确条件下有证据支持，哪些已被观察结果挑战，哪些因条件不匹配或证据不足必须保持未决。

## 2. 古典研究入口与文本边界

- 《墨子·小取》“其然也同，其所以然不必同”：同一结果不能直接证明路径机制相同。M12 因而要求显式保存每条路径的状态序列和关系签名。
- 《淮南子·说林训》“见物同，而用之异”及不同方法“得鱼一也”：同一目标可以由不同路径达到；路径不能因结果相同而被合并。
- 《周易·系辞下》“天下同归而殊涂，一致而百虑”：作为多路径、同归目标的经典研究入口，但不能据此断言所有目标都存在多条路径，亦不能把经文直接等同于现代路径规划算法。
- 《荀子·正名》及《墨经》名实辨析提醒：路径节点/关系签名的名称必须有稳定指称，不可仅凭词面相似合并。

经文、古注、现代解释和工程操作化必须分层。M12 的 PathCandidate、context_axes 和 evidence_refs 均为现代数据结构，并非古籍原生概念。

## 3. 操作化模型

每条路径包含：
- path_id：候选路径唯一标识；
- source_node / target_node：共同起点与共同目标；
- ordered_states：路径的有序状态签名；
- relation_signatures：该路径实际声称保持/调用的关系；
- context_axes：路径成立时的时、位、主体、任务、环境等条件轴；
- outcome：viable、failed 或 unknown；
- evidence_refs：支持该路径结果的证据引用。

竞争集包含至少两条路径，且所有路径必须具有相同起点与终点。不同路径应保留各自状态和关系结构，禁止只凭终点相同而折叠。

## 4. 条件门禁与裁决

- 目标情境必须声明全部 required_context_axes。
- 路径必须为每个必需条件轴提供取值；缺失则结构审计 BLOCKED。
- 路径条件与目标情境不一致时，进入 unresolved/context_mismatch，不直接判定路径在其他情境中无效。
- viable 仅表示调用方提交的观察结果标为可行且结构门禁通过；failed 表示结果标为失败；unknown 保持未决。
- 路径之间不得复用同一证据引用，以防同一条证据被重复当作多个独立路径的支持。
- 所有路径必须保留；不计算单一相似度排名，不输出“最优路径”。

## 5. 与 M7/M9/M10/M11 的关系

- M7：当前编排 M3–M6；M12 可作为后续候选路径裁决器接入，不直接修改 M7 的证据流。
- M9：提供多视角关系候选；M12 可把不同关系解释形成的路线作为竞争候选。
- M10：未来可对路径组合主张设计预注册实验；M12 自身不证明组合涌现。
- M11：提供动态快照和转移证据；M12 进一步比较同起点、同终点的不同轨迹。
- M8：未来应分层评估路径拒绝、未决和范围内可行性，特别是情境错配与证据复用。

## 6. 评估设计建议

后续基准应至少覆盖：
1. 同目标异路径：不同关系拓扑达到同一目标；
2. 同路径异情境：只改变时、位、主体或任务条件；
3. 表面同路径、关键边反转：检查关系方向是否被忽略；
4. 一条失败、一条可行：检查是否错误平均化；
5. 多条均可行：检查系统是否保留竞争而非强选赢家；
6. 路径未知：检查是否将未知误判失败；
7. 共享证据伪独立：检查同一证据是否被重复计数；
8. 共同终点但不同源点：检查是否错误放进同一竞争集。

## 7. 当前边界

M12 不做路径搜索、路径优化、未来预测、因果识别、概率估计或自动古文解释。输入结果由调用者提供，审计器只检查结构一致性、条件匹配和证据引用卫生。证据引用不重复不等于来源真实或独立，仍需 M8 来源谱系与人工核查。通过后只进入 HUMAN_REVIEW。

## 8. 验收

专项测试覆盖多条可行路径保留、失败路径隔离、未知路径保留、情境错配未决、必需条件缺失、共同端点、证据复用、重复 ID、输入结构和最低路径数量。
