# E13-C：动态机制类象与干预验证协议

日期：2026-11-11  
状态：有限确定性原型与实验协议；不代表开放世界因果发现已实现

## 1. 研究问题

E13-B 验证的是有限静态关系结构能否按显式类型、关系、角色和上下文映射。E13-C 增加时间和干预响应：

**若源域与目标域存在候选类象映射，那么源域机制对干预的响应，能否预测目标域在对应干预下的结果？**

静态图同构不构成机制等价证据。角色相同、关系方向相同，也可能有不同的响应方向、延迟、幅度、上下文边界或副作用。

## 2. 机制层数据对象

- `MechanismModel`：有限变量集合与确定性响应规则。
- `MechanismRule`：干预变量/取值、响应变量/取值、离散延迟步数、上下文。
- `InterventionQuery`：待执行的干预及上下文。
- `MechanismMap`：源/目标干预变量、响应变量、取值和上下文键的显式映射。
- `MechanismResponse`：目标响应变量、响应取值和延迟。
- `Evidence`：候选预测与独立目标模拟器/环境观测之间的比较结果。

当前原型把幅度/响应值离散化为符号取值，把时间离散化为 step；没有连续动力学、随机噪声或部分可观测状态。

## 3. 双边界验证

1. **候选预测**：只从源模型和显式映射生成目标域响应预测。
2. **独立观测**：目标模型单独执行对应干预，返回实际响应。
3. **比较**：变量、值、延迟全部一致才算该 query 上通过。
4. **更新**：可把各候选对同一 query 的预测交给 E13-B3-D，先按预测分歧选择干预；执行后再按观测过滤版本空间。
5. **矛盾**：若观测排除所有候选，报告 CONTRADICTION；不得把观测改写成支持最接近的候选。

选择 query 时不得读取目标模型的实际响应；选择器函数签名不接收 target model。目标响应只在 query 锁定后由 `validate_mechanism_query` 读取并比较。这是避免 evaluator 泄漏的最小边界。

## 4. 原型 API

- `forecast_target_response(source, mapping, query)`
- `observe_target_response(target, mapping, query)`
- `forecast_record(...)`
- `select_mechanism_query(source, mappings, queries)` — target simulator is intentionally absent from the signature.
- `validate_mechanism_query(source, target, mapping, query)` — compares the locked forecast with the independent target response.

原型是有限、确定性、表驱动 DSL。它验证的是“给定机制表和显式映射后的可预测性”，不是从原始数据自主发现因果结构。变量/值映射由外部提供，不能把它包装成自动发明。

## 5. 必须包含的证伪案例

| 案例 | 静态结构 | 动态差异 | 期望结果 |
|---|---|---|---|
| 正向迁移 | 角色和关系一致 | 响应值、延迟一致 | 对该 query 通过 |
| 方向反转 | 角色仍可对应 | 响应值相反 | 拒绝候选 |
| 延迟改变 | 角色和响应值一致 | 响应延迟不同 | 拒绝候选 |
| 上下文边界 | 表面结构相同 | 仅特定上下文响应 | 未映射上下文拒绝 |
| 机制缺失 | 图上有关系 | 无对应响应规则 | UNKNOWN，不推断 |
| 多机制候选 | 静态映射均成立 | 不同干预下预测分歧 | 主动选择区分干预 |

## 6. 易象先验如何进入，而不预设正确

易象方法只产生待测的机制变换候选：

- 阴阳对偶：尝试干预方向/响应方向的互补映射；必须与反向随机映射比较。
- 变爻：提出局部状态变化或阈值跨越假设；不得把“变”直接解释为因果。
- 错综：提出角色重排、方向反转或时间顺序变换候选；每种变换单独编码并验证。
- 互体：提出子机制抽取假设；必须验证子机制是否保留响应预测。
- 爻位/时位：提出阶段、顺序、延迟和上下文条件映射。
- 五行生克：提出带符号促进/抑制候选；必须与无符号、随机符号和反向符号对照。

先建立通用机制基线，再单独运行易象先验消融。传统解释不能代替干预证据。

## 7. 评价指标与门槛

- 干预响应准确率：变量、值和延迟分别统计，另报联合准确率。
- 错误接受率：动态机制不一致却被接受的比例。
- 拒答质量：无规则、上下文不匹配、候选预测不完整时是否拒绝。
- OOD 迁移：留出变量名、值名、干预组合和机制模板。
- 查询效率：达到候选唯一识别所需的干预次数与成本。
- 反例撤回：新干预能否使原候选从版本空间移除。
- 校准：若以后引入概率预测，另测 Brier score / log loss；当前确定性版本不报告概率置信度。

通过单元测试只说明代码符合有限契约。要宣称机制迁移，必须通过独立生成器、锁定测试集、多个随机种子、硬负例和预算匹配基线。

## 8. 当前限制与下一阶段

当前不支持：
- 连续状态、连续时间、随机机制、噪声观测；
- 多步状态转移和反馈回路；
- 多干预交互、混杂变量、干预副作用；
- 从观察数据自动识别因果方向；
- 自动学习变量和值的语义映射；
- 真实物理/生物机制等价证明。

下一步 E13-C.2 应引入有限状态转移系统与多步轨迹，比较单步规则与状态机；E13-C.3 再加入噪声、成本和干预风险。只有在这些 Gate 通过后，才连接 E12 主动观测与易象消融。

## 9. 证伪优先结论

若系统只在单步、确定性、人工给定映射下成功，应报告为“有限 DSL 的机制响应一致性验证”，不能称为自主因果发现、通用类象或新型智能。若易象变换候选不优于无先验/随机先验，应该删除或降权，而不是事后解释失败。
