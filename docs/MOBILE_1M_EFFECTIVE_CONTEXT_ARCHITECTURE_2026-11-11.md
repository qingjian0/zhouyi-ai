# Mobile 1M+ Effective Context Architecture

日期：2026-11-11  
优先级：P0  
状态：架构提案 / 需要基准验证；不是已实现功能或已测得性能。  
目标平台：普通 Android 手机，优先 CPU/NPU 可用、低内存、离线优先。

## 0. 产品目标必须精确定义

“手机支持 1M+ 上下文”分成两个不同指标：

1. **1M+ Effective Context（本提案的首要目标）**：系统可持久保存、索引、检索和组合至少 1,000,000 个来源 Token 的历史材料；单次推理只把与当前任务有关的证据装入模型活动上下文。
2. **1M Native Attention Context**：模型在一次 forward 中对 1M token 直接执行其训练/架构定义的注意力。它需要模型架构、位置编码、训练数据和推理内核共同支持，不能由外部记忆系统伪装实现。

手机端首先交付 Effective Context；Native Attention 作为独立研究路线。UI 必须区分“记忆库容量”“本次装入模型的 token 数”和“模型原生上下文窗口”，不得把三者混称为上下文长度。

## 1. 内存下界与设计结论

标准 GQA/MHA KV cache 的近似内存：

`KVBytes = 2 * layers * kv_heads * head_dim * tokens * bytes_per_element`

示例：32 层、8 KV heads、head_dim=128、FP16：
- 每 token 约 128 KiB；
- 128K token 约 16 GiB；
- 1M token 约 128 GiB。

这是单一示例，不代表所有模型；MHA、GQA、MLA、层数、KV heads、维度、量化格式都会改变结果。实际运行还需要权重、激活、临时缓冲、图像/音频缓存和系统内存。

结论：不能把完整历史的 KV cache 常驻普通手机 RAM。必须避免“每轮把整个历史拼接进 prompt”，并将持久记忆与活动注意力分离。

## 2. 总体架构：六层记忆 + 两条推理路径

### 2.1 六层记忆

| 层 | 名称 | 内容 | 介质/策略 |
|---|---|---|---|
| M0 | Active Working Set | 当前问题、最近轮次、当前任务状态 | RAM；严格 token/byte budget |
| M1 | Recent Episodic | 最近对话、操作、观察、局部事件 | SQLite append-only；按时间分块 |
| M2 | Session Summaries | 会话摘要、任务摘要、决策与未决事项 | 磁盘；多级摘要，保留来源指针 |
| M3 | Semantic Memory | 稳定事实、偏好、概念、规则、实体 | SQLite/结构化表；版本化 |
| M4 | Relational Memory | 实体关系、因果链、时间线、冲突、依赖 | 图/关系表；带证据边 |
| M5 | Archive | 完整原始记录、附件、模型输入输出、来源 | 文件/SQLite；压缩、加密、按需读取 |

所有派生记忆必须带 provenance：source_id、span/range、timestamp、task/session、extractor_version、confidence/status。摘要和语义事实不得替代原始记录；需要时必须可回到原文。

### 2.2 两条推理路径

- **快速路径**：M0 + 少量 M3/M4 命中 + 最近历史，低延迟。
- **深度路径**：查询规划 -> 多路检索 -> 原文片段加载 -> 证据去重/冲突处理 -> 结构推演 -> 结果校验。

不能默认每个问题都运行昂贵的深度检索；也不能让快速路径静默丢弃高风险或高不确定性证据。

## 3. 检索不是“只做向量搜索”

采用混合检索：
1. 精确 ID / 文件名 / 关键词 / FTS；
2. 向量语义召回（低维或量化 embedding，索引可磁盘化）；
3. 实体、时间、关系、因果和任务过滤；
4. 重要性、近期性、来源可信度和未解决状态排序；
5. 去重、冲突检测、coverage 检查；
6. 加载原文片段及邻接证据。

排序必须保留来源和时间；“相似”不等于“正确”。向量检索只负责候选召回，不能单独决定事实真伪。

### 3.1 查询规划

查询拆成若干检索子问题，例如：
- 需要哪个人/项目/实体？
- 时间范围是什么？
- 是找事实、决策、代码、证据还是未完成任务？
- 是否需要反例或相反意见？
- 哪些结论必须读取原文才能回答？

查询规划器应输出结构化 RetrievalPlan、预算和停止条件，便于审计与重放。

### 3.2 证据装配

每个候选片段带：
- source ref、原始范围、摘要范围；
- 相关度、来源类型、时间；
- 证据状态（原文/抽取/推断/待验证/冲突）；
- token cost 与加载成本。

按预算选择，不允许只按相似度贪心。优先覆盖不同来源、必要时间点、支持与反证，并避免重复片段占满窗口。回答中的可核查主张要能够指回证据来源。

## 4. 历史压缩：多级、可逆、可审计

压缩流程：
1. 原始事件先追加保存，不覆盖；
2. 对事件做分块，生成 chunk summary；
3. 对 chunk summary 生成 session/task summary；
4. 提取候选事实、实体关系和决策；
5. 对候选事实做冲突检测与来源回链；
6. 只有经验证/确认的项目才能进入稳定语义层；
7. 旧摘要版本保留，重算时可比较差异。

压缩策略：
- 重要决策、约束、用户明确指令、未解决问题、代码提交和失败记录设为高保留优先级；
- 普通寒暄、重复内容可降低检索优先级，但原文仍保存在 archive；
- 不能将模型推断写成用户事实；
- 不得仅凭一次摘要把不确定信息升级为确定事实；
- 对冲突信息保留多个版本、来源与时间，不做无证据覆盖。

## 5. CPG-EI 的核心作用

CPG-EI 不只是向量数据库的替代品，也不是把所有历史都变成一个知识图谱。它负责记忆之上的结构化认知操作：

- 将事件、实体、属性、关系提议为候选原语；
- 发现跨片段的高阶关系和非连续组合；
- 形成可追踪的结构版本；
- 在冲突、缺证、过期时主动降低置信或 abstain；
- 根据问题选择检索、比较、反事实和验证路径；
- 将新证据作为事件追加，更新结构而不是覆盖历史。

必须区分：Memory Store 保存“发生过什么/来源是什么”；CPG-EI 推理“这些材料可能意味着什么”。不能让推理结果伪装成原始记忆。

## 6. 移动端内存预算与运行时策略

### 6.1 目标不是固定所有设备用同一模型

设备能力探测至少读取：
- Android API / ABI / 可用 RAM；
- 当前进程可用内存与系统内存压力；
- GPU/NPU/NNAPI/Vulkan/CPU delegate 能力；
- 模型权重大小、KV cache 格式和最大活动窗口；
- 磁盘空间、温度与电量状态。

按设备动态配置，而不是仅按总 RAM 分类。运行中出现系统内存压力时，必须降低活动窗口、回收临时 buffer、暂停后台 embedding、必要时卸载模型或切换云端/轻模型（若用户允许）。

### 6.2 建议初始预算（待真机验证）

| 设备档位 | 记忆索引策略 | 活动上下文建议起点 | 运行策略 |
|---|---|---:|---|
| 4 GB RAM | FTS + 磁盘向量索引，低并发 | 4K–8K | 小模型、CPU 优先、强制后台回收 |
| 6 GB RAM | 混合检索、按需 embedding | 8K–16K | 低并发、KV 量化 |
| 8 GB RAM | 混合检索、缓存热门向量 | 8K–32K | 可选 NPU/GPU，动态窗口 |
| 12 GB+ | 更大活动窗口和并发预算 | 16K–64K+ | 仍须按模型实测限额 |

这些是工程起测区间，不是对所有模型的保证。4GB 手机也必须把系统后台和 Android 本身的内存计入预算，不能将全部 RAM 分配给模型。

### 6.3 内存控制

- 使用分配器池与可复用 buffer，减少碎片和峰值；
- embedding 分批、后台低优先级执行；
- 向量索引支持磁盘/内存映射或分片加载；
- SQLite WAL、分页读取、索引分区；
- archive 压缩并按需解压；
- 热缓存设硬上限与 LRU/重要性联合淘汰；
- KV cache 量化需评估长对话质量、数值稳定性和不同层敏感度；
- 多模态图像/音频采用独立缓存与缩略/patch 预算；
- 记录 P50/P95 峰值内存、GC、OOM、首 token 延迟、每 token 延迟和温度。

## 7. Native 1M Attention 研究路线

如果未来确实要让模型直接对 1M token 做注意力，必须使用支持长上下文的架构和训练/推理路径，例如：
- Sliding-window / block-sparse attention；
- Retrieval-augmented attention；
- Chunked prefill 与分块 KV；
- Recurrent/state-space 或线性注意力模型；
- 分层/压缩 KV、重要 token 保留；
- 模型原生的长上下文位置编码与训练。

不能仅在配置文件中把 max_seq_len 改成 1M。模型必须经过相应长度训练/适配，并在目标设备上验证位置外推、召回率、needle-in-haystack、跨段推理和长程干扰。

外部检索式 1M Effective Context 和原生 1M Attention 可以并行发展，但产品能力标签必须明确区分。

## 8. 评估：不能只用 Needle-in-a-Haystack

必须建立手机端长程记忆 benchmark：
1. Exact Recall：精确找回早期原文与数字；
2. Multi-hop Recall：跨多个会话组合事实；
3. Temporal Update：识别旧值、新值和生效时间；
4. Contradiction：同时保留冲突来源并正确 abstain；
5. Provenance：回答能定位原始来源与 span；
6. Selective Retrieval：大量干扰信息下召回关键片段；
7. Longitudinal Task：跨天/跨会话持续任务；
8. Compression Audit：压缩前后事实、关系、否定、条件和时间信息损失；
9. Mobile Stress：低内存、后台切换、断电恢复、磁盘不足；
10. Latency/Power：冷启动、首 token、P50/P95、能耗、温升。

每项报告 Recall@K、Precision@K、答案正确率、证据覆盖率、冲突识别率、错误记忆率、token budget、峰值 RSS/PSS、磁盘增长和能耗。必须有无记忆、摘要记忆、向量检索、混合检索和 CPG-EI 结构记忆等基线。

## 9. P0 实施顺序

### P0-A：测量与防止上下文膨胀
- 盘点 prompt 构造路径，禁止每轮无界拼接完整历史；
- 统计实际 input tokens、KV bytes、prefill time、RSS/PSS；
- 给活动上下文、检索结果、缓存分别设硬预算；
- 超预算时走检索与压缩，不静默截断系统指令或关键证据。

### P0-B：分层记忆 MVP
- 原始事件 append-only 存储；
- SQLite FTS + 元数据过滤；
- 分块摘要及来源回链；
- 最近历史 + 语义/关键词检索；
- 预算感知的 context assembler；
- 对冲突与不确定内容显式标记。

### P0-C：混合检索与结构记忆
- 向量 embedding 按需生成；
- 关系/实体/时间索引；
- reranker 或轻量相关性排序；
- CPG-EI Proposal/StructureVersion adapter；
- 记忆合并、失效、纠错与撤回流程。

### P0-D：移动推理优化
- KV cache 量化对比；
- sliding-window / chunked prefill；
- 动态活动窗口；
- 内存压力回调；
- 设备档位测试与自动降级。

### P1：长上下文原生模型
- 评估适合移动端的 recurrent / linear / sparse attention 模型；
- 原生长上下文微调与蒸馏；
- 与外部记忆架构组合评测。

## 10. 验收条件

首个可交付版本必须满足：
- 记忆库至少支持 1M source tokens 的持久化和索引（以 tokenization manifest 记录精确口径）；
- 单轮 prompt 不因历史总长度线性增长；
- 活动上下文有硬 token 与 byte 双预算；
- 检索到的每个事实都可追溯到原始记录；
- 对未召回证据明确说明，不假装完整记住；
- 低内存压力下不会持续扩大缓存；
- 进程被杀后记忆可恢复；
- 有 4GB/6GB/8GB 设备实测报告；
- 对比基线报告准确率、召回率、峰值内存和延迟。

建议将首个目标定义为：**4GB RAM 设备上可使用 1M+ Effective Context，活动窗口从 4K–8K 起步，硬预算、低峰值、可追溯；随后按真机结果扩大。** 不承诺 4GB 设备运行原生 1M 全注意力。

## 11. 安全与隐私

- 本地优先，默认不上传用户记忆；
- 数据库与 archive 支持加密和密钥隔离；
- 删除/遗忘请求必须能沿 source lineage 删除派生摘要、embedding、关系和缓存；
- 记忆内容是数据，不是可执行指令；检索到的 prompt injection 不得改变系统策略；
- 插件/工具返回内容需标注来源和信任等级；
- 备份、导出、迁移与删除均需用户可控。

## 12. 设计结论

手机端百万级上下文不应依赖“把一百万 token 全塞进模型”。应将长期历史视为一个可检索、可验证、可演化的外部认知空间；模型活动窗口只承载当前推理所需的最小充分证据。

CPG-EI 的价值在于让这个外部认知空间不止是文本仓库，而是具备结构发现、关系推演、证据修订和长期任务连续性的认知系统。

首要交付：1M+ Effective Context；后续研究：Native 1M Attention。两者不可混淆。
