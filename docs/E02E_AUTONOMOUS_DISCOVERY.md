# E02-E：反例驱动的未知关系发现（首个可运行原型）

## 研究问题

不给学习器正确成员集合或目标关系阶数，能否从观测样本中提出候选关系，用独立证据拒绝错误候选，并且只把通过门控的关系写入动态超图？

## 原型机制

1. **候选生成**：从输入特征的 2–4 阶交互组合中生成候选；目标成员集合不提供给候选生成器。
2. **训练排序**：按交互项与标签的绝对相关性排序，保留 top-K。
3. **反例保留**：训练样本中与候选预测不一致的样本作为 counterexample evidence，不能被删除或改标。
4. **独立门控**：用独立 gate split 评估第一名候选，并与训练集选出的 pairwise 候选比较。
5. **结构提交**：只有 gate gain 达到阈值才调用 E02-C 生命周期管理器 CREATE；失败则拒绝创建。
6. **锁定测试**：结构决策完成后才评估 test split；测试集不参与候选生成或结构选择。

## 重要边界

这是一个透明、确定性、CPU 友好的符号交互搜索基线，不是神经学习器，也不是开放域自主概念发明。它的候选语言（有限阶乘积交互）是明确的归纳偏置。实验成功只能证明系统能在未知成员组合的合成任务中发现一个未指定的高阶交互；不能证明因果发现、自然语言理解或通用智能。

## 必须报告

- 候选池大小、top-K 候选及训练相关度；
- 发现成员集合与隐藏目标的审计恢复率；
- gate/test accuracy、pairwise baseline、增益；
- CREATE 率、support/counterexample 数量；
- 多随机种子均值、标准差和置信区间；
- 噪声、候选阶数、样本量扫描；
- 与静态超图、随机超图、强成对模型的预算匹配比较。

## 下一步证伪实验

- **成员数 OOD**：训练仅覆盖 3 阶，测试 4 阶目标。
- **规则族 OOD**：从乘积交互切换到非乘法的多值角色约束。
- **干扰特征**：加入与标签相关但非因果的伪相关维度，检查误发现。
- **数据量曲线**：样本数 32/64/128/256/512/1024。
- **噪声曲线**：0/2/5/10/20% 标签噪声。
- **反例压力**：系统性加入 hard negatives，观察 CREATE 是否被阻止。
- **公平基线**：强 pairwise、静态超图、随机候选、oracle 上界。
