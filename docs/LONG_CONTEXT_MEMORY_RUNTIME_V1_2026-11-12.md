# Zhouyi-AI 长上下文低内存运行时规格 v1

日期：2026-11-12  
状态：研究/工程规格；尚非已实现能力或性能结果  
承接：`integration/per-file-runtime-map-2026-11-12` 的逐文件运行时审计  
目标：建立 8K / 1M Token 的有界常驻认知状态，不依赖完整历史 Transformer KV Cache。

## 0. 决策摘要

本规格将此前讨论的目标收敛为可测量的工程合同：

- 8K Token：上下文子系统增量常驻内存目标 **≤16 MiB**。
- 1M Token：上下文子系统增量常驻内存首版硬预算 **≤64 MiB**；优化挑战目标 **≤32 MiB**。
- 8 MiB：保留为 8K 场景的远期挑战目标，不作为第一版验收门槛。
- 原始文本/多模态证据保存在外部持久存储；内存中保存有界活动工作集、结构化关系、索引缓存和临时检索工作区。
- 不把“外部可检索的 1M Token”表述成“1M Token 全部常驻内存”，也不把语义摘要表述成任意原文的无损压缩。
- K0/K1/K2 分层验收：结构内核、持续认知、原生表达分别证明 KV-cache 独立性。

本规格不承诺模型权重、操作系统、解释器或整个 Agent 进程总内存只有 64 MiB。预算对象是**上下文/记忆运行时相对于空载基线的增量内存**，模型权重和通用运行时必须单独报告。

## 1. 术语和边界

### 1.1 三种容量不可混用

| 名称 | 定义 | 是否计入本规格预算 |
|---|---|---|
| 输入容量 | 一次任务可接收并处理的 Token 总量，例如 1M | 否，作为功能测试规模 |
| 活动认知工作集 | 当前推理轮次直接驻留 RAM 的结构、关系、状态和缓存 | 是 |
| 持久证据容量 | 磁盘/数据库中的原文、分块、事件、来源跨度和索引 | 否；必须报告磁盘占用与 I/O |

系统必须支持从 1M 输入中按需检索证据，但不要求将 1M Token 的原文和所有派生对象同时放入 RAM。

### 1.2 允许与禁止

允许：
- 流式分块读取、增量解析、按需加载和可验证的缓存淘汰。
- 将语义单元、事件、关系、约束、时间线和不确定性保存为结构化状态。
- 将原始证据放在外部持久层，并保留稳定的 chunk/span 引用。
- 使用可插拔解析器/语言模型作为输入或表达适配器，但必须单独标注其内存与 KV Cache。

禁止：
- 以“1M 上下文”名义将所有历史 K/V 持续保留在内存。
- 将摘要或类象结构当成原文的无损替代。
- 只报告 Python 对象大小而不报告进程峰值 RSS/容器内存。
- 将磁盘容量、虚拟地址空间或 mmap 文件大小当成 RAM 占用。
- 将结构内核 K0 的无 KV 依赖，外推为持续认知 K1 或端到端生成 K2 已通过。
- 用固定卦象标签硬编码自然语言含义；易象/XSL 算子必须有类型、适用域、证据、反例和消融。

## 2. 目标内存曲线

首版验收采用分段预算，而不是假设内存随 Token 数线性增长：

| 输入规模 | 上下文运行时增量常驻内存上限 | 状态 |
|---:|---:|---|
| 8K | 16 MiB | 首版硬验收目标 |
| 32K | 24 MiB | 目标 |
| 128K | 32 MiB | 目标 |
| 256K | 40 MiB | 目标 |
| 512K | 48 MiB | 目标 |
| 1M | 64 MiB | 首版硬验收目标 |
| 1M | 32 MiB | 后续优化挑战 |
| 8K | 8 MiB | 远期极限挑战，不阻塞首版 |

这些数值是**待验证预算**，不是已测结果。若某项任务需要更多状态，必须报告超预算、退化策略和准确率变化，不能静默突破预算。

### 2.1 内存统计口径

每个实验至少报告：
1. 空载进程基线 RSS。
2. 输入接收后的峰值 RSS。
3. 结构化状态构建后的峰值 RSS。
4. 查询/回溯期间峰值 RSS。
5. 稳态 RSS（完成 GC/缓存策略后）。
6. 上下文子系统增量 RSS = 同配置峰值 RSS - 空载基线峰值 RSS。
7. 容器/cgroup 峰值内存、磁盘占用、读取字节数、缓存命中率。
8. 进程重启恢复时的峰值 RSS。

所有数字使用 MiB（2^20 bytes），固定运行时、分配器、线程数和硬件环境。禁止混用 MB 与 MiB。

## 3. 运行时结构：证据层与认知层分离

### 3.1 持久证据层（不计入 RAM 预算，但需计量）

保存：
- 原始输入及其内容摘要；
- 分块清单、稳定 chunk ID、字符/Token/span 范围；
- 原始来源、时间、域、权限和完整性元数据；
- 结构化单元到原文 span 的反向映射；
- 事件日志、版本、修订和冲突证据。

原文是事实回溯的最终依据。摘要、关系和类象都是可重建/可修订的派生视图，不得覆盖原始证据。

### 3.2 活动认知层（计入 RAM 预算）

保存：
- 当前任务目标与约束；
- 当前轮次的高价值语义单元；
- 活动实体、事件和关系超边；
- 必要的时间/因果/状态依赖；
- 检索候选及有限结果缓存；
- 来源引用、置信状态、冲突标记和版本指针。

活动层必须有明确容量、淘汰策略、恢复策略和版本边界。

### 3.3 结构对象最小契约

每个语义单元至少包含：
- `unit_id`、`unit_type`、`payload`；
- `source_ref`（chunk/span）；
- `domain_id`、`timestamp`（若适用）；
- `confidence/status`；
- `operator_version`、`state_version`。

每条关系/超边至少包含：
- `edge_id`、有序/无序角色定义；
- 参与节点引用与类型约束；
- 关系类型及适用域；
- 来源证据引用；
- 生命周期状态、有效区间；
- 置信/争议状态与生成版本。

不得将来源跨度从结构对象中剥离；无证据来源的推断必须标记为假设，不能伪装为事实。

## 4. 核心数据流

```text
1M-token stream
  -> bounded chunk reader
  -> Observation + source spans
  -> grounding / semantic units (typed, uncertainty-aware)
  -> Yixiang/XSL operator proposals (versioned, falsifiable)
  -> TRLW active typed workspace
  -> SROK sparse role composition
  -> CSG-GCR typed constraints and candidate coordination
  -> RSDN state transition / update
  -> E09 evidence governance
  -> E12-A6 lifecycle authority
  -> ZPCM durable event log + rebuildable projections
  -> query-time retrieval of original evidence
  -> structured answer plan
  -> optional native expression adapter
```

此图是目标数据流，不代表全部调用链已实现。逐文件审计指出 Observation → grounding → XSL → TRLW → SROK 的真实输入路径、RSDN 接线和 native expression 仍有缺口。现有 CSG-GCR → E09 → E12-A6 → ZPCM 生命周期 E2E 不可替代完整输入到输出测试。

## 5. 内存池建议

1M 首版 64 MiB 预算建议如下（上限分配，不是必须全部使用）：

| 池 | 预算 | 内容 |
|---|---:|---|
| 活动任务/状态 | 8 MiB | 当前目标、约束、短期状态 |
| 语义单元工作集 | 12 MiB | 活跃实体、事件、概念和属性 |
| 关系/超边工作集 | 16 MiB | 稀疏关系、角色绑定、依赖 |
| 检索与索引缓存 | 8 MiB | 有界候选、轻量索引页、命中缓存 |
| 原文回溯缓冲 | 8 MiB | 查询命中 chunk 的短时解码缓冲 |
| 临时计算/算子工作区 | 8 MiB | SROK/CSG-GCR/状态更新临时数据 |
| 安全余量 | 4 MiB | 分配器碎片、对象头、峰值波动 |
| **合计** | **64 MiB** | **首版预算** |

8K 场景不能照搬整套池配额，应按实际活动单元数缩小分配，并在 16 MiB 总预算内运行。

索引主体应外置或采用可分页结构；不可将百万级全量倒排索引或全图对象无界载入 RAM。每个池必须能输出当前/峰值占用和淘汰计数。

## 6. 关键算法约束

### 6.1 流式摄取
- 分块处理，单块最大内存固定；块大小作为实验参数。
- 每块处理完成后提交持久证据和派生结构，再释放解析缓冲。
- 中断后从稳定 chunk ID 恢复，不重复提交或产生双重事件。
- 记录解析失败、截断、未知类型和低置信度内容。

### 6.2 类象压缩
- 仅在类型、角色、关系、适用域和证据约束兼容时合并。
- 保留被合并对象的 provenance 列表或可追溯映射。
- 对冲突证据并存，不以多数投票直接覆盖少数反例。
- 压缩必须可逆向定位原文，不要求语义表示可还原全部原文。
- 通过错配先验、随机先验、无先验消融，证明易象算子的独立贡献。

### 6.3 关系计算
- 优先按类型/角色/索引筛选候选，再做有界组合。
- 记录候选池截断和搜索预算；截断导致的召回损失必须进入评估。
- 对关键剪枝与未剪枝 oracle 做差分验证。
- 不因“高阶”本身而默认有效；必须通过保留 pairwise 投影的高阶必要性实验。

### 6.4 缓存淘汰与恢复
- 淘汰的是可重建的派生缓存，不是原始证据。
- 采用任务相关性、近期访问、依赖重要性、证据等级和重建成本组合评分。
- 任何淘汰均保留稳定引用和版本，不得让悬空关系静默指向新对象。
- 进程重启后由 ZPCM 事件重建活动投影，并验证与提交前状态摘要一致。

## 7. K0 / K1 / K2 验收

| 级别 | 必须证明 | 关键测试 | 通过后允许的表述 |
|---|---|---|---|
| K0 结构内核 | SROK/typed unifier/CSG-GCR/E09/E12-A6/ZPCM 结构路径不需要历史 K/V | 依赖扫描、运行轨迹、内存剖析 | “结构内核无需完整 KV Cache” |
| K1 持续认知 | 多轮、跨重启、固定 RAM 下持续更新、检索、冲突处理和恢复 | 8K/128K/1M 长流、重启、淘汰、细节/关系回忆 | “持续认知状态不依赖历史 KV Cache” |
| K2 原生表达 | 结构化推理结果能经非 Transformer 表达路径输出 | native expression E2E；断开 Transformer/LLM 后测试 | “端到端表达可不依赖 Transformer KV Cache” |

K0 通过不代表 K1/K2 通过。若可选 LLM 负责 grounding 或表达，必须分别报告该适配器的 KV 和内存，不得隐藏在系统总指标之外。

## 8. 基准测试协议

### 8.1 数据集分层

- D1 8K：短上下文基础功能和精确 span 回溯。
- D2 128K：跨块实体/关系/约束整合。
- D3 1M：跨文档、跨时间、长距离依赖和冲突证据。
- D4 对抗集：重复名称、近似实体、矛盾陈述、诱导性错误摘要、跨域错配、稀有关键事实。
- D5 高熵集：大量互不相关、难以压缩的独立事实，用于防止只在高度重复文本上取得漂亮压缩率。

数据集必须锁定版本、随机种子、切分、生成器版本和答案证据。

### 8.2 任务类型

1. 精确事实回忆：答案必须返回原文 span。
2. 实体消歧：区分同名/近名实体。
3. 关系回忆：恢复多跳及非连续角色关系。
4. 时间线重建：识别先后、持续和状态变化。
5. 冲突识别：并存冲突并定位双方证据。
6. 约束追踪：跨多块保留禁止项、条件和范围。
7. 证据修订：新证据到达后局部更新，不污染无关状态。
8. 重启恢复：跨进程恢复后答案与证据链一致。

### 8.3 必须报告的指标

- exact-span recall / precision；
- entity linking accuracy；
- relation recall / precision；
- contradiction detection F1；
- temporal ordering accuracy；
- evidence attribution accuracy；
- unsupported-claim rate；
- state drift / stale-edge rate；
- 每轮增量计算量与延迟 P50/P95；
- 峰值/稳态 RSS、容器峰值、磁盘读写；
- 缓存命中率、重建成本和恢复时间。

只报告压缩比或上下文长度不构成通过。

### 8.4 对照组

至少比较：
- 全量原文按需扫描（无语义缓存）；
- 分块检索 + 普通摘要；
- 结构化实体/关系记忆；
- Zhouyi 类象 + 类型化超图；
- 可用时，标准 Transformer KV Cache 基线。

所有组必须匹配输入、输出、数据、计算预算和硬件。若某组使用外部 LLM，需单独报告模型和 KV 内存。

## 9. 实施阶段与退出条件

### M0：测量基础
- 建立空载基线和上下文子系统内存计量器。
- 固定 MiB 口径、环境、种子和报告格式。
- 为所有缓存池提供 current/peak/eviction counters。

退出条件：同一配置重复运行的内存结果可复现。

### M1：流式证据摄取
- 建立 bounded chunk reader、稳定 chunk/span ID、持久化与 crash resume。
- 不构建全量常驻语义图。

退出条件：1M 输入能分块完成，峰值缓冲有硬上限，重启不丢失/重复证据。

### M2：结构化活动工作集
- 接通 grounding、TRLW、Yixiang/XSL、SROK、CSG-GCR 的最短真实路径。
- 每个结构对象保留来源和版本。
- 完成池化预算、淘汰与按需重建。

退出条件：8K ≤16 MiB；1M ≤64 MiB；精确证据回溯和核心关系任务达到预注册门槛。

### M3：持续认知闭环
- 接通 RSDN 状态更新与现有 E09/E12-A6/ZPCM 权威链。
- 完成跨进程重启、冲突修订、依赖失效和长流测试。

退出条件：K1 测试通过；内存预算不因会话轮数持续线性增长。

### M4：原生表达
- 建立结构化 answer plan 与不依赖 Transformer 的表达实现。
- 将语言可读性与事实/关系正确性分开评估。

退出条件：K2 独立测试通过；否则明确保留可选语言适配器，不宣称端到端 KV-Free。

## 10. 当前优先实施项

基于逐文件审计，先后顺序必须是：

1. M0 内存测量基础——否则 16/64 MiB 只是口号。
2. M1 流式证据摄取——先解决 1M 输入的有界读取和可恢复性。
3. M2 最短真实认知路径——补齐 Observation → grounding → Yixiang/XSL → TRLW → SROK → CSG-GCR。
4. 复用 E09/E12-A6/ZPCM，不另建账本/状态机。
5. 最后做 K1 长期记忆与 K2 原生表达。

当前不启动全项目联合训练。只有当 M0–M3 有稳定数据、关键消融和锁定测试集后，才评估是否启动相应模块训练。

## 11. 明确的非目标

本规格不声称：
- 已实现 1M Token / 64 MiB；
- 已证明 1M 任意文本都能无损语义压缩；
- 已证明类象算子优于 Transformer；
- 已完成完整自然语言理解或原生语言生成；
- 已消除所有 KV Cache；
- 整个模型/Agent 进程只需 64 MiB；
- 仅凭 CI 通过即可证明科学有效性。

**最终原则：输入容量可以增长，活动认知工作集必须有界；原文证据必须可回溯，摘要推断必须可证伪，内存与能力必须在同一锁定基准上共同验收。**
