# E10-A：对象束与关系骨架归纳——预注册协议 v0.1

状态：预注册设计；尚未实现、尚未执行、无实验结果。
父研究：`docs/E10_XIANG_OPERATOR_LEARNING.md`
工作分支：`research/e10a-structure-induction-protocol-2026-11-10`
目的：先验证系统能否从带噪观测中恢复可复用的对象角色与关系骨架，再讨论类象迁移、算子发明和易象先验。

## 0. 本实验究竟要证明什么

主要命题不是“模型能预测合成标签”，而是：

> 当训练集与测试集在对象身份、表面属性组合和关系模板上隔离时，学习器能否恢复生成数据背后的关系结构，并把结构用于未见对象组合？

必须区分四个能力层级：

- L0：样本记忆 / 查表。
- L1：已知特征上的规则归纳。
- L2：已知关系原语的未见组合泛化。
- L3：提出训练 DSL 之外的新关系原语，并在独立任务上复用。

E10-A 主要测试 L1 与 L2，不允许将结果表述为 L3。L3 留给 E10-C。

## 1. 数据生成器：潜在关系图，而不是标签捷径

每个 episode 先生成一个潜在关系结构：
`G=(V,R,C)`
- V：对象集合，每个对象有类型、属性、行为状态。
- R：带方向、角色槽位、元数和关系类型的关系实例。
- C：关系成立的上下文条件与时位变量。

再由观测器产生记录：
`O = Observe(G, noise, missingness, surface_relabel, permutation)`

目标标签只由潜在结构和预注册任务查询生成，不直接暴露潜在关系 ID。

### 1.1 对象属性

初始生成器使用 4 个类型族，每类 3 个离散属性；属性值从每 episode 独立随机映射到不透明符号，避免固定 token 与语义绑定。属性表面名称、对象 ID、记录顺序全部随机置换。

### 1.2 关系结构

第一阶段只使用明确的关系骨架：
- 有向二元关系；
- 有角色槽位的三元关系；
- 条件化关系；
- 两条关系共享中间对象的组合关系。

不得把关系类型名称、目标程序 AST 或正确答案放入输入记录。

每个任务 episode 由 2–4 条潜在关系组成。关系实例可跨越任意记录位置，允许跳过中间对象，确保不能只靠邻接窗口完成。

### 1.3 观测噪声

分别控制：
- 属性缺失率：0 / 0.1 / 0.25；
- 关系实例漏观测率：0 / 0.1；
- 随机标签翻转率：0 / 0.05 / 0.15；
- 干扰对象比例：0 / 0.25 / 0.5。

噪声源必须分开记录，不得将概念变化、数据缺失与标签翻转合并成单一噪声参数。

## 2. 数据划分：四重隔离

不能仅随机拆分样本。每次正式评测需同时实施：

1. **对象身份隔离**：测试对象 ID 在训练中完全未出现。
2. **表面属性组合隔离**：测试中的部分属性共现组合未在训练出现。
3. **关系模板隔离**：测试模板不能只是训练模板换对象名。
4. **关系组合隔离**：测试中的关系组合在训练中未整体出现，但其组成原语可在训练中出现。

另设一个更难的 OOD-primitive split：测试中出现训练 DSL 未声明的新关系模式。该 split 只用于测量系统拒答、异常检测或提出新原语的能力，不把猜中标签等同于发现原语。

数据生成器应导出 split manifest 和潜在结构的审计真值；审计真值只交给评测器，不得进入学习器输入。

## 3. 任务形式

每个 episode 给学习器一组观测记录和查询，要求输出：
- 对象束：对象属性/行为特征的可复用分组；
- 角色分配：每个关系参与者的角色槽位；
- 关系骨架：关系类型、方向、元数及条件；
- 预测：对留出查询的关系是否成立；
- 证据账本：支持、反例、未知、冲突分别列示；
- 不确定性：允许 abstain，不得强制猜测。

评测器使用潜在结构计算结构恢复指标，不能只看预测准确率。

## 4. 主要指标（预注册）

### 4.1 结构恢复
- Object bundle：pairwise precision / recall / F1，使用置换不变匹配。
- Role assignment：角色槽位 macro-F1。
- Relation skeleton：关系实例 precision / recall / F1。
- Relation type：macro-F1。
- Condition recovery：条件变量与阈值/取值恢复准确率。
- Graph edit distance：预测结构与潜在结构的归一化编辑距离。

### 4.2 泛化与校准
- Held-out composition exact match。
- OOD relation-template accuracy。
- Coverage、selective accuracy、overall accuracy、abstention rate。
- ECE 或 Brier score；必须同时报告校准前后结果。
- 错误类比接受率与有效类比迁移率（后续 E10-B）。

### 4.3 成本
- 假设/算子候选生成数；
- 候选—样本匹配次数；
- 反例检查次数；
- wall-clock time；
- peak memory；
- 结构编辑数与最终结构复杂度。

禁止把候选数当作总计算量。所有方法报告相同口径的成本。

## 5. 必须比较的基线

所有方法使用同一输入、数据划分、训练样本数和评估查询：
1. Majority / random。
2. Exact lookup。
3. Nearest-neighbour。
4. 手工特征 + 线性分类器。
5. 固定关系模板匹配器。
6. E09 有限 DSL 反例驱动学习器。
7. 受限程序合成 / CEGIS。
8. 普通图结构学习器。
9. 动态超图结构学习器。
10. XPC 无易象先验版本。

后续再增加参数量和 FLOPs 匹配的梯度神经基线。若当前原型无法严格匹配参数量，必须明确标注比较限制，不得声称全面优于神经网络。

## 6. 易象先验：单独实验，不进入主任务答案

E10-A 主实验先使用 X0（无易象先验），避免同时引入多项变化。

后续独立消融：
- X0：无先验；
- X1：随机置换的同规模先验；
- X2：阴阳二元互补；
- X3：四象/八卦/六爻分层状态编码；
- X4：关系保持类象映射；
- X5：互体、错综、角色置换候选；
- X6：可学习且允许拒绝的完整先验。

先验不能进入标签生成器、split manifest、对象 ID 或答案字段。必须增加先验失配任务：当先验与潜在结构冲突时，系统应降低其权重或拒绝使用。

## 7. 样本规模与随机种子

开发阶段：3 seeds，仅用于检查数据生成器与调试，不用于结论。
预注册验证阶段：20 seeds。
正式确认阶段：100 seeds；每个 seed 生成独立潜在结构与表面重映射。

报告逐 seed 数据、均值、中位数、标准差和 bootstrap 95% CI。所有超参数仅用训练/验证 split 选择。测试集只运行一次正式评估；若修复 bug，必须升版本并重新运行完整确认集。

## 8. 关键泄漏攻击

至少执行以下攻击并确认基线/学习器表现：
- 将对象 ID 与目标关系随机关联；
- 打乱记录顺序；
- 置换所有属性符号；
- 将关系模板 ID 从输入中删除；
- 固定对象数量但改变记录顺序；
- 让数据生成器在 train/test 使用不同属性映射；
- 在 metadata 中放置与标签相关但无因果意义的字段；
- 复制同源记录并改变 source_id，检查系统是否虚增独立证据。

如果某个模型只在未攻击数据上高分，而在表面重映射或元数据攻击下崩溃，优先判定为泄漏或捷径学习，不接受其结构发现主张。

## 9. 成功与失败标准

E10-A 的有限成功条件：
- 关系骨架恢复显著高于 lookup、nearest-neighbour 和固定模板基线；
- 在对象身份隔离与关系组合隔离下仍有稳定泛化；
- 成本在预设预算内；
- 证据账本能正确区分未知与反例；
- 多种表面重映射与泄漏攻击下结论保持稳定。

失败条件：
- 仅 IID 随机拆分有效；
- 测试性能依赖对象 ID、字段顺序、模板名称或 metadata；
- 结构恢复不优于简单基线；
- 只提升标签准确率，却不能恢复角色/关系；
- 计算成本远高于基线而无可解释收益；
- 先验失配时仍强行类比。

无论成功或失败，都必须报告失败模式，不得只挑选有利 seeds。

## 10. 实现拆分建议

建议代码模块：
- `prototype/e10a_generator.py`：潜在结构与观测生成；
- `prototype/e10a_splits.py`：四重隔离与 manifest；
- `prototype/e10a_schema.py`：ObjectBundle / Relation / Evidence 数据模型；
- `prototype/e10a_metrics.py`：结构恢复、泛化、校准和成本指标；
- `prototype/e10a_baselines.py`：简单基线；
- `prototype/e10a_benchmark.py`：统一 runner；
- `tests/test_e10a_generator.py`：生成器性质；
- `tests/test_e10a_no_leakage.py`：泄漏攻击；
- `tests/test_e10a_metrics.py`：指标边界与退化情况。

生成器和评测器必须可独立运行。学习器不能 import 潜在真值对象；通过不同模块/序列化边界隔离训练输入和评测答案。

## 11. 当前结论

E10-A 预注册协议已经把“取象”从抽象口号收敛为对象束、角色槽位和关系骨架恢复问题。它仍是有限合成环境中的结构归纳实验，不代表真实世界的开放概念发现。

在该协议完成并通过泄漏攻击前，不进入 E10-B 类象迁移的性能主张；在 E10-A 有可复现结果前，不把 XPC 称为已验证架构。
