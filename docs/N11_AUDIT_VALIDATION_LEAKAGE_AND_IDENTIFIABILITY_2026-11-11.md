## 本轮发现：验证集曾参与候选程序排序

初始实现先要求候选程序完全解释训练集，再计算验证集支持数；随后却把候选按验证集支持数排序。这会使验证集不再只是泛化评估集，而成为候选模型选择集。若后续再把同一验证分数作为最终泛化结果，就会产生验证集选择偏差。

### 已执行修复

- 候选排序只依赖程序长度与程序字符串的确定性顺序。
- validation_support 仍保留为报告字段，但不再影响候选排序、候选生成或搜索剪枝。
- 新增回归测试：同一训练集、不同验证标签应得到完全相同的候选程序顺序，但验证支持指标可以不同。

## 当前 N0.11 原型能力边界

这是一个有限 DSL 的确定性枚举程序合成基线，当前原语包括 neg、abs、swap、add、sub、max、min。它可以在给定训练转移中寻找完全匹配的短程序，并在独立验证转移上报告支持情况。

它目前没有：
- 从原始自然语言/多模态观测中 grounding 状态变量；
- 从数据中自动发明 DSL 原语或类型系统；
- 概率化搜索、神经程序提议或可学习算子路由；
- 因果可识别性保证；
- 对语法外算子的发现能力。

程序“类型”目前主要由向量维度和索引范围约束；这不是对象类型、关系类型、角色类型组成的完整语义类型系统。文档和后续实现不得夸大。

## 仍需研究的关键问题

1. **等价程序类**：多个不同程序可能在有限观测上完全等价。应报告等价候选数量，并在额外干预输入上区分，而不是任意把最短程序称为真实机制。
2. **反事实识别**：训练数据应包含能区分竞争程序的输入；主动选择最有区分力的干预状态，比单纯增加随机样本更有效。
3. **组合泛化**：按原语组合、程序深度、输入区域和机制家族切分，而非只用同分布随机向量。
4. **语法偏置审计**：比较原语集合扩张、删减、错误原语、随机原语和通用算子库，测量发现结果对人工 DSL 的依赖。
5. **数值稳定性**：对连续 add/sub 的极端值和长程序执行范围检查，明确拒绝非有限中间状态。
6. **神经—符号协同**：下一步让 N0.10 的结构评分器提出/排序候选程序，但确定性解释器负责执行，独立 evaluator 负责验证；比较纯枚举、神经提议+符号验证、随机提议+符号验证。
7. **易象 grounding**：取象、互、错、综、应、时、位、变必须落到带输入类型、输出类型、前置条件、可观察状态差分和反例的操作定义；名称不能代替语义。

## 与 MTS-0 的整合建议

MTS-0 目前是同一 Python 进程内的 prediction-commit / evidence-reveal 协议原型。它能检查调用顺序和可见性策略，但不是安全边界。N0.11 的程序发现、候选排序、阈值选择必须由 learner/selector 角色完成；最终 locked-test 结果只能由独立 evaluator 进程读取。

在 evaluator 独立化之前，结果只可标记为“流程语义测试”，不能标记为可信锁定测试。
