# M19 古籍类象案例人工审定与分歧裁决工作流 v0.1

## 1. 目标

M18 已把 M17 的古籍案例安全转换为 M8 的 pending-review 数据，但它还没有解决“谁核过底本、两位标注者是否独立、标注分歧如何处理、什么条件下可以进入 gold 集”这一问题。

M19 定义可审计的人工审定包。它不自动判定古籍真伪或解释正确性；它只确保进入 M8 的 adjudicated 数据具有可追溯的底本核验记录、至少两份独立标注，以及一份明确的最终裁决。

## 2. 四层记录，不得合并

1. **文本见证核验**：作品、版本、见证、卷篇/页码/行号、逐字转录、影印或馆藏证据、核验者。
2. **独立标注**：每位标注者独立填写主张、文本层、共同依据、非共同依据、范围条件、必要不变量、反例、因果状态和理由。
3. **分歧登记**：对决策、主张文本、文本层、共享依据、差异依据、范围、不变量、反例和因果状态逐字段比较。不得以多数票静默抹掉分歧。
4. **最终裁决**：由不同于两位标注者的裁决者，明确给出 accept/reject/conditional/abstain、理由和裁决证据。

## 3. 状态机

| 状态 | 条件 | 能否导出 M8 gold |
|---|---|---|
| SOURCE_UNVERIFIED | 来源仍为未核验转录/二手引文/研究假设 | 否 |
| INSUFFICIENT_REVIEWS | 独立标注少于两份 | 否 |
| REVIEWER_CONFLICT | 两份标注存在字段分歧，尚无最终裁决 | 否 |
| READY_FOR_ADJUDICATION | 两份独立标注一致，但尚无最终裁决 | 否 |
| ADJUDICATED | 底本来源已核验、两份独立标注、独立裁决者、裁决理由与证据均齐全 | 是 |

即使两位标注者完全一致，也只能进入 READY_FOR_ADJUDICATION，不能自动变成 gold。审查者 ID 只能表示声明的不同身份，不能由程序证明现实中的人确实独立。

## 4. 防止错误升级

- verified_primary / critical_edition 必须有底本定位、核验引用和核验者。
- 核验者不得与标注者 ID 重叠；此规则只是流程隔离，不是身份认证。
- 裁决者必须与标注者 ID 不同。
- accept 必须写明共享依据；conditional 必须写明适用条件。
- 最终决策可以是 abstain；未决本身是合法审定结果。裁决者必须提交最终主张、文本层、关系族、共享/差异依据、范围、不变量、反例与因果状态；导出时只使用裁决者的最终记录，不从任一标注者的记录中挑选字段。
- 只有显式最终裁决才能导出 M8 adjudicated case。
- 导出时必须明确指定 train/dev/test/holdout 分组；适配器不自行随机拆分。
- M8 的两名 reviewer 门禁仍保留；正式切分还必须按作品、版本和见证谱系防泄漏。

## 5. 与 M14–M18 的衔接

- M14：文本见证来源 DAG 与派生依赖。
- M15：原文片段对主张的支持范围、限定与反证。
- M16：竞争解释并存，避免术语映射固化。
- M17：推类迁移的根据、关系、范围、条件和反例门禁。
- M18：将待审案例转换为 M8 pending-review 结构。
- M19：只有经过来源核验、独立标注和显式裁决的案例才可升级为 M8 adjudicated。

## 6. 当前边界

原型不会自动核验扫描图像、馆藏号、版本真伪或审查者身份；不会判断引文是否蕴含主张；不会把一致率等同于真理。当前 source_status 的“已核验”是由审定工作流中的人工记录声明，仍需外部质量控制和抽样复核。

## 7. 测试

22 项专项测试覆盖：一致标注仍需最终裁决、分歧保留、来源未核验阻断、双标注加独立裁决后导出、缺裁决拒绝导出、探索集禁止作为 gold split、裁决者身份隔离、重复 reviewer、标注不足、来源核验凭据、核验者隔离、accept/conditional 依据门禁、abstain 合法性、分歧裁决、证据引用合并和缺失定位拒绝。

M19 是数据治理与审定流程工具，不是古籍自动判真器，也不构成类象理论有效性的实证结论。
