# E02-K：自适应关系生命周期证据

## 研究问题

E02-I 证明固定两窗口确认在七种合成场景中可行，但它把强证据和弱证据都按相同窗口数处理。E02-K 检验：能否根据独立窗口中的证据强度，自适应决定关系重配置与退役需要多少证据，同时避免单窗口冲击造成永久修改？

## 核心机制：有界序贯证据

对同一候选签名，比较候选与当前关系/最佳低阶基线在同一 Gate 样本上的成对正确性：

- wins：候选正确而基线错误；
- losses：候选错误而基线正确。

采用序贯对数似然比：

\[
LLR = wins\cdot\ln(0.65/0.5)+losses\cdot\ln(0.35/0.5)
\]

每个窗口的 LLR 限幅到 [-1.5, 1.5]，防止单个超大样本窗口独占决策。相同候选签名跨窗口累计正负证据；签名改变或候选被撤回时，清除该候选的待决证据。

默认序贯阈值：

\[
A=\ln((1-\beta)/\alpha),\quad \alpha=0.05,\;\beta=0.10
\]

因此 A 约为 2.89。另设至少两个独立支持窗口的下限，确保单窗口瞬态变化即使很强，也不能直接永久重配置。强而持续的变化通常两窗口可确认；弱变化需要更多窗口；反证会抵消先前证据。

当前关系健康状态使用独立证据累积器。退役同样要求至少两个支持窗口；恢复证据会降低失效分数。退役后重新创建关系也必须再次积累证据，避免噪声候选立即复活。

## 控制器原型

`prototype/e02k_adaptive_evidence.py` 只负责证据累计和生命周期动作。它不负责发现候选，也不从测试集取证。上游必须提供：
- 候选与基线在 Gate 上的 paired wins/losses；
- 当前持久关系的失效证据；
- 每个窗口的候选签名。

本模块当前是控制器单元原型，尚未接入 E02-I 的真实数据生成器与发现器。不能把单元测试通过解释为 E02-K 端到端实验通过。

## 预注册对照实验

| 维度 | 取值 |
|---|---|
| 控制器 | E02-I 固定 2 窗口、固定 3 窗口、E02-K 有界序贯证据 |
| 标签噪声 | 0.02、0.10、0.20 |
| 每窗口 Train/Gate/Test | 128、512、2048 |
| 变化持续时间 | 1、2、3、5 个窗口 |
| 变化类型 | 成员增减、规则反转、瞬态反转、缓慢漂移、消失、从未存在 |
| 随机种子 | 先 20 个 smoke，再 100 个确认 |

## 主要指标

- 永久变化检测延迟（窗口数）；
- 瞬态变化误重配置率；
- 稳定场景误重配置率；
- 当前关系误退役率；
- 退役后噪声复活率；
- Candidate Test 与 Persistent Test；
- 每个决策所需 Gate 样本量和计算开销；
- 不同噪声/样本量条件下的 Wilson 95% 事件率区间。

## 必须证伪的情况

- 单窗口瞬态冲击导致 RECONFIGURE；
- 弱噪声持续变化永远无法确认；
- 稳定关系因随机负证据频繁 DEGRADED/RETIRE；
- 退役后随机候选轻易 CREATE；
- E02-K 只是在某个噪声水平调参获胜，跨条件没有优势。

## 当前限制

p1=0.65、窗口证据限幅 1.5、alpha/beta 是预注册设计参数，不是系统自主学出的参数。E02-K 当前只验证了控制器逻辑，尚未证明其相对固定窗口基线具有端到端优势。后续敏感性分析必须比较 p1、限幅、alpha/beta 的多个组合，不能只报告最有利的一组。
