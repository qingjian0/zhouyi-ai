# E09-B 独立审计：反例驱动学习器是否真正增量修订？

日期：2026-11-11

## 1. 摘要

E09-B 已经有一个有价值的纯符号、非梯度原型：它在预先声明的有限类别变量域和合取式 DSL 中枚举候选模式，以支持数和已观察反例过滤候选，再用贪心覆盖构造规则集合。它具备候选预算、拒答路径、结构快照和零梯度更新声明。

但当前实现更准确的名称是：

**带反例约束的批量规则归纳器（batch rule induction with counterexample constraints）**

它还不是严格意义上的在线/增量反例驱动结构学习器。当前的反例测试通过把旧样本与新反例重新传给 `fit()`，从全部证据重新拟合；没有持久证据账本、单样本观察接口、规则版本迁移记录或 prequential（先预测、后揭示标签）评估。

## 2. 代码级发现

### F1. 规则语言与变量域由外部预先给定

`CounterexampleRuleLearner(domains)` 要求调用方提供变量数、变量顺序和每个变量的离散取值域。搜索空间为每个变量选择 `None` 或一个域值的笛卡尔积。

这能验证“在指定 DSL 内搜索规则”，不能验证系统能自主发现：
- 变量边界与变量数量；
- 新属性或关系类型；
- 新的规则语法/算子；
- 不属于部分赋值合取式的规则形式（例如 XOR、模运算、递归或带状态的转换）。

因此，E09-B 结果必须按“有限预设语言内的规则归纳”报告，不能写成自主发明规则语言。

### F2. 当前 counterexample 测试不是在线更新

测试 `test_new_counterexample_invalidates_broad_rule` 的流程是：
1. 构造初始样本列表；
2. 调用 `fit(initial)`；
3. 观察一个尚未见过的输入上的规则预测；
4. 把反例追加到 Python 列表；
5. 调用 `fit(initial + [counterexample])`。

第二次 `fit()` 会重新验证和重建全部候选及规则。学习器对象没有接收单条证据的 `observe()` / `update()` 接口，也没有保留样本 ID、证据来源、规则旧版本或变更原因。

所以该测试证明“批量重拟合会排除与新增反例冲突的规则”，不证明“系统在线接收反例并自主修订内部结构”。

### F3. 规则选择是贪心覆盖，不是全局结构最优

每个标签的候选规则必须：
- 覆盖至少 `min_support` 个正例；
- 不覆盖任何已观察负例。

随后按新覆盖样本数优先、文字数次优、repr 稳定排序，逐条选择规则。这是清楚且可复现的启发式，但不保证全局最小规则集、最小描述长度或最佳泛化。

建议增加 exact set-cover / MDL 小规模 oracle，仅在可穷举的小任务上测量贪心差距；同时保留贪心版本作为低成本基线。

### F4. 候选预算有上限，但计数与实际运行成本仍需区分

当前在生成模式前估算：
`product(|D_i| + 1) × number_of_labels`

并对超过 `max_candidates` 的任务直接失败。这是正确的 fail-closed 起点。

但它尚未报告：
- 实际 pattern-label 匹配次数；
- 正负样本扫描次数；
- 生成候选和贪心覆盖的独立耗时；
- 峰值内存；
- 每次增量修订的边际成本。

应明确区分理论候选数、实际评估数和 wall-clock 成本。

### F5. 当前演示集过小，不能作为方法效果证据

`run_demo()` 使用三变量、每变量三个值的单个固定目标函数，保留 4 个样本作为 held-out。测试验证的是这个固定例子能运行并得到指定结果，不是跨规则族的统计泛化。

尚缺少：
- 多种子生成；
- 规则族级 train/test 隔离；
- 低阶规则与高阶交互的分层对照；
- XOR / parity / 非合取反例；
- 标签噪声、缺失证据和矛盾证据；
- 查表、随机、精确枚举、MDL、梯度方法同预算比较。

### F6. “零梯度”目前主要是实现审查与报告字段

代码路径未见自动微分或梯度优化调用，报告写入 `gradient_updates: 0`。但这个字段由实现自行声明，不是独立的运行时证明。

正式基准应增加依赖/调用路径审计，明确纯非梯度主臂允许的模块白名单，并把 HYB 单独标记为混合对照。不能仅凭字段值认定全实验链未使用梯度。

## 3. 推荐 E09-B0.2：把批量归纳升级为可审计的增量学习器

不建议先扩展更大的 DSL。先让同一小型 DSL 具备真正可审计的时间维度。

### A. 证据账本
- 每条输入证据有稳定 `example_id`、内容哈希、来源和到达序号；
- 重复相同 ID/内容应幂等；
- 同 ID 不同内容必须拒绝或进入显式冲突处理；
- 原始证据不可被规则更新覆盖。

### B. 单条观察接口
新增 `observe(example)` 或等价接口：
- 预测必须发生在标签揭示之前；
- 标签揭示后才更新证据账本；
- 更新返回新增/保留/降级/删除的规则版本差异；
- 不要求调用方重放全部历史数据。

允许内部选择全量重算作为实现基线，但必须将其标记为 batch-recompute 对照；真正的增量臂需要展示增量状态和成本。

### C. 反例修订语义
每条规则记录：
- 支持证据 ID；
- 反例证据 ID；
- 当前状态（active / weakened / split-candidate / rejected）；
- 父版本与修订原因；
- 适用上下文及未知边界。

反例不能自动证明某条规则应删除：应测试“局部缩窄、拆分、降级、拒答”与“全局删除”之间的选择。

### D. Prequential 评测
按时间顺序逐条输入：
1. 先预测；
2. 记录预测和置信/拒答状态；
3. 再揭示标签；
4. 更新结构；
5. 继续下一条。

报告修订前后性能、错误规则存活时间、反例响应延迟、旧任务遗忘、每次更新计算量。禁止把已揭示标签用于同一条样本的先验预测。

## 4. 最小验收测试

1. **反例到达测试：** 新反例在揭示前不能改变预测；揭示后才允许改变。
2. **证据幂等性：** 相同 ID/内容重复输入不改变结构版本。
3. **证据冲突：** 同 ID 不同内容不得静默覆盖。
4. **版本可追溯：** 每次规则改变都能追溯支持和反例。
5. **局部修订：** 一条规则的反例不应无证据地删除不相关规则。
6. **顺序测试：** 对相同最终证据集，比较流式学习与 batch refit 的结果差异；差异必须被解释。
7. **预算测试：** 单条更新的候选评估成本有硬上限，超限显式拒答/暂停。
8. **prequential 测试：** 指标使用标签揭示前的预测，不用训练后回放分数冒充在线能力。

## 5. 研究定位与下一步

当前 E09-B 可以保留为 batch symbolic induction baseline。建议新增 E09-B0.2 独立实验臂，不覆盖现有实现。

实施顺序：
1. 冻结当前原型与固定 demo 作为 batch baseline；
2. 加入稳定证据 ID 和不可变账本；
3. 加入 observe/feedback 两阶段接口；
4. 加入 prequential 多种子 benchmark；
5. 加入局部规则修订与 lineage；
6. 再比较 NG-A/B/C/D/E 及 HYB。
