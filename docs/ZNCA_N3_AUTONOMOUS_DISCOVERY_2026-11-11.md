# ZNCA N3：自主关系候选发现（参考原型）

日期：2026-11-11  
状态：有限候选生成与排序原型；不是因果发现算法，也不是端到端自主学习系统。

## 1. 问题

N2 要求外部提供候选关系项。N3 的第一步是从状态转移样本提出候选交互结构，而不是由研究者手工指定全部组合。

## 2. 当前算法

对每个目标状态 (y)，先以训练样本均值作为基线，计算残差 (r=y-\bar y)。对非目标变量的每个有界组合 (S)，构造乘积特征 (p_S=\prod_{i\in S}x_i)，并计算中心化关联分数：

\[
score(S,y)=\left|\frac1N\sum_n(p_{S,n}-\bar p_S)r_n\right|
\]

分数符号提出促进/抑制方向。每个大小为 r 的变量组合有 2^r 种互补配置，因此候选总数呈指数增长；按分数、结构大小、变量名和互补配置确定性排序，输出有限数量的候选 InfluenceTerm。

## 3. 当前实现

- `prototype/znca_discovery.py`：正向/互补文字候选枚举、关联评分、极性提议、证据引用保留、预算耗尽显式返回。
- `tests/test_znca_discovery.py`：高阶联合关联、XOR 互补组合、负关联、预算确定性、无信号、模式校验和证据保留。

## 4. 重要边界

1. 关联不等于因果。共同原因、数据偏差和时间泄漏都可能制造高分候选。
2. 该实现从已结构化的状态变量工作；它不从原始文本、图像或声音中提取状态。
3. 正向/互补文字使候选数按每个组合的 2^arity 增长；当前枚举复杂度为指数级，候选预算只能限制工作量，不能保证高召回。
4. 当前评分没有条件互信息、混杂控制或干预识别。
5. 训练样本证据引用表示候选来自哪些训练观察，不代表这些证据独立支持因果方向。
6. 不能在同一数据上发现候选、拟合权重并报告最终成绩。必须采用 train / validation / locked test 分离，最好再加分布外组合测试。
7. 变量名和候选排序只用于确定性，不提供语义理解。

## 5. 下一阶段

- N3-C：结构竞争、复杂度惩罚和跨折稳定性；
- N3-D：类象映射的部分结构同构发现与负迁移检测；
- N3-E：干预/反事实验证，区分预测关联与因果机制。

## 6. 证伪条件

若发现的高阶候选在锁定测试中不优于随机候选，或对变量置换不敏感，或跨折不稳定，则不得将其视为有效结构。若更简单的 pairwise 模型同等或更好，应选择更简单模型。
