# 类象有效性与迁移评估基准 M8 v0.1

状态：研究设计 / 待实现 / 待原典校勘  
适用分支：`research/classical-yixiang-corpus-2026-11-13`  
前置模块：M3 竞争裁决、M4 条件干预、M5 主动观测、M6 新象提议、M7 编排  
原则：本文件提出现代工程操作化方案，不将信息论、贝叶斯或因果推断术语倒灌为古人原有理论。

## 1. 要回答的核心问题

类象系统不能只回答“两个对象像不像”，必须分别回答：

1. **何处同**：共享依据是什么，属于形态、结构、功能、关系、过程、时序、位置还是语境？
2. **何处异**：关键差异是否会改变目标属性或推论？
3. **何时可迁移**：哪些条件保持时，映射才可能有效？
4. **迁移到哪里**：结论适用于对象、关系、过程还是某个局部维度？
5. **何时拒绝**：证据不足、关键变量缺失、反例成立或来源不独立时，系统能否 abstain？
6. **因果地位为何**：文本象征、规范类比、相关、时间共现、机制假说、干预证据必须分层。

“相似度高”不得自动推出“同类”，更不得自动推出因果关系。

## 2. 关系类型：先分型，再比较

每个类象候选必须声明一个或多个 relation family；禁止只存一个无类型的 similarity score。

| 关系族 | 最低判据 | 典型失败 |
|---|---|---|
| 形态相似 | 可观察形态特征对应 | 外形相似但功能无关 |
| 结构同构 | 关系节点及连接模式对应 | 节点标签相似、关系方向不同 |
| 功能相似 | 在明确目标和环境下实现相近功能 | 同功能但机制、代价或副作用不同 |
| 过程/机制相似 | 状态转移、作用链条可对齐 | 只对齐起点终点，遗漏中间机制 |
| 时序类比 | 顺序、周期、相位或转折结构对应 | 时间尺度不同或周期只是巧合 |
| 位势/情境类比 | 主体能力、资源、约束、位置与环境共同对应 | 把环境优势误作主体能力 |
| 符号/规范对应 | 文本或传统内部的象征、伦理、制度映射 | 把文化约定当作自然因果 |
| 经验相关 | 在明确样本与测量中稳定共变 | 混杂、选择偏差、反向因果 |
| 因果类比 | 机制与干预条件均有独立证据 | 仅凭共现或叙事顺序断言因果 |

不同关系族可以组合，但必须逐项给出证据，不允许由一种关系的证据替另一种关系背书。

## 3. 类象记录的最小评估对象

建议新增评估样本结构（后续实现为独立 schema，不直接改写现有古籍 corpus schema）：

- `case_id`：稳定样本标识。
- `source_lineage`：作品、版本、注疏谱系、数字见证；用于防止同源泄漏。
- `source_status`：原典已核、可靠校本、数字转录候选、二手转引、研究假设。
- `target_claim`：本次迁移真正要检验的命题。
- `relation_families`：明确关系族。
- `shared_basis`：共享依据及可观测/可核验方式。
- `non_shared_basis`：关键差异，不得只写“其他差异”。
- `scope_conditions`：主体、环境、尺度、时间、资源、制度等边界。
- `required_invariants`：迁移时必须保持的关系或条件。
- `known_counterexamples`：已知反例与反例成立条件。
- `causal_status`：symbolic / normative / co_occurrence / correlational / mechanistic_hypothesis / intervention_supported / unknown。
- `evidence_refs` 与 `independence_group`：引用标识和来源独立性分组；多个 URL 不等于多个独立来源。
- `gold_decision`：accept / reject / conditional / abstain。
- `gold_rationale`：可追溯裁决依据及审查者。
- `split_group`：按作品、版本、注疏谱系、领域或主体分组，供严格留出。

古籍语料原始记录继续保存原貌；评估样本通过引用 record_id/claim_id 建立链接，不把现代裁决写回古籍原文层。

## 4. 裁决标签与决策顺序

四种裁决结果：

- **ACCEPT**：关系族明确、共享依据与目标命题相关、关键差异未破坏目标推论，且证据满足该关系族门槛。
- **REJECT**：存在决定性反例、关系类型错配、必要不变量破坏，或推论超出证据范围。
- **CONDITIONAL**：只有在可明确陈述、可检查的条件下成立；条件必须成为结果的一部分。
- **ABSTAIN**：来源、测量、关键条件或独立证据不足；不得把未知编码为假，也不得强行二分类。

建议裁决顺序：

1. 来源与文本状态核验；
2. 目标命题精确定义；
3. 关系族判定；
4. 共享依据与关键差异抽取；
5. 不变量及适用范围检查；
6. 反例搜索；
7. 因果地位检查；
8. 选择 ACCEPT / REJECT / CONDITIONAL / ABSTAIN；
9. 记录理由、证据谱系和版本。

## 5. 基准分层

### B0：关系识别

判断候选属于哪类关系，允许多标签和 abstain。测试形似、结构、功能、机制、时序、位势、象征及经验关系的混淆。

### B1：共享依据与关键差异

给定一组对象/文本主张，分别识别 shared_basis 与 non_shared_basis。关键差异遗漏应计为高代价错误。

### B2：范围与条件迁移

在主体、环境、时间尺度、资源、制度或目标发生变化时，判断结论是否仍成立，或是否必须降级为 CONDITIONAL / ABSTAIN。

### B3：反例与拒绝迁移

注入反例、边界样本、机制不一致样本。检验系统是否能拒绝，而不是事后补充任意解释。

### B4：相关—因果辨析

用时间共现、共同原因、反向因果、选择偏差、真实干预等对照组，测试因果标签是否越级。

### B5：新象发现

向 M6 输入噪声残差、重复来源、同域重复、条件遗漏、已知签名变体和真正跨域候选，测量伪新象率与漏检率。M6 proposal 不等于已发现规律。

### B6：组合与分布外泛化

对未见过的关系组合、领域、作品、版本、注疏谱系和主体进行留出。不能让同一作品的不同转录版本跨训练/测试集泄漏。

## 6. 必须包含的古典论证对照样本

以下只作为候选研究入口，须按项目古籍规程完成底本、篇章语境和异文校勘后，才能成为 gold sample：

- 《墨子·小取》：“其然也同，其所以然不必同。”用于区分结果相同与所以然/机制相同，测试从表面同一误推因果同一。
- 《荀子·非相》：“相形不如论心，论心不如择术。”用于测试外观代理与目标属性错配；须核验上下文和版本。
- 《淮南子·说林训》关于“见物同而用之异”的论述，作为同物异用、主体—工具适配的候选材料；具体文字与篇章上下文待校。
- 《韩非子·难势》龙蛇乘云雾与蚯蚓、蚂蚁的对比，测试主体能力与外部条件不可混淆；不得把寓例直接当作自然科学观察数据。
- 《论衡·感类》对祈雨感应的质疑，作为时间先后/叙事共现不足以证明因果的反例材料；需保留王充论证语境，不将其自然气解释自动当作现代因果结论。

这些材料各自处于不同文本类型与论辩语境，不应合并成单一“古人统一算法”。

## 7. 负控与对抗测试

每个关系族都必须具备：

- **表面相似负控**：共享显眼特征，但目标属性不共享。
- **机制破坏负控**：表面和结果相似，中间机制不同。
- **条件遗漏负控**：缺少决定性主体/环境/时位条件。
- **尺度错配负控**：微观局部规律被错误迁移到宏观整体，或反之。
- **来源伪独立负控**：多个网页/版本实为同一底本或同一转引链。
- **反向因果负控**：结果可能影响原因变量。
- **选择偏差负控**：只收集成功案例或被观察到的样本。
- **时间共现负控**：事件先后相接但没有机制或干预证据。
- **新颖性负控**：对已有签名做字段顺序、别名、噪声扰动，不能误报为新结构。

## 8. 指标：不能只报告准确率

必须同时报告：

- relation-family macro-F1；
- ACCEPT/REJECT/CONDITIONAL/ABSTAIN 的 per-class precision、recall、F1；
- 关键差异遗漏率；
- 适用范围越界率；
- 反例拒绝率；
- 因果越级率（把共现/相关/象征误报为因果）；
- abstention coverage 与 selective risk；
- 条件裁决正确率；
- 来源谱系去重后的独立复现率；
- OOD 性能下降；
- M6 false novelty rate、novelty recall、review reversal rate；
- 观察成本、风险与真实信息增益（只能在观察实际执行并记录后计算）。

所有指标按关系族、文本时期、来源状态、领域、难度和留出组分别报告，并给出样本量与置信区间。小样本不得只报一个总体分数。

## 9. 与 M3—M7 的接口

- M3 输出竞争解释及证据状态；评估 gold decision 不由 M3 自己生成。
- M4 只评估显式条件干预/反事实，不将模型模拟结果升级为实测因果。
- M5 的信息增益是基于给定似然的 prospective estimate；真实信息增益必须在观察执行后另行计算。
- M6 的 evidence_refs 必须在调用前按 source_lineage 去重；仅检查引用字符串数不够。
- M7 负责调度，不负责给自身打分；评估器应在管线外运行，防止自证循环。

## 10. 消融与验收

最少比较：

1. M3-only；
2. M3 + M4；
3. M3 + M4 + M5；
4. M3 + M4 + M5 + M6；
5. 完整系统去掉 shared/non-shared basis；
6. 完整系统去掉 scope/invariants；
7. 完整系统去掉 source lineage dedup；
8. 完整系统去掉 counterexample retrieval。

验收前提：

- gold 样本由至少两名独立审查者标注；分歧保留，不以多数票抹掉理由。
- 作品、版本、注疏谱系与领域隔离清晰。
- 所有古籍 gold 样本有原典/校本定位；未经核验的数字转录只能进入 exploratory split。
- 负控覆盖每种关系族。
- 报告全部指标、置信区间、失败样例和 abstention 情况。
- 任何性能提升都必须与消融、负控和 OOD 结果同时呈现。

## 11. 实施顺序

1. 新建独立 benchmark schema 与 validator，不改变现有 corpus 原始层。
2. 建立 30–50 个人工审查的最小对照样本，先覆盖 B0–B4；所有未校勘古籍例只进入 exploratory pool。
3. 加入 source lineage / independence group 去重。
4. 实现 deterministic evaluator，输出分层指标和错误案例。
5. 接入 M7 的输出快照，但保持评估器外置。
6. 形成第一轮基准报告后再扩到 B5–B6。

当前阶段只定义协议与数据契约；没有人工 gold 标注、独立来源谱系审核和实际观察结果之前，不得宣称基准验证了类象理论的普遍有效性。
