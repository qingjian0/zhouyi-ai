# YJ-05：统一算子学习闭环（证据治理参考实现）

日期：2026-11-11  
分支：`research/yj05-unified-operator-learning-loop-2026-11-11`  
基于：YJ-04 PR #204

## 1. 目标与非目标

YJ-01～04 分别建立易学结构算子契约、确定性参考算子、类型组合规划和关系差分候选发现。N0.10、N0.11、N0.12、E13 则分别提供角色结构评分、有限 DSL 归纳、主动候选辨识和跨域实验协议。

这些原型并没有真正接成一个训练系统。YJ-05 首先统一它们共同需要的**候选生命周期、证据分割、主动实验提交/揭示和反例处理协议**。

它不是端到端神经认知模型，也不宣称已经把 N0.10/N0.11/N0.12/E13 runtime 全部接入。

## 2. 统一循环

1. **DISCOVERY**：只用发现集提出候选机制。
2. **PROPOSED**：保留候选结构、来源证据、适用领域与前置条件。
3. **VALIDATION**：独立验证集计算 accuracy 与 coverage；达到门槛才进入 VALIDATED。
4. **ACTIVE QUERY**：在候选预测分歧的有限查询池中选择实验，并先提交 query ticket。
5. **REVEAL**：实验结果只能在 ticket 提交后揭示，保留来源与证据类型。
6. **COUNTEREXAMPLE**：确定性候选被有效反例击中时进入 SUSPENDED，保留反例，不静默删除。
7. **TEST**：测试集只做最终报告，不能参与发现、阈值选择或候选晋级。

## 3. 统一对象契约

- `EvidenceCase`：观测/干预轨迹 + 数据分割标签；
- `MechanismCandidate`：YJ-04 的版本化、角色绑定关系转移假设；
- `CandidateRecord`：候选生命周期、发现证据、支持证据、反例和验证指标；
- `CandidateEvaluation`：accuracy、coverage、弃权和错误样本；
- `ExperimentQuery`：明确状态、干预、领域和 query ID；
- `ExperimentFeedback`：匹配候选、被反例否定候选和证据来源。

## 4. 防止数据泄漏

- DISCOVERY evidence ID 不能进入 VALIDATION 或 TEST；
- 每个 evaluation split 内 evidence ID 不能重复使用；
- TEST 结果不能调用 validate，也不能改变候选生命周期；
- 主动实验必须先 commit query，再 reveal outcome；
- 反例进入持久候选记录，候选被暂停而不是被静默抹除；
- 当前内存态 coordinator 只用于协议原型；跨进程防篡改、锁定测试隔离和持久事件存储仍需后续实现。

## 5. 与现有研究线的关系

| 模块 | 统一闭环中的角色 | 当前状态 |
|---|---|---|
| YJ-04 | 关系状态候选发现与预测 | 本原型直接调用 |
| N0.10 | 学习角色绑定与结构评分 | 尚未接入；未来作为候选排序器 |
| N0.11 | 从有限 DSL 归纳组合程序 | 尚未接入；需要 typed relational DSL adapter |
| N0.12 | 主动选择区分候选的实验 | YJ-04 finite-pool disagreement 先行复用；N0.12 numeric API 尚未直接接入 |
| E13 | 跨域映射、证据事件与干预轨迹 | 协议概念对齐；尚未接入 E13 runtime |
| MTS-0 | prediction/commit/reveal 隔离 | 当前只有 coordinator 内部 ticket；不是安全隔离边界 |

## 6. 为什么暂不直接把所有模块 import 到一起

N0.11 的状态是数值向量和 DSL 程序；N0.12 的预测器同样以数值向量为接口；YJ-04 使用带类型、角色、关系和上下文的 RelationalState；N0.10 则处理角色候选节点与特征向量。E13 的共享图契约更通用，但尚需明确映射与证据可见性。

若此时写一个大而全的 import 适配器，会把“接口看起来相同”误当成“语义等价”。因此 YJ-05 先统一生命周期和证据协议；后续为每条研究线建立有损/无损映射说明、round-trip tests 和独立消融。

## 7. 易学结构的进入方式

易学结构不能作为不可更改的 oracle。阴阳、五行、爻位、时位、卦变、象数理和取象比类可以生成候选先验或结构约束，但必须同时保留通用关系先验、无先验、随机先验和错误先验对照。

候选晋级只依赖可观察的任务证据，不因候选名称来自传统理论而获得额外分数。

## 8. 当前限制

- YJ-04 候选是离散关系新增/删除模式，不含连续强度、概率转移和隐状态；
- 主动查询只对外部给定的有限 query pool 排序；
- accuracy 仅在可适用样本上计算，coverage 必须同时报告；
- 单个反例只会暂停候选，需人工/更高层证据审查后再决定修订或拒绝；
- coordinator 是单进程内存对象，不是防篡改事件存储；
- 目前无原始语言、多模态 grounding，无神经梯度训练，无真实世界因果识别；
- 尚未接入 N0.10/N0.11/N0.12/E13 runtime。

## 9. 验收

- 测试集不能晋级候选；
- 发现证据不能重复用作验证；
- 低 coverage 不能仅靠高 conditional accuracy 晋级；
- 未提交 query 不得揭示结果；
- 重复揭示必须拒绝；
- 反例必须保留并暂停候选；
- 所有候选保留证据 ID、领域与版本；
- 完整 CI 和结果应如实报告，不以代码静态审查代替运行。
