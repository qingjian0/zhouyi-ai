# E09-B0.3：Prequential Incremental Index Arm

日期：2026-11-11  
状态：原型已提交；等待自动化测试与代码审查。  
基础：E09-B0.2 / PR #54。

## 目标

在严格 predict/commit/reveal 时间边界下，加入一个不对全量历史数据执行 `fit()` 的独立增量更新臂，并与既有 `BATCH_REFIT` 对照。

## 实现结构

- `IncrementalConjunctionLearner`：按输入值生成其匹配的 (2^d) 个合取模式，并维护每个模式的总计数和按标签计数。
- `PrequentialRunner(revision_mode="INCREMENTAL_INDEX")`：揭示标签后先写账本；只有调用 revise 才把该条新证据应用到增量索引。
- 预测、揭示、修订仍沿用 B0.2 的时间因果协议。

## 局部更新规则

对新唯一输入 x：
1. 枚举每一维“约束为 x_i / 忽略”组合；
2. 对匹配的 (2^d) 个模式增加总计数和标签计数；
3. 重复同标签输入不重复贡献；
4. 同一输入出现不同标签时，撤销第一次唯一标签的贡献，并把该输入永久视为 contested，后续标签也不参与学习。

模式预测条件：支持数达到 `min_support`，且该模式匹配的所有未争议训练输入都属于同一个标签。若查询同时命中多个标签的有效模式，拒答。

## 复杂度与公平比较

设变量数 d：
- 增量更新：每个新唯一输入最多 (2^d) 次模式计数修改；冲突撤销再执行 (2^d) 次。
- batch baseline：每次重拟合遍历完整合取模式空间 (prod_i(|D_i|+1))，并按标签检查训练样本。
- 当前计数是逻辑操作数，不可冒充 wall-clock、CPU 指令或峰值内存。
- 增量模式保留全部有效安全模式，不等同于 batch learner 的 greedy-cover 子集；表达能力与覆盖率必须单独比较。

## 验证要求

测试覆盖：
- 新反例只影响其匹配模式；
- 重复样本幂等；
- 冲突撤销与隔离；
- reveal 后、revise 前模型保持不变；
- revise 后增量更新成本恰为 (2^d)（无冲突新样本）；
- 输入 arity/domain 检查；
- 与 BATCH_REFIT 同一 prequential 数据流对照。
