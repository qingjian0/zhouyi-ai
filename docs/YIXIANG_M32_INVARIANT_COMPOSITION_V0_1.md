# M32：类象不变量组合与层级涌现 v0.1

## 1. 研究问题

M31 的不变量候选即使在各自适用域内成立，也不能推出它们组合后的整体规律成立。M32 专门审计这一推理断层：局部规律如何组合、交互如何改变结果、整体主张需要什么独立证据，以及如何记录“局部稳定但整体失效”的反例。

核心原则：**成员状态不向整体状态自动蕴含**。M32 不自动发现组合、不证明涌现，也不把传统类象理论等同现代复杂系统理论。

## 2. 对 M26 的复用审计

M26 已提供 SymbolicElement、CompositionNode、CompositionEdge、EmergentCategoryClaim，并覆盖并列、有序、包含、交互、对立、转化、成员端点、情境版本、整体/成员证据分离、非可约化论证与反例引用。M32 不复制这些通用组合结构。

M26 的缺口在于：它组合的是符号元素，不是 M31 的不变量候选；未校验成员不变量状态；没有整体级证据的来源家族独立性检查；没有组合依赖 DAG；没有对象/组合/来源家族多维隔离评估；也未显式建模局部不变量全部成立而整体失效的成对反例。因此 M32 新增的是“不变量层组合审计”，并保留 M26 为通用符号组合层。

## 3. 古典材料与解释边界

### 《周易·系辞上传》

“参伍以变，错综其数，通其变，遂成天地之文；极其数，遂定天下之象。”此句处于蓍筮变数、成卦的传文语境。可研究其变、数、文、象之间的程序关系；把它映射为组合算子、状态空间或复杂系统涌现，只能作为现代工程假设，不能当作古义。

### 《周易·系辞下传》

“近取诸身，远取诸物”提示取象材料可跨尺度、跨来源；它本身不证明局部规律组合后必然形成整体规律。

### 《墨子·小取》

“其然也同，其所以然不必同”警告相同结果未必同因；“远而失，流而离本”警告推类在跨越过远时会失去根据。M32 因此分别记录成员证据、交互证据、整体证据，并要求竞争解释。原文与异文见证可对读维基文库《小取》、四部丛刊本及 Ctext；胡适《〈墨子·小取〉篇新诂》属于现代解释史，不作为先秦原义。

### 《荀子·正名》

“物有同状而异所者，有异状而同所者”要求区分表面属性、对象所处和类别判断；“状变而实无别”涉及变化与对象连续性。工程上不可仅凭成员标签相同推断整体身份或行为相同。

### 《淮南子·说林训》《吕氏春秋·别类》

适合作为条件变化、反例和类推边界的材料入口；须逐条核验篇章语境、版本和文本层次，不能把譬喻直接当成现代实验结果。

## 4. 组合类型

- parallel：并行/并列，不预设成员交互。
- ordered：顺序组合，交换顺序视为不同干预。
- containment：包含与层级关系。
- interaction：成员相互作用。
- opposition：对立、制约或张力。
- transformation：状态转化。
- constraint：一个成员限制另一个成员的可行域。
- conditional：某成员或条件触发另一规律。

后两类是 M32 新增类型；均为工程分类，不是古典术语的直译。

## 5. 数据契约

- InvariantSnapshot：显式引用 M31 不变量 ID、层级、状态、范围、对象家族、情境家族和成员证据。
- CompositionSpec：成员集合、组合类型、顺序、范围、情境家族和边界条件。
- CompositionDependency：成员不变量之间的有向依赖边；必须端点完整、无自环、无循环。
- EvidenceRecord：证据级别 MEMBER / WHOLE / INTERACTION，并记录来源家族、情境家族和审查状态。
- EmergentInvariantClaim：整体级定义、预测观察量、成员/整体/交互证据、非可约化论证、反例、竞争解释和审查者。
- CompositionCounterexample：局部稳定但整体失效、顺序翻转、交互改变、机制相同而系统行为不同等反例。
- CompositionEvaluation：按对象家族、情境家族、组合 ID、来源家族隔离训练/测试，并留存配置、指标、结果引用与限制。

未知 M31 状态一律拒绝；REFUTED 成员不能进入可支持整体主张的成员池。CANDIDATE / INCONCLUSIVE / UNKNOWN 成员只允许进入探索性组合并触发人工审查。

## 6. 整体证据门槛

整体主张至少需要：
1. 两个以上不同不变量成员；
2. 分离的成员级与整体级证据；
3. 交互/约束/条件/转化类组合的交互证据；
4. 整体级证据来自不同来源家族，且不与成员证据 ID 重叠；
5. 操作定义、预测观察量、范围、边界条件；
6. 非可约化论证；
7. 反例登记与竞争解释；
8. 人工审查。

来源家族不同仅是独立性的最低代理指标，不能保证统计独立或无共同祖先。后续须与 M28 来源谱系审计显式对接；当前未实现端到端集成。M29 不确定性状态也尚未自动接线。

## 7. 必须覆盖的反例

- 各成员局部稳定，但组合整体表现失败。
- 成员关系均成立，交互后结果反转。
- A→B 与 B→A 得到相反结果。
- 局部机制不变，系统级行为因环境/边界改变。
- 整体输出相似，但内部来源机制不同。
- 删除一个成员或一条依赖边后，整体规律消失。
- 整体看似新颖，实际可由成员属性并集或既有关系充分解释。

任何未解决的已审查整体反例阻止整体主张升级；局部成员状态不覆盖整体反例。

## 8. 评估基线与反泄漏

至少比较：
- member_prediction：只用局部成员预测整体结果；
- local_composition：局部组合模型；
- structural_relation：结构关系基线；
- whole_level：直接使用整体观测的模型/上界。

按对象家族、情境家族、组合 ID、来源家族隔离。固定数据划分、模型配置、参数量、训练预算、指标和置信区间方法。报告整体预测误差、局部到整体迁移落差、交互消融效应、顺序翻转率、整体反例漏检率、伪涌现率和选择性风险；不可只报告总体准确率。

## 9. 原型边界与测试

原型：`prototype/yixiang_invariant_composition_m32.py`  
测试：`tests/test_yixiang_invariant_composition_m32.py`

当前实现检查成员状态、组合边界、顺序排列、依赖环、证据级别、来源家族独立性代理、整体反例、竞争解释和多维数据泄漏。它不自动判断涌现真值，不自动把 M31 状态升级为整体规律，也没有把 M26/M28/M29 的对象自动适配到本模块。

专项测试覆盖 32 个结构与拒绝条件。测试是否通过以实际运行结果或精确 HEAD CI 为准；仅创建测试文件不等于通过。
