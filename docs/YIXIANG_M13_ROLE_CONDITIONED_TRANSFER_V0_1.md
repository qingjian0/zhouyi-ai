# M13 角色—机制—条件联合迁移审计 v0.1

## 1. 研究问题

M12 保留同一目标下的竞争路径；M13 进一步检查跨领域迁移是否同时保留参与角色、关系拓扑、作用步骤与适用条件。结果相似、名称相近或单条关系相似，均不足以证明迁移成立。

## 2. 古典研究依据（研究入口，不等同现代算法）

- 《墨子·小取》“其然也同，其所以然不必同”：结果相同不推出所以然相同，故关系结构与过程机制必须分别检查。
- 《淮南子·说林训》“见物同，而用之异”“类不可必推”：对象相同或类别相近，不构成无条件迁移许可；主体、任务和环境须进入适用条件。
- 《荀子·正名》关于名实、同异与辨类的讨论：名称/谓词必须回到对象、角色与实际关系，不能只做词面匹配。
- 《周易·系辞下》“方以类聚，物以群分”可作为分类研究入口；分类相近不等于机制相同。
- 《庄子·齐物论》彼是与参照视域相关论述提示比较框架会影响判断；视域变化必须显式记录，不能消解同条件下的真实冲突。

清以前典籍为研究主体，清代以后用于校勘、辑佚、补漏和解释史审查。经文、古注、现代解释与工程结构分层记录；以上引文仍须逐条核验版本、上下文和注疏。

## 3. 联合迁移合同

源域/目标域分别记录角色、关系边（谓词、主客角色、极性、顺序）、机制步骤（操作、施事/输入/输出角色、步骤序号）、条件轴和证据引用。合同另声明一一对应的角色映射、必需条件轴、必需关系谓词、必需机制操作，以及有双侧证据支持的条件变换。

## 4. 三层门禁

1. 角色与关系结构：角色映射须覆盖两侧全部角色且一一对应；映射后的关系边须保留谓词、方向、极性和顺序。关键结构冲突 -> REJECT。
2. 机制过程：逐步比较操作类型、施事/输入/输出角色及顺序。操作、角色或顺序改变 -> REJECT；不能由共同结果推断过程相同。
3. 适用条件：必需条件轴缺失或不同且无证据支持的变换 -> ABSTAIN。条件值不同，只有显式声明变换规则、边界且双侧证据均属于对应框架，才记录为有限条件变换。

证据缺失、来源两侧复用、未解决反例/击败因素 -> ABSTAIN。输入结构不合法（如角色映射不完整、变换证据未锚定）则抛出输入错误。

## 5. 裁决语义

- ACCEPT_SCOPED：声明的角色、关系、机制和条件门禁通过，仅表示有限范围内结构对应可进入人工复核。
- ABSTAIN：证据不足、条件缺失/错配或存在未解决击败因素；不得解释为反例不存在。
- REJECT：角色关系拓扑、方向、极性、顺序或机制步骤存在明确关键冲突。
- 所有裁决均 scope_only=True、causal_transfer_established=False；不做概率估计、因果识别、未来预测或唯一类象选取。

## 6. 验收覆盖

专项测试覆盖完全匹配、关系方向/极性反转、机制操作/角色/顺序变化、条件缺失/错配、证据支持的条件变换、变换证据未锚定、变换值不一致、双侧证据缺失/复用、未解决反例、角色映射不完整/非一一、必需关系/机制缺失及因果主张边界。

## 7. 当前边界

M13 使用调用方提供的结构化输入，不从古文自动抽取角色或机制；不验证证据内容真伪，也不把引用不同直接等同于真实独立。后续需接入来源谱系审计、M8 人工 gold、M7 编排与跨域留出评估。古籍案例在版本、卷篇、注疏和数字见证核验前，不得升级为 adjudicated gold。
