# 从二元关系到多元角色结构：类象关系研究 v0.1

## 1. 研究问题

简单图把关系表示为两个实体之间的边。但不少对象关系需要三个或更多角色共同成立，例如“某主体在某时、某地、以某方式作用于某对象”。拆成若干二元边可能丢失角色组合和整体条件。

必须区分：
1. 二元关系：两个实体之间的关系，方向性须显式声明。
2. 多元关系/超边：三个及以上实体共同参与一个关系，每个实体占据具名角色。
3. 过程/事件结构：多个关系在时间、条件和阶段上组织成序列或状态转移；不能仅靠一条静态超边表达。

## 2. 古典研究入口

- 《墨子·小取》：研究譬、侔、援、推、类、故等论辩操作，分析论证结构与推止条件，不把术语直接翻译成图算法。
- 《荀子·正名》：研究名、实、同异与分类目的，避免把角色名称误当成对象本体。
- 《周易·系辞》“方以类聚，物以群分”“引而伸之，触类而长之”：作为分类、扩展与关系组织的文本入口，解释须回到上下文。
- 《周易·说卦》：卦象条目并置方位、时令、亲属、身体部位等多种关系线索；不能未经论证就合并成统一规则。
- 《淮南子》《吕氏春秋》类应材料：研究多因素共同出现的历史宇宙论模型，不等同现代因果机制。

这些古籍并未提出现代“超图”概念；超图是本项目用于检验关系结构的现代形式化工具。

## 3. 角色化表示

一个 n 元关系表示为 H=(kind, dimension, {(role_i, entity_i)})。

例如 transfers(agent=A, source=B, recipient=C) 与 transfers(agent=A, source=C, recipient=B) 的参与实体集合相同，但角色不同，不能判为同一关系。

计算规则：
- 映射只对实体执行。
- 关系类型、角色名和维度默认精确匹配。
- 不自动假设对称、逆向、因果等价或时间可交换。
- 未映射实体所在超边不纳入保持集合，但必须报告为缺失。
- 映射结论必须具备证据、条件和有效范围。

## 4. 当前原型

新增 prototype/yixiang_relations.py：
- HyperRelation：带具名角色的多元关系。
- HypergraphAnalogy：源域、目标域、实体映射、关系、证据、条件与范围。
- assess_hypergraph_analogy：对角色化超边执行精确结构保持评估。
- 报告 precision、recall、F1、缺失关系和额外关系。
- 缺少证据、条件、范围或关系数据时拒绝接受。

它与 prototype/analogy.py 分工：后者是二元关系基线；新原型处理多元角色结构。它不自动发现实体、关系语义、角色同义词或因果规律。

## 5. 必须验证的实验

1. 角色交换负例：实体集合不变，只交换 source/recipient，必须拒绝。
2. 元数变化：三元关系与二元关系不得因共享部分边而被视为等价。
3. 部分映射：未映射实体涉及的关系必须列为缺失，不得静默忽略。
4. 额外关系：目标域多出的关系必须降低 precision。
5. 角色命名变化：没有显式角色对齐规则时，不允许自动视为等价。
6. 时间过程扩展：事件序列、持续时间、先后关系独立建模，不与静态超边混淆。

## 6. 本轮限制

当前是确定性符号原型，只验证给定映射是否保持具名角色结构。它没有证明超图比普通图更有效，也没有实现古文自动解析。下一步应在相同数据预算下比较二元图、角色化超图和事件过程表示，并设置角色置换、关系缺失和分布变化负例。


## 7. 与时空情境联合模型的关系

多元角色结构描述“哪些角色共同参与何种关系”；`prototype/yixiang_situated.py` 则把这种关系放回具体状态、时间步、位置、阶段与环境条件中比较。二者不可混同：静态超边不表达事件先后或环境变化，情境比较也不自动推断关系变化的原因。
