# E02-A v0.1：三阶协同 hard-negative 基准

## 目的
检验显式三元交互项能否解决二元边特征无法识别的关系。这是 E02-A 的最小诊断，不代表自然语言理解或通用智能。

## 数据生成
每个候选是角色有序三元组 (a,b,c)，每一维取 -1 或 +1。标签规则为 y=1 当且仅当 abc=+1。每个样本含 4 个候选：1 个正例、3 个负例。正例从乘积为 +1 的 4 种模式均匀抽取；负例从乘积为 -1 的 4 种模式中无放回抽取 3 个，再随机打乱。因此负例明确违反整体三阶约束。

## 对照
- Pairwise：截距、一阶项和全部三个二阶乘积项，共 7 维特征。
- Static order-3：在上述特征上增加 abc 三阶交互项，共 8 维。
- Dynamic CREATE gate：比较两种模型在独立验证集上的 exact-choice accuracy；三阶模型提升超过 0.01 时才创建三阶关系，否则保留 pairwise 结构。

三种方法使用相同训练样本、优化器、训练轮数和候选集。动态门控只用验证集作结构决策，测试集不参与选择。

## 运行
- python -m prototype.e02_higher_order --seeds 5 --start-seed 7 --json
- python -m unittest tests.test_e02_higher_order -v

## 可证伪点
1. 若 pairwise 模型稳定超过随机水平，检查采样器是否泄露一阶/二阶统计差异。
2. 若静态三阶模型无法优于 pairwise，检查优化器、特征实现和数据平衡。
3. 若动态门控在验证集选择三阶结构、但测试集不提升，说明结构发现可能过拟合验证分布。
4. 该任务只检验显式三阶交互在 parity 规则上的表达优势。下一版必须增加角色置换、噪声、分布偏移、非 parity 高阶规则，并加入参数/计算预算匹配。

## 状态
代码与单元测试已实现；性能结论以 CI 实际结果为准。未运行前不宣称任何准确率。


## 高阶归因审计（新增约束）

近期超图基准研究提醒：高阶模型的性能优势不自动证明模型使用了高阶信息；移除高阶信息后，模型可能仍保留大部分优势。因此 E02-A 后续报告必须区分“模型更强”和“增益确由三阶交互导致”。

本任务采用显式归因检查：
- 对 Pairwise 特征，逐项检查训练集与测试集的一阶、二阶统计是否平衡；
- 将三阶特征列屏蔽后重新评估，确认性能退化；
- 对三阶标签作受控置换，同时保持候选数量、类别比例和一阶/二阶边际不变；
- 报告模型参数量、训练步数和每样本特征计算量，避免把容量/预算差异误判为高阶信息收益。

若屏蔽三阶项后性能不降，或受控置换后仍保持原性能，则不得将结果解释为真正的三阶信息利用。

参考：Bu et al., “Do Higher-Order Models Win for Higher-Order Reasons? Rethinking Performance Gains in Hypergraph Learning” (2026-10-06), arXiv:2610.07981；Li et al., “DHG-Bench” (ICLR 2026)。
