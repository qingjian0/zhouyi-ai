# E02-B：三元有限域关系诊断协议（生成器阶段）

## 研究问题

E02-A 使用二元 parity。E02-B 改用三值变量与模 3 加法关系，检验结论是否只依赖二元编码或 parity 的特殊性。

## 任务定义

变量取值于有限域 Z3={0,1,2}。每个查询固定有序角色 (a,b)，候选为三个 (a,b,c)，其中 c∈{0,1,2}。唯一正确候选满足：

`(a + b + c) mod 3 = 0`。

因此每题 3 个候选、1 个正例、2 个负例。目标规则是可组合的代数关系，不是预先采样的随机标签。

## 平衡性证明与构造

每个完整数据块遍历全部 9 个 (a,b) 查询一次，并随机打乱查询顺序与每题候选顺序。

- 正例：对任意固定 (a,b)，恰有一个 c 满足规则；对任意固定 (a,c)，恰有一个 b 满足规则；对任意固定 (b,c)，恰有一个 a 满足规则。因此正例中三个角色对的 9 种取值组合各出现一次。
- 负例：每个角色对组合总共出现 3 次，其中 1 次为正例、2 次为负例。因此负例中每个角色对组合各出现两次。
- 所以任一单角色边际和任一角色对边际在正、负类别条件下均匀；仅依赖一阶/二阶类别条件频数的模型无法获得类别信息。

每个 block 的正例/负例比为 1:2。样本数必须为 9 的正整数倍。seed 控制块内查询顺序与候选顺序，不改变数学规则。

## 学习器对照（新增原型）

`prototype/e02_ternary_learners.py` 实现两个同数据、同优化器、同训练轮数的候选排序模型：

- Pairwise categorical：三个角色的一阶 one-hot 与 AB/AC/BC 三组二阶 one-hot，共 36 个参数。
- Static third-order categorical：在上述特征上增加 ABC 三元 one-hot，共 63 个参数。
- Validation gate：仅根据独立验证集准确率决定是否采用三元模型，门槛为提升超过 0.01；测试集不参与选择。

默认每个 seed 使用 900/180/180 条 train/validation/test 样本，350 epochs；每个集合大小是 9 的倍数，查询和候选顺序分别随机化。报告参数量，明确当前模型容量不匹配，因此不能把差异纯粹归因于阶数。CI 运行五个 data seeds。

## 当前实现边界

当前阶段只实现并自动验证数据生成器及边际审计；**尚未实现学习器对照，也没有准确率结果**。不能把此阶段称为模型实验成功。

下一步学习器比较至少包括：
1. Additive pairwise model：一阶类别特征 + 三组二阶角色对特征；
2. Static third-order model：在 pairwise 基础上增加三元联合特征；
3. Rule-composition model：学习有限域运算/关系组合，而不是把 27 个三元组当作独立记忆表；
4. Random / label-permuted controls；
5. Ablation：屏蔽三元项，检验性能是否退化。

必须报告参数量、训练步数、候选排序随机性、训练/验证/测试拆分方式。随机打乱同一 9 个查询不构成独立规则族复现；跨规则泛化需要额外构造不同运算、角色置换和未见符号映射任务。

## 证伪条件

- 若 pairwise 统计审计不通过，停止模型比较并修复采样器。
- 若 pairwise learner 明显超过机会水平，检查实现是否意外泄露三元规则或查询身份。
- 若高阶模型增益在屏蔽三元项后仍存在，不得归因于三元关系。
- 若 rule-composition 仅在见过的符号编码上有效，不能宣称抽象关系泛化。
