# M54：公平基线对照协议 v0.2

## 目标与边界

M54 提供预算匹配的基线比较入口。候选方法只接收训练观测、候选变量、目标变量和统一预算；验证/测试数据与评估真值不进入 AgentContext。该隔离由执行框架实现，但 Python callable 属于受信任适配器：若适配器主动通过闭包读取外部真值，框架无法从语言运行时层面阻止。正式实验必须采用独立进程/容器和只读数据挂载实现强隔离。

当前交付是协议与适配器接口，不等于已完成 PC/FCI、SCM、Transformer 或类象 Agent 的端到端实测，不构成类象优越性证据。

## 已实现

- 固定种子随机结构提案基线。
- 训练观测上的绝对 Pearson 相关筛选基线。
- 统一结构指标：Precision、Recall、F1、SHD。
- 干预覆盖、预算利用率、预算违规、提案合法性、提前提交、证据充分性、轨迹有效率、工具错误数。
- 训练/验证/测试 unit_id 互斥且完整覆盖审计；训练记录必须具备全部候选变量和目标。
- 训练数据行只读；候选算法不接收验证/测试记录。
- Oracle 仅作 evaluator-only 诊断，不参与参赛方法排名。
- 对非法预算类型、缺失训练特征、重复 baseline ID、非 tuple 提案和越界真值 fail-closed。

## 公平比较的操作定义

1. 固定 SCM、种子、样本单位和候选变量全集。
2. 运行任何方法前固定 train/validation/test unit_id。
3. 所有方法共享同一训练数据、预算和干预权限。
4. 所有方法输出统一 BaselineProposal；资源计量需由外部执行监控器核验，不能只信任适配器自报的 samples_used/total_cost。
5. 测试集只用于最终评估；禁止测试集调参。
6. Oracle 仅作评估上界。
7. 外部模型登记模型/权重版本、提示词、解码参数、软件版本、硬件、运行成本、随机种子和失败重试策略。
8. 若算法计算复杂度、模型规模或工具能力无法匹配，必须报告资源差异并采用分层比较，不得宣称严格等预算。

## 当前不包含

- 完整 PC/FCI、SCM 结构学习器、Transformer 或 Zhouyi 类象 Agent 的端到端接入。
- 强进程隔离和操作系统级资源计量。
- M55 的统计功效、置信区间、效应量、多重比较校正与校准。
- 真实世界普遍性结论。

## 后续验收

M55 应接入多种 SCM 家族和重复随机种子，使用配对效应量、置信区间、多重比较校正、校准与失败案例分析。M56 再接入古籍来源可追溯的类象知识，并设置知识增强/关闭盲测消融。
