# 类象候选生成：观察、取征、关系发现与证据门禁 v0.1

## 1. 研究定位

M2–M8 已覆盖结构约束、竞争解释、条件干预、主动观测、新象提议和迁移评估，但“类象候选最初如何从观察中产生”仍主要依赖调用方预先提供的结构化输入。本专题补上这一环节的最小可执行基线。

这里的“生成”严格指：对已经结构化、带证据引用的观察记录进行确定性比较，提出待审查的对应候选。它不表示系统已经能从任意古文、图像或现实感知中自动抽取可靠特征。

## 2. 理论依据与解释边界

### 《周易·系辞上传》

“引而伸之，触类而长之”可作为从已知关系触发进一步扩展的研究入口。此语不能直接翻译成现代机器学习算法，也不能证明任意相似对象都可迁移。

### 《墨子·小取》

“以类取，以类予”强调取舍与推展需有类的根据；同篇又提醒“物有以同而不率遂同”，并区分“其然也同”与“所以然不必同”。候选生成必须先报告“同在何处”，不能直接给出共同本质或因果结论。

### 《荀子·正名》

关于天官、征知、同异、共名/别名的讨论，提示观察通道、对象锚点、属性特征和名称层级不可混为一谈。特征相同不能证明对象同一；名称相同也不能代替对象与语境证据。

## 3. 候选生成流程

观察记录 → 特征/关系取征 → 精确匹配 → 候选登记 → 范围审查 → 反例检索 → 独立验证 → 人工审查。

当前原型只实现最小版本：

1. 输入观察记录，保留领域、特征、模态、关系角色、来源引用。
2. 对完全相同的 (dimension, value, modality) 特征签名进行匹配。
3. 对完全相同的 (predicate, subject_role, object_role) 关系签名进行匹配。
4. 仅以直接观察、文本见证或明确标记的观察报告作为候选证据；纯模型输出和纯推论不能作为独立候选根据。
5. 输出 PROPOSED 或 ABSTAIN，同时保留证据引用、跨领域提示和未共享特征维度。

当前采用精确匹配而非 embedding 近似聚类，目的是先建立可审计基线，避免相似度阈值把不同关系、模态或对象误合并。

## 4. 必须区分的五层

| 层次 | 可记录的候选 | 不得自动推出 |
|---|---|---|
| 感知/文本特征 | 同维度、同取值、同模态 | 对象同一、同类 |
| 关系结构 | 谓词与角色结构相同 | 关系机制相同 |
| 功能/用途 | 需要独立的任务与结果证据 | 仅凭结构相似认定功能相同 |
| 因果机制 | 需要独立因果识别证据 | 同果、共现或相似即同因 |
| 规范/象征 | 需要记录文本语境与规范前提 | 把象征对应当作经验因果 |

原型当前只产生前两层的候选，不自动生成“功能相同”或“因果相同”的结论。

## 5. 证据等级与防循环

DIRECT_OBSERVATION、TEXTUAL_ATTESTATION、REPORTED_OBSERVATION 可以支持待审查的对应候选，但它们并非同一种证据，必须保留原始类型。INFERENCE 和 MODEL_OUTPUT 不能反过来充当其自身结论的独立观察根据。

即使候选通过结构化门槛，也只表示引用链完整且存在精确对应；程序不判断文本真伪、观察准确性、来源独立性或跨域规律真实性。多份转录、转载或同源报告仍需另行做来源谱系去重。

## 6. 原型与验收

- 原型：prototype/yixiang_candidate_generation.py
- 测试：tests/test_yixiang_candidate_generation.py
- 候选 ID 按观察 ID 排序，保证输入顺序不影响结果。
- 无精确匹配不生成候选；只有推论/模型输出支持的匹配保留为 ABSTAIN 审计记录。
- 每条候选显式列出不可越级推断：对象身份、类属、功能等价、因果等价、全称推广。
- 本模块不取代 M6：本模块从观察对生成初始对应候选；M6 从已标注残差提出可能的新结构候选。

## 7. 下一阶段研究问题

1. 近似匹配如何显式声明容差、量纲、语义对齐和错误合并风险？
2. 如何从经传、诸子材料中分离文本明言、注家解释、现代研究解释和项目结构化假设？
3. 如何在多个候选之间竞争，而不是把高频共现误当成正确类象？
4. 如何将 M5 主动观测接入候选生成，使下一项观察最大程度地区分竞争结构？
5. 如何在作品、版本、主体和来源谱系隔离的留出集上评估候选精确率、误合并率、拒绝率与人工审查成本？
