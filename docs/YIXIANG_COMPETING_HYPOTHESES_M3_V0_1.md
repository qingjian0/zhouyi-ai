# M3 竞争类象与证据裁决原型 v0.1

## 1. 目标

M3 将“多个候选解释并存、证据分层、适用条件、反例与未决”变成显式数据结构。它是可审计的规则基线，不是概率校准器，也不宣称实现了自动发现古义或自主认知。

## 2. 证据层必须分离

每条证据记录包含：

- evidence_id：稳定标识；
- dimension：证据针对的结构维度，如形态、功能、关系、时序或条件；
- stance：支持、反对、中性；
- strength：记录者给出的 0–1 强度，不能解释为概率；
- layer：原典、现实观察、历代注疏、现代研究、模型推论；
- source_ref：可回溯出处；
- note：补充说明。

五种证据层不互相替代。模型推论不得冒充原典证据；注疏不得覆盖原典；现代研究可以校勘原典，但须保留其论证和引用链。

## 3. 候选类象与适用条件

每个候选包含：

- mapping_claim：源域—目标域的明确映射主张；
- applicable_conditions：声明适用范围；
- required_conditions：该映射成立所需的条件；
- satisfied_conditions：已有证据确认满足的必要条件；
- violated_conditions：已有证据确认违反的必要条件；
- evidence：支持、反对和中性证据集合。

未观察/未核验的条件属于 missing，不可当作 false；明确违反必要条件才触发 rejected。

## 4. 多维证据剖面

原型按 dimension 分别累计支持、反对和中性强度，并按证据层统计支持记录数。不同维度不合并成单一总分，避免把“文本直接记载”“现代观察”“模型猜测”加权混成一个伪概率。

注意：strength 是输入的审查标记，不是由数据自动校准所得。若要跨标注者比较，后续必须先制定标注手册、双人标注和一致性评估。

## 5. 状态与未决规则

- rejected：至少一个必要条件被明确违反；
- underdetermined：没有支持证据，或仍有必要条件未知；
- contested：同时存在支持与反对证据；
- viable：当前没有已知必要条件违反、反对证据或未满足条件，且至少有一条支持证据。

arbitrate 返回全部候选，不以分数强行选唯一答案。只要存在多个 viable、contested 或 underdetermined 候选，整体结果就是 unresolved。即使只有一个 viable，也只表示“当前证据与条件下唯一暂时可行”，不表示真理已被证明。

## 6. 测试覆盖

`tests/test_yixiang_competing_hypotheses.py` 覆盖：

1. 多个可行候选并存时保持未决；
2. 缺失条件不等于条件失败；
3. 明确违反必要条件时拒绝；
4. 反证保留并将候选标记 contested；
5. 原典、注疏、模型推论证据层隔离；
6. 重复 ID 校验；
7. 条件状态互斥校验。

## 7. 文献研究与古义审查

优先顺序建议：

1. 《周易》经文、彖象、系辞、说卦：分层记录经、传，不把传文直接视作经文。
2. 《墨子·小取》：考察“类”“故”“譬”“侔”等推类论证及其适用范围；具体训读须据可靠校本核验。
3. 《荀子·正名》《解蔽》《非相》：名实、分类、偏蔽与形貌判断边界。
4. 《庄子·齐物论》：视角、彼此、是非与分类界限；不得简单等同现代相对主义。
5. 《论衡》相关篇章：作为对灾异、感应等推论的历史批判材料。
6. 《吕氏春秋》《淮南子》相关篇章：比较时序、分类和同类论证，注意篇章与时代层次。

每个文本主张必须补齐底本、卷篇定位、原文上下文、异文、注家、现代校勘意见和反方解释后，才能进入“已核验语料”。仅有书目名称或二手摘要时，状态只能是 candidate。

## 8. 后续实验

- 歧义任务：同一证据支持多个映射，测量过早裁决率；
- 缺失任务：随机隐藏必要条件，测量未知误判率；
- 反证任务：逐步注入反例，测量 contested/rejected 状态转换；
- 来源层任务：将现代推论伪装成原典层，验证 schema/审查流程能否发现；
- 标注一致性：多标注者对 stance、dimension、strength 的一致性；
- 跨域 OOD：训练领域与测试领域按来源作品分组隔离。

对照单标签分类、Top-k 分类、集合预测和选择性预测。报告候选覆盖率、错误过早裁决率、拒绝质量、条件识别准确率、证据层混淆率和标注成本。未达到预注册标准时保留负结果，不把规则基线包装成模型突破。
