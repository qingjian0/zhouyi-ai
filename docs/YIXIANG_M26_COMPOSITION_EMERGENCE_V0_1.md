# M26：类象组合语义、复合结构与新类涌现审计 v0.1

## 1. 定位：补足 M9/M10，而不是重复实现

M9 已处理多视角候选的显式桥接组合；M10 已规定预注册实验臂、成员消融、去桥接对照和替代解释控制。M26 不再增加一套候选生成器或涌现实验框架，而是补上组合对象本身的语义契约：

- 组合由哪些元素构成，元素是否有序；
- 组合操作究竟是并列、次序、包含、交互、对立还是转化；
- 操作规则、范围、情境与证据是否一致；
- 组合关系是否可拆解，改变顺序或情境时哪些声明必须重审；
- 新类别主张是否具有整体层证据，是否超出成员属性的简单并集。

M26 的原型只做结构审计。它不从数据自动发现组合，不宣称证明涌现，也不替代 M9 的独立桥接或 M10 的实验验证。

## 2. 古典材料：可支持什么，不可支持什么

### 2.1 《周易·系辞下》：观象、取象与组合变化的程序背景

《系辞下》以“仰则观象于天，俯则观法于地……近取诸身，远取诸物”说明取象的观察范围，并以“以类万物之情”表述类化目标。它可以作为多来源、多尺度取象的思想背景，但不能据此断言古人已经提出现代组合代数或涌现理论。

### 2.2 《周易·系辞上传》：参伍、错综与成象

传文说“参伍以变，错综其数，通其变，遂成天地之文；极其数，遂定天下之象”。此段紧接蓍筮变数与成卦语境。至少应保留两层：
1. 传文本身把变、数、文、象联系在一个程序链中；
2. 将其抽象为现代系统的排列、交互、状态组合或计算算子，是工程类比，不是原文训诂结论。

尤其“参伍”“错综”的具体解释在后世注疏中并不完全一致。不得把某一宋儒解释直接当成先秦原义。

### 2.3 《墨子·小取》：同结果不等于同所以然

“其然也同，其所以然不必同”构成组合推论的关键限制：两个复合结构即使产生相同结果，也不表示其内部组成、作用方式或形成根据相同。组合验证必须记录机制与条件，不能只比较输出。

### 2.4 《荀子·正名》：同状异所、异状同所

《正名》辨析同状而所在不同、异状而所在相同等情况，并讨论状变与实是否仍为同一对象。对工程设计的启发是：成员身份、可观察属性、组合位置和整体类别必须分开，不能仅凭表面特征或标签拼接决定类别。

### 2.5 《淮南子》相关譬喻与情境变化

《淮南子·说林训》等材料常以物、势、用、处境变化说明推类不能脱离条件。它支持对组合情境进行版本化，不支持把某一具体譬喻无条件推广成普遍规律。

## 3. 组合类型与语义契约

| 类型 | 工程语义 | 必须保留的条件 |
|---|---|---|
| parallel | 并列共存 | 成员身份、共同范围；不暗示交互 |
| ordered | 有序组合 | 明确顺序；交换顺序视为不同组合 |
| containment | 包含/部分—整体 | 包含方向、边界与层级 |
| interaction | 成员间相互作用 | 交互规则及整体层证据 |
| opposition | 对立、制约或张力 | 对立维度、极性与适用条件 |
| transformation | 状态或阶段转化 | 有向转化规则、前后状态与情境 |

这些是现代工程标签，不是古典术语的逐字翻译。一个组合可以同时存在多条关系边，但不能将关系边数量误当成组合有效性。

## 4. 整体属性与新类主张

至少区分四种情况：

1. **属性并集**：整体只拥有成员已有属性的汇总，不足以主张新类。
2. **关系性属性**：性质来自成员之间的关系，但仍可能由既有关系规则充分解释。
3. **交互依赖性质**：去除某个成员、改变顺序或切断交互后，性质发生可复现变化。
4. **候选涌现性质**：整体层表现具有独立测量证据，并且相对于成员单独、属性并集、替代解释和拆解对照仍有剩余解释差异。

第 4 类只能形成候选主张。M26 要求记录：
- 组合 ID 与成员；
- 候选新属性；
- 整体层证据与成员层证据；
- 非可约化论证；
- 相同情境和适用范围；
- 反例引用；
- 明确的理由。

整体证据 ID 与成员证据 ID 不得重叠，但“不重叠”只是一项最低结构约束，不等于统计独立或来源独立。来源谱系仍须由 M14 等机制审查；实验因果与效应仍须由 M10 及真实实验设计验证。

## 5. 顺序、拆解与情境失效

- 对 ordered 组合，交换成员顺序必须产生新的组合版本，不能沿用旧结论。
- 对 interaction 组合，删除成员或交互边后，旧整体性质必须重新验证。
- 对 transformation 关系，边有方向；出现循环不必然错误，但应交人工审查，不可默认为单向线性过程。
- 情境版本变化时，成员、边、组合和涌现主张必须绑定同一情境版本；版本不一致则阻断。
- 拆解或重组后，即使成员相同，也不能默认原组合主张仍有效。

本版记录结构和关键约束，尚未实现不可变事件账本、自动传播失效或真实实验执行；后续应与 M22 的情境修订账本对接。

## 6. 原型与测试

- 原型：`prototype/yixiang_composition_m26.py`
- 专项测试：`tests/test_yixiang_composition_m26.py`

原型定义 SymbolicElement、CompositionNode、CompositionEdge、EmergentCategoryClaim。审计器检查成员、操作、顺序、范围、情境、证据、边端点、转换环和整体层主张。涌现主张即使结构完整也只进入 HUMAN_REVIEW；缺少反例或关键字段则阻断。

专项测试覆盖顺序要求、成员重复/缺失、情境错配、操作规则缺失、边端点、转换环、整体证据与成员证据重叠、非可约化论证、反例缺失和范围错配。

## 7. 可证伪研究设计

后续与 M9/M10/M8 连接时，至少构造以下成对或多臂对照：
1. 成员属性并集 vs 完整组合：判断整体主张是否超出简单汇总。
2. 有序组合 A→B vs B→A：测量顺序敏感性，不能将顺序差异误判为噪声。
3. 完整交互 vs 去除交互边：测试交互规则是否必要。
4. 完整组合 vs 逐一移除成员：识别必要成员与冗余成员。
5. 原情境 vs 改变主体/任务/位置/时机：评估适用域和情境依赖。
6. 候选新类 vs 最近邻旧类别：检验新标签是否只是重命名。
7. 真实整体测量 vs 模型从成员属性推算：避免模型生成的“整体证据”循环论证。

结果至少报告：组合结构有效率、伪涌现率、顺序翻转敏感性、成员消融敏感性、情境外失效率、人工裁决一致性及 selective risk。不得只报告总准确率。

## 8. 解释边界与下一步

M26 的通过只意味着组合声明满足结构契约。它不证明：
- 古典类象理论已包含现代组合理论；
- 某一组合确有本体论意义上的涌现；
- 整体性质必然不能还原为部分与关系；
- 类象组合优于 Transformer 或其他模型。

下一阶段建议 M27：把 M22 的情境修订、M23 的形成链、M24 的类别边界、M25 的关系权限和 M26 的组合结构连成可追溯的统一声明图，再设计跨模块失效传播测试。
