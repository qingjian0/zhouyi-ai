# E17：自组织认知结构与联合结构发现学习（2026-11-11）

> 状态：[研究设计]。本文件定义研究假设、架构边界和实验协议，不代表 E17 learner 已实现或实验已运行。基于 E02、E13、E16、GPOI、CGL、DCC 与 DCH 研究。

## 0. 核心结论

只学习超边结构不足以形成开放式认知。若节点、测量方式、原语和程序全部由人预先定义，系统最多是在固定概念空间里重组结构。

E17 研究更完整的目标：系统能否从原始观察开始，联合发现：
1. 如何测量（Measurement Operators）；
2. 用什么概念描述（Primitives / Predicates）；
3. 如何组织关系（Relations / Mechanisms）；
4. 如何执行认知过程（Cognitive Programs）。

四个搜索空间必须相互反馈，而不是单向流水线。机制预测失败可能源于关系结构错误，也可能源于测量维度不足；程序失败可能源于策略错误，也可能暴露缺失的原语。

核心假设 H17：在类型约束、证据谱系、独立评估和计算预算控制下，联合学习测量、原语、关系和程序，可能比固定原语空间内的结构搜索具有更好的组合泛化、机制迁移和持续适应能力。该假设必须由 E17 实验检验。

## 1. 与现有研究的关系

- E02：研究高阶关系结构和生命周期。
- E13：结构发现、类象映射、区分性查询和证据更新闭环。
- E16：条件化结构重构、来源谱系、版本和依赖失效。
- GPOI：测量算子与原语发现。
- CGL：可执行组合语法与类型化程序。
- DCH：共享高阶认知结构。
- DCC/CWU：调度候选生成、验证和资源。
- WSG：控制长期记忆和当前激活工作集。

E17 不新建一套平行的图或程序系统。它定义上述模块如何共同学习认知表示本身。

## 2. 四个联合搜索空间

\[
\mathcal S=\mathcal M\times\mathcal P\times\mathcal R\times\mathcal G
\]

- M：Measurement Operator Space，测量算子空间。
- P：Primitive Space，原语/谓词/状态描述空间。
- R：Relational and Mechanism Space，关系和机制空间。
- G：Cognitive Program Space，认知程序空间。

该乘积是概念定义，不允许直接穷举。实际搜索必须按依赖、类型、目标、证据和预算稀疏展开。

### 2.1 M：测量算子空间

输入可包括原始数值序列、事件流、空间数据、文本片段、音频/视觉特征和对象状态。测量算子应有：
- 输入模式和输出模式；
- 适用条件；
- 时间/空间范围；
- 单位和量纲；
- 不变性与边界条件；
- 误差模型和不确定性；
- 计算成本；
- 证据来源与版本。

候选族包括差分、比率、变化率、滞后、周期、突变、趋势、共变、空间距离、方向、排序、条件互信息等。候选族本身可扩展，但新算子必须给出可执行定义和可测试输入输出契约。

不得把“模型产生了一个名字”视为发现了新测量。只有当新算子能从原始数据稳定计算，并在独立数据上提供额外预测/区分价值，才进入候选原语空间。

### 2.2 P：原语空间

原语是由测量值、对象、状态和条件构成的可复用描述单元。应区分：
- 原始可观测量；
- 连续测量值；
- 阈值谓词；
- 相对/比较谓词；
- 时序谓词；
- 对象角色；
- 状态与事件；
- 具有不确定性的软谓词。

每个 PrimitiveCandidate 记录：
- primitive_id、version、definition_program；
- input_measurement_refs；
- output_type、domain_scope；
- preconditions、invariants；
- support_groups、counterexample_groups；
- train/validation/gate metrics；
- complexity、cost、uncertainty；
- parent_refs、supersedes_refs。

允许连续原语和模糊边界，不能把所有现实概念硬压成二元标签。阈值应可学习、可校准、可版本化。

### 2.3 R：关系与机制空间

关系表示多个原语/对象在条件下的结构约束。机制候选必须表达：
- 参与者及其角色；
- 前置状态和环境条件；
- 作用方向、顺序、强度；
- 时间尺度和适用域；
- 可观察结果；
- 可区分的竞争预测；
- 反例和证据谱系。

高阶超边不自动等于因果机制。观测相关只能提出 ASSOCIATION 或 MECHANISM_CANDIDATE；因果主张必须有干预、自然实验或其他明确识别设计。

### 2.4 G：认知程序空间

认知程序是可执行的有限 DSL 程序，不是自由生成并执行任意代码。其操作可以包括：
- SELECT / SKIP / BIND；
- MEASURE / COMPARE；
- COMPOSE / BRANCH / RECURSE；
- PROJECT_VIEW / CHANGE_SCALE；
- GENERATE_HYPOTHESIS；
- DESIGN_DISCRIMINATING_QUERY；
- EVALUATE / UPDATE_EVIDENCE；
- REWRITE_STRUCTURE；
- STOP / ABSTAIN。

程序具有输入输出类型、前置条件、效果、预算和证据引用。涉及外部行动、写记忆或更新模型的操作必须由效果系统和权限策略控制。

## 3. 联合反馈，而非单向流水线

四个空间构成循环依赖：
- 新测量可能拆分旧原语；
- 新原语可能使旧超边失去区分力；
- 关系残差可能要求增加新测量维度；
- 程序执行失败可能暴露缺失的控制流或条件；
- 新机制可能反向要求更精细的时间/空间测量；
- 新证据可能导致原语、关系和程序同时版本化。

因此，候选变化要作为一个结构补丁提交，而不是立即覆盖四层状态。

### 3.1 Failure Localization

当预测或程序执行失败时，不应默认“增加一条边”。按可诊断层级提出竞争解释：
1. Observation failure：输入数据缺失、噪声或 grounding 错误；
2. Measurement failure：测量算子遗漏、单位/时间窗错误；
3. Primitive failure：谓词边界或概念划分不合适；
4. Relation failure：角色、条件、方向或阶数错误；
5. Mechanism failure：作用过程错误或遗漏变量；
6. Program failure：执行顺序、分支、搜索策略或停止条件错误；
7. Distribution shift：数据生成机制变化；
8. Resource failure：预算耗尽导致的部分结果。

使用诊断实验区分这些解释。若证据不足，返回 UNRESOLVED，不强行归因。

### 3.2 Candidate Bundle

每个候选是一个可追溯的变更包：
- candidate_bundle_id；
- proposed_measurement_ops；
- proposed_primitives；
- proposed_relations/mechanisms；
- proposed_programs；
- parent_version_refs；
- predicted_effects；
- required_observations；
- resource_estimate；
- risk_and_scope；
- validation_plan。

候选包可以只修改一层，也可以修改多层，但多层修改必须能拆分归因；不能一次同时引入多种未经验证的新机制并把总收益归给全部组件。

## 4. 搜索与评估算法框架

推荐分阶段、预算驱动的稀疏搜索：

1. Detect：由预测残差、反例、漂移、未知输入、程序失败发现问题。
2. Localize：提出可能出错的层级与依赖子图。
3. Generate：由不同提议器提出候选算子、原语、关系和程序。
4. Type-check：检查输入输出类型、单位、作用域和效果。
5. Deduplicate：对语义等价候选进行规范化去重；仅 embedding 相近不等于语义等价。
6. Cheap-screen：用低成本合成例、静态约束和小样本筛掉明显无效候选。
7. Predict：为候选生成可证伪的预测和区分性观察。
8. Challenge：主动寻找反例或最能区分竞争候选的查询。
9. Independent-gate：在隔离数据上评估。
10. Commit：创建不可变版本，更新 DCH 与依赖图。
11. Monitor：监控泛化、震荡、遗忘、内存和计算成本。

候选选择不应只使用一个分数。记录预测增益、解释覆盖、跨域迁移、证据质量、复杂度、风险和计算成本的 Pareto 前沿。DCC 根据当前目标和预算选择下一项工作。

## 5. 结构学习目标

可使用多目标向量：
\[
Q(c)=(
\Delta L_{predict},
\Delta L_{transfer},
\Delta L_{counterfactual},
\Delta Q_{calibration},
\Delta Q_{coverage},
-Complexity,
-Cost,
-Risk
)
\]

其中不同分量分别报告，不得在没有权重敏感性分析的情况下用一个加权平均隐藏取舍。

MDL 可作为候选压缩与筛选原则：
\[
J(M)=L(M)+L(D\mid M)+\lambda C(M)+\mu R(M)
\]
但不能代替独立验证，也不能仅凭训练压缩率声称发现了真实机制。

## 6. 神经与符号的分工

E17 不要求去掉神经网络，也不允许把全部认知重新交给一个黑箱网络。

建议双空间：
- Latent Proposal Space：连续神经表示，快速提出测量、原语、关系和程序候选；
- Explicit Executable Space：类型化算子、DCH 结构和 CGL 程序，负责执行、验证、审计和持久化。

潜在空间负责召回和提议，不负责最终语义裁决。显式结构负责可执行定义和验证，但不应被限制为最初手工枚举的有限词表。

候选提议器可以通过成功轨迹、失败轨迹、反例和验证结果学习，但 Locked Test 不得进入训练反馈。

## 7. 易象与类象的角色

易象不是强制分类器，而是候选生成先验：
- 象：提出多视角、多尺度测量和投影；
- 数：提出计数、序位、组合、约束和比例算子；
- 理：提出竞争解释、关系约束和机制假设；
- 变：提出状态转移、条件变化和结构重写；
- 类象：提出跨领域角色映射和关系对齐；
- 阴阳：提出对偶、互补、方向反转、促进/抑制候选；
- 四象/八卦：提出状态因子化和多视角投影；
- 六爻：提出位置、阶段、时序条件；
- 五行：提出带方向、强度、条件和时间的交互图候选。

每个先验都必须与随机提议、通用结构先验和无易象提议器比较。先验不得直接决定事实，不得把传统分类映射当作已验证的自然规律。

## 8. 证据和数据隔离

至少使用：
- Train：学习候选提议器和参数；
- Discovery Validation：候选筛选；
- Independent Gate：冻结候选后独立门控；
- Locked Test：最终报告，只能由隔离评估器访问。

按 world/object/environment/mechanism/source_group 分组拆分，禁止仅按样本 ID 随机拆分导致近重复泄漏。

候选搜索会引入多重比较和 winner's curse。应控制候选预算、预注册主要指标、采用独立门控，必要时使用多重检验校正或嵌套验证。

证据独立性以来源谱系为准，不以 evidence_id 数量代替独立样本数。

## 9. E17 实验计划

### E17-A：新测量算子发现
提供原始序列/事件数据，隐藏关键测量维度。比较固定测量集、自动算子组合、开放测量提议器。指标：算子恢复、等价算子去重、预测增益、成本和错误发现率。

### E17-B：原语边界发现
构造连续、模糊、带噪概念，测试系统能否发现阈值、软谓词和上下文条件。指标：边界恢复、校准、OOD 迁移、过度离散化率。

### E17-C：高阶关系和机制发现
包含 pairwise shortcut、真正高阶协同、混杂因素和不同条件下的机制反转。指标：高阶结构 F1、机制预测、混杂误判、反事实区分能力。

### E17-D：程序归纳
提供成功/失败执行轨迹和动态环境。比较模板脚本、固定 DSL 搜索、神经程序提议、联合提议+类型验证。指标：未见目标组合、条件分支正确率、执行成本、失败恢复。

### E17-E：跨层故障定位
随机注入观察、测量、原语、关系、机制、程序和分布层错误。测试是否能定位正确层级并提出最小修复。指标：定位准确率、错误修复率、诊断成本、级联错误率。

### E17-F：持续自组织
分阶段改变数据生成机制，允许系统新增、拆分、休眠和替换结构。指标：适应速度、旧域遗忘、结构震荡、记忆增长、重构收益。

### E17-G：易象先验消融
对照无先验、随机先验、通用结构先验、易象先验；匹配候选数量、参数量、数据和计算预算。

## 10. 对照组

1. Fixed primitives + fixed relations；
2. Learned primitive combinations；
3. Dynamic hypergraph only；
4. Open-set primitive discovery only；
5. Program induction only；
6. Joint M/P/R/G discovery；
7. Joint discovery + DCH/DCC/E13；
8. Joint discovery + 易象先验；
9. Oracle measurement/primitives/relations/programs（上界）。

必须分别报告候选召回率和候选评估质量。搜索器没有生成正确候选时，不能将失败全部归咎于评估器；候选过多也不能以更高预算冒充架构优势。

## 11. 资源约束

禁止直接枚举全部测量算子、原语、关系和程序的组合。采用：
- 目标相关的候选召回；
- 类型、量纲和前置条件剪枝；
- 共享 DAG/超图子结构；
- 等价候选规范化；
- 两阶段廉价筛选与独立验证；
- DCC 多目标预算调度；
- WSG 只激活相关工作集；
- 失败候选摘要化保存，完整轨迹按需回溯。

每个候选包都记录估算成本与实际成本。报告峰值内存、搜索节点数、算子调用数、候选数、验证成本和最坏情况增长。

## 12. 证伪条件

- 开放测量发现不优于固定测量集，或错误发现率不可控；
- 原语发现只是在训练样本上重命名和过拟合；
- 联合搜索的增益完全来自更多候选/更多计算；
- 程序归纳无法在未见条件组合上泛化；
- 故障定位经常修改错误层级；
- 持续自组织引发结构震荡、灾难性遗忘或无界内存增长；
- 易象先验没有独立增益；
- 复杂治理成本超过其带来的推理和适应收益。

失败时应移除无效层级或缩小联合搜索空间，而不是不断增加模块。

## 13. 实施路线

P0：先把 E16 的结构版本、来源谱系、依赖失效和独立门控契约做扎实；补齐 E02-C 数值边界与证据来源模型。

P1：把 GPOI 测量算子候选、E12-A16 原语候选、CGL 程序候选统一成 CandidateBundle；实现失败层级诊断和候选包的类型检查。

P2：建立 E17-A 至 E17-E 的小型合成基准，固定数据生成器、分组拆分和预算。

P3：加入神经提议器，但只做候选召回；与符号搜索器进行预算匹配对照。

P4：加入易象先验和多模态真实数据实验，进行独立消融。

## 14. 当前状态

本文件为研究设计。没有在本分支实现 E17 learner、联合搜索器、失败定位器或实验基准；没有执行 E17 训练或产生性能结果。所有性能优势均为待验证假设。

当前最合理的研发入口是 P0 契约审计和 CandidateBundle 数据模型；不应立即训练大模型。只有测量、原语、关系和程序能够在小型合成任务上形成可复现闭环，才值得扩大模型训练。
