# M7 统一类象认知闭环编排原型 v0.1

## 1. 目标

M7 将已有 M3、M4、M5、M6 透明基线连接成一个有边界的执行流程，验证各阶段的数据契约能否协同工作。M7 是 orchestration baseline，不是端到端学习系统，也不负责从原始古籍、图像或传感器自动抽取证据。

## 2. 流程

1. **M3 竞争类象裁决**：保留 viable、contested、rejected、underdetermined 状态以及各证据层。
2. **M4 条件/反事实核验**：对显式关联到候选解释的条件映射执行基线与假设干预比较。干预结果标记为反事实评估，不伪装成观察。
3. **M5 主动观测选择**：仅当 M3 仍有竞争、争议或未决解释时，才对调用方给出的候选观察排序。输出仍是 prospective_only，不代表观察已执行。
4. **M6 新象提议**：只消费调用方明确提供、已经标注的残差案例；不会从 M3/M4/M5 的结果自动制造残差，也不会自动接受新象。

## 3. 输入契约

- M3 候选 ID 必须唯一；M5 prior 的 hypothesis_id 集合必须与 M3 中非 REJECTED 候选 ID 完全一致，避免已明确排除的解释继续占用先验概率质量；所有先验概率必须有效且归一化。
- M4 每条 ConditionalMapping 必须通过 mapping_to_candidate 显式关联一个 M3 候选；干预只能引用已声明 mapping。
- M5 观察候选、先验及似然分布继续由 M5 模块独立验证。
- M6 残差必须是已标注 ResidualCase，保留 observation_id、domain、typed signature、context 和 evidence_refs。
- M7 的集合输入统一使用 tuple，以避免调用方在执行过程中意外修改数据。

## 4. 不可越过的证据边界

- M5 预测似然不是实际观察；选择观察也不代表执行观察。
- M4 的假设干预不构成真实因果证据。
- M6 候选只保持 PROPOSED，必须独立留出验证和人工审查。
- M6 现在要求 evidence_ref 显式映射到 independence_group；相同底本/转引链即使有多个 URL 也只计一个组。缺少映射时独立性为 UNKNOWN，不满足多来源门槛。程序只能执行分组计数，不能自动认证调用方声明的谱系真实独立，仍需人工核验。
- 不把 M3 的支持证据、M4 的反事实输出、M5 的预测或 M6 的候选互相循环充当独立证据。

## 5. 当前实现

- 编排器：`prototype/yixiang_m7_pipeline.py`
- 测试：`tests/test_yixiang_m7_pipeline.py`
- 结果对象保留 M3 arbitration、M4 assessment、M5 prospective selection、M6 proposals 和 stages_executed。
- 当 M3 已无未决解释时，不强制调用 M5；没有显式残差时，不调用 M6。
- 当前没有自动测量执行器、持久化事件账本、多人审查权限、来源独立性解析器或在线学习器。

## 6. 验收与后续实验

先通过单元测试验证阶段契约和证据边界，再开展：
1. M3-only、M3+M4、M3+M4+M5、完整 M3–M6 的分阶段消融；
2. 观察选择前后真实不确定性变化，而不是只报告预测信息增益；
3. 将来源谱系、作品、版本、领域和主体作为分组单位，做严格独立留出；
4. 注入错误先验、似然错设、选择偏差、条件缺失和伪重复来源，测量错误新象率；
5. 报告观察成本、风险、人工审查成本、独立复现率、误创建率和回滚率。

通过编排测试只说明模块按接口协作，不证明易象理论优于其他认知架构。
