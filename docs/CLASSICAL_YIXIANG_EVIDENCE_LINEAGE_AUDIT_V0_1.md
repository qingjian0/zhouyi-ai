# 古籍证据来源谱系与独立见证审计 v0.1

## 1. 研究问题

多个数字平台、数据库或网页可能复制同一底本、同一整理本或同一现代转录。URL 数量、网站数量和数据库数量不能直接当作独立见证数量。若把镜像转录误计为多份独立证据，语料会发生伪互证，M6 的“多来源”门槛也会被轻易绕过。

本专题建立一个保守的来源谱系审计原型。它只检查调用者显式声明的谱系根，不鉴定版本真伪，不推断古籍文本的历史传承，也不以数字来源的数量代替校勘。

## 2. 核心数据模型

每个见证记录包括：

- witness_ref：项目内唯一引用；
- work_id：作品/篇章身份；
- witness_id：具体见证身份；
- lineage_root_id：声明的共同祖本、整理本或转录来源谱系根；
- kind：写本、金石、刻本、整理本转录、二手引文、数字转录或模型生成；
- derives_from：可选的直接派生引用。

多个网页若来自同一数字转录或同一整理本，必须使用同一 lineage_root_id。只有不同 URL、不同平台或不同文件名，不足以建立不同谱系根。

## 3. 裁决规则

- 不同记录共享同一谱系根：只计为一个声明谱系。
- 只有一个或零个不同谱系根：ABSTAIN。
- 达到调用方设定的不同谱系根数量，且没有模型生成材料参与计数：SUFFICIENT_DECLARED_LINEAGES。
- 模型生成材料永不作为见证；若输入集合混入模型生成材料，整体保持 ABSTAIN，并列出忽略项。
- 作品身份不一致、引用重复、见证 ID 重复或字段畸形：拒绝输入并抛出错误。

SUFFICIENT_DECLARED_LINEAGES 只表示声明的谱系根数量达到门槛，不表示这些谱系在历史上确实独立。真实独立性仍须由版本学、目录学、写本学和影像校勘审查。

## 4. 与既有模块的关系

- 类象语料 Schema：继续保存版本、来源层和文本定位；本模块不替代来源记录。
- M6 新象发现：可在调用方提供证据前先做谱系去重，避免把镜像 URL 当成多条独立证据。
- M8 基准：加入“多 URL 同源”负控，并报告伪独立率。
- 古籍校勘：必须进一步记录底本、版本、卷篇、页/叶、馆藏/影像来源、校勘者及异文处理。

## 5. 研究边界

本模块不做自动谱系推断，不从网页域名推断祖本，不从相同文字自动判定同源，也不从不同文字自动判定独立。谱系根是人工或上游版本学流程给出的显式声明。未知谱系不能被系统自动拆成多个独立来源。

## 6. 后续验证

1. 建立同一底本多平台镜像的人工标注样本。
2. 加入同一整理本的不同数字化版本与不同 OCR 结果。
3. 加入真正不同写本/刻本但存在共同祖本的复杂谱系。
4. 由版本学审阅者评估 lineage_root_id 标注一致性。
5. 在 M6 中接入谱系审计，并比较接入前后的新象候选数量及误报率。

当前 v0.1 只验证显式谱系声明的去重逻辑，不代表已完成真实古籍谱系考证。
