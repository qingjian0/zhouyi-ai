# E02-D benchmark scope clarification (2026-11-11)

## Finding

The existing `prototype/e02_rule_ood.py` evaluation was previously described as "held-out rule-family induction". Inspection of the generator and inference path shows that this name overstated the split:

- The hypothesis class contains all 27 affine rules `(alpha, beta, delta) in {0,1,2}^3`.
- Every one of those 27 rules is evaluated in a separate episode.
- Each episode receives labeled Support examples generated by that same rule.
- One Query pair is withheld from that episode's Support.
- `consistent_rules` enumerates the full known 27-rule class and retains candidates consistent with that episode's Support.

Therefore the benchmark measures **per-rule held-out-query identifiability inside a known finite rule family**. It does not withhold an entire rule family from training, and it does not test cross-family OOD transfer.

## Corrected naming

The experiment task identifiers and CI step are now named:

- `Z3_affine_rule_identifiability_with_heldout_query`
- `Z3_affine_rule_identifiability_support_sweep`
- CI: `E02-D per-rule held-out-query identifiability`

The hypothesis class and calculations are unchanged. This is a reporting/scope correction, not a claim that the existing benchmark has gained a new capability.

## What a real held-out-family experiment requires

A future cross-family evaluation should:

1. Define multiple rule families with explicit, non-overlapping family identities.
2. Partition complete families into train/development/test before generating examples.
3. Ensure no parameterization or family-specific template from the held-out families appears in learner-visible training data.
4. Give the learner only the declared public DSL and permitted examples—not the hidden held-out family ID or target rule.
5. Compare against exact lookup, majority, deterministic random, and an evaluator-only oracle.
6. Report both accuracy and abstention/coverage, plus per-family results and multi-seed uncertainty.
7. Include family descriptors only when they are part of the declared input contract; separately test descriptor collision and misleading descriptors.

Until such a split exists, E02-D should not be cited as evidence of cross-family generalization, semantic analogy, or open-world operator invention.
