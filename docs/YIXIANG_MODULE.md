# 易象状态模块：可检验化设计

状态：研究规格；不代表运行时已实现，也不代表易象先验已经通过实验。

## 1. 研究立场

易象模块是 CPG-EI 的候选结构表征与关系先验来源，不是未经检验的宇宙规律，也不是命理预测模块。

研究目标是检验传统符号体系中的互补、层次、位置、关系制约、状态变化和取象比类，能否为机器学习任务提供有效归纳偏置。

核心约束：
- 不把卦名当作固定语义标签；
- 不把所有历史时期、所有流派揉成单一规则集；
- 不把类比当作因果；
- 不允许无证据类象强制参与推理；
- 所有先验均可关闭、可学习、可比较、可拒绝；
- 只有经过消融与独立测试，才允许主张易象模块具有独立贡献。

详细研究见：
- [第二轮：取象体系、卦爻关系算子与象数史](YIXIANG_METHODS_AND_XIANGSHU_HISTORY_DEEP_RESEARCH_2026-11-11.md)
- [第三轮：易象多维类象、五行历史分层与关系映射原型](YIXIANG_TYPED_ANALOGY_AND_FIVE_PHASES_RESEARCH_2026-11-11.md)

## 2. 表示层次

| 易学概念 | 候选计算抽象 | 可检验任务 |
|---|---|---|
| 阴/阳 | 二元互补状态、对偶变量 | 二元状态辨析、互补约束 |
| 四象 | 两位状态组合 | 层次状态分类 |
| 八卦 | 三位二元编码 + 多维语义视图 | 局部模式识别、视角选择 |
| 六十四卦 | 六位二元编码 + 上下卦关系 | 复合状态与组合泛化 |
| 取象 | 多尺度结构投影 | 多视角表征质量 |
| 类象 | 有类型的跨域关系映射 | 跨领域关系迁移 |
| 爻位 | 有序位置与关系图 | 阶段、位置、响应关系推理 |
| 卦变 | 状态转移算子 | 动态系统预测 |
| 五行 | 带历史来源的多类型关系网络 | 促进/抑制关系学习 |
| 河图洛书 | 带来源版本的数阵/约束结构 | 组合约束、对称性与形式验证 |
| 变通 | 根据新证据更新映射与状态 | 分布变化适应 |

以上是计算抽象候选，不是对传统概念的唯一解释。

## 3. 编码规则

六爻状态属于 \(\{0,1\}^6\)。位序必须在代码和数据集说明中固定，避免上下卦、初爻/上爻顺序混乱。

当前原型编码约定：
- 阳爻编码为 1，阴爻编码为 0；
- 爻数组按自下而上排列；
- 下卦取前三位，上卦取后三位；
- 六位二进制 ID 仅用于程序索引，不等同于文王卦序；
- 动爻索引从 0 开始，索引 0 表示初爻，索引 5 表示上爻。

八卦三位编码表（自下而上）：

| 二进制 | 卦名 |
|---|---|
| 111 | 乾 |
| 110 | 兑 |
| 101 | 离 |
| 100 | 震 |
| 011 | 巽 |
| 010 | 坎 |
| 001 | 艮 |
| 000 | 坤 |

该表只定义稳定编码，不赋予机器学习任务之外的固定预测语义。若需要展示文王卦序、先天次序或其他历史次序，必须另建独立且带来源的映射表。

## 4. 多视角 PatternView

同一对象或卦体可以有多个并存视图：
- trigram_view：三爻局部结构；
- hexagram_view：六爻整体结构；
- line_view：单爻与局部邻接；
- mutual_view：按指定流派规则计算的互体；
- nuclear_or_hidden_view：明确规则下的伏/潜在结构；
- positional_view：中、正、应、承、乘等位置关系；
- transformation_view：动爻及变后结构；
- temporal_view：时序、阶段或过程视图。

每个视图必须记录方法 ID、来源/流派、选取位置、输出结构、适用条件、排除项和证据引用。不同视图可以冲突，不能静默合并。

## 5. Typed Analogy Bridge

类象不能只有“乾→马”或“震→事件”这样的标签。每条映射必须记录：

- source_domain / target_domain；
- source_structure / target_structure；
- source_aspect；
- mapping_type：形态、功能、角色、关系、动态、时空、传统约定或义理解释；
- aligned_relations；
- preserved / omitted / violated relations；
- scope_conditions；
- predicted_consequences；
- counterexamples；
- evidence_refs；
- tradition_or_theory；
- confidence / status。

映射评估至少分开考虑关系对应度、关系系统性、动态一致性、证据支持、边界条件、反例惩罚和额外假设成本。不能把所有映射压缩成一个无类型的向量相似度。

系统必须允许：
- 接受映射；
- 部分接受；
- 保留多个竞争映射；
- 暂缓判断；
- 明确拒绝类比。

## 6. 爻位与关系图

爻位结构不仅是六个数组索引，还包括位置与关系：
- position：1..6，自下而上；
- polarity：阴/阳；
- zone：下卦/上卦；
- center：二、五中位判据；
- parity_fit：阳居奇位、阴居偶位的得正判据；
- correspondence：初四、二五、三上关系；
- adjacency / cheng / cheng乘：邻接、承、乘等关系；
- host_relation：卦主关系，必须按具体方法配置。

得正、得中、相应不是同一指标；得正不自动等于吉，不得正也不自动等于凶。必须结合卦体、卦时、爻辞、其他爻关系和解释体例。

向现代领域迁移时，只能把它们作为阶段、位置、中心、边界、支持、约束、响应等候选结构模板，不得把爻位硬编码为现实中的固定职位。

## 7. 五行与其他传统 profile

五行应是独立可插拔的关系体系，不是所有易象推理的强制基础层。

每个 profile 必须标记：
- tradition_id；
- historical_period；
- element_set；
- generation_edges；
- control_edges；
- abnormal_relation_rules；
- temporal_state_rules；
- correspondence_tables；
- source_refs；
- applicability；
- known_disputes。

应区分先秦经传、出土文献、两汉象数易学/京房体系、宋代图书易学、明清发展和现代民间术数。不得把宋代河图洛书黑白点图或后世纳甲规则直接说成先秦《周易》原始算法。

若某任务没有证据表明五行 profile 能提升效果，应允许它完全不参与。

## 8. 解释竞争与证据约束

对每个任务：
1. 先定义可用视角和规则 profile；
2. 并行生成候选结构和类象映射；
3. 检查关系保持、缺失关系、矛盾和边界；
4. 生成可检验预测与反证条件；
5. 比较竞争解释；
6. 允许保留多解释或拒绝作答；
7. 记录证据、规则来源和选择轨迹。

禁止在看到目标答案后才挑选能够解释它的规则。必须标记答案泄漏和事后合理化风险。

## 9. 对照实验与消融

对照方案：
A. 不使用额外编码；
B. 固定随机 64 类编码；
C. 可学习 64 类嵌入；
D. 六位结构编码；
E. 六位结构编码 + 状态转移先验；
F. 结构映射但不使用易象先验；
G. 结构映射 + 易象多视角；
H. 完整易象 profile + 证据竞争。

消融：
- 去掉易象模块；
- 随机置换卦象 ID；
- 保留二元状态但去掉传统关系先验；
- 仅用五行关系矩阵；
- 仅用卦变状态转移；
- 固定先验 vs 可学习先验；
- 去掉反例检查；
- 去掉多解释竞争。

指标：
- relational_alignment；
- systematicity；
- prediction_precision；
- disconfirmation_recall；
- negative_transfer_rate；
- abstention_quality；
- cross_case_stability；
- post_hoc_rule_selection_rate；
- provenance_completeness；
- latency / memory / FLOPs。

只有完整模块在独立测试集、相同数据和预算下稳定优于基线，才允许主张其具有独立贡献。

现有编码约定见 `prototype/yixiang_encoding.py`。本文件描述的是模块目标和验证纪律，不表示 Typed Analogy Bridge、Position-Relation Graph、五行 profile 或解释竞争器已经实现。
