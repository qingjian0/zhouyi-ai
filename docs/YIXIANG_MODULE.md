# 易象状态模块：可检验化设计

## 1. 研究立场

易象模块在本项目中是结构化状态空间和关系先验的候选来源，不是未经检验的宇宙规律，也不是命理预测模块。研究目的在于测试传统符号体系中“互补、层次、关系制约、状态变化、类象迁移”等抽象，是否能为机器学习任务提供有用归纳偏置。

## 2. 表示层次

| 易学概念 | 计算抽象 | 可检验任务 |
|---|---|---|
| 阴/阳 | 二元互补状态、对偶变量 | 二元状态辨析、互补约束 |
| 四象 | 两位状态组合 | 层次状态分类 |
| 八卦 | 三位二元编码（8 状态） | 局部状态模式识别 |
| 六十四卦 | 六位二元编码（64 状态） | 复合状态与组合泛化 |
| 卦变 | 状态转移算子 | 动态系统预测 |
| 取象比类 | 结构映射/关系保持的类比 | 跨领域关系迁移 |
| 五行 | 多类型带符号关系网络 | 促进/抑制关系学习 |
| 变通 | 根据新证据更新映射 | 分布变化适应 |

## 3. 编码规则

六爻状态 (hin{0,1}^6)。编码的位序必须在代码和数据集说明中固定，避免上下卦、初爻/上爻顺序混乱。建议先用纯二进制状态 ID 作为机器编码，显示层再映射传统卦名。

对照方案：
A. 不使用额外编码；
B. 固定随机 64 类编码；
C. 可学习 64 类嵌入；
D. 六位结构编码；
E. 六位结构编码 + 状态转移先验；
F. 完整五行关系先验。

## 5. 类象与证据约束

类象候选由结构相似度提出：
[
s(a,b)=mathrm{sim}(f(a),f(b))
]
只有在关系结构保持、任务结果验证、反例检查后，才可提升为可用映射。每个类象必须记录：
- 来源域和目标域；
- 对齐的结构/关系；
- 支持证据与反例；
- 置信度与适用范围；
- 最近一次验证结果。

模型必须有拒绝选项：结构相似度高但关系不保持、证据不足或出现反例时，不应强行类比。

## 6. 关键消融

- 去掉易象模块；
- 随机置换卦象 ID；
- 保留二元状态但去掉传统关系先验；
- 仅用五行关系矩阵；
- 仅用卦变状态转移；
- 固定先验 vs 可学习先验。

只有完整模块在预注册指标上稳定优于这些基线，才能主张易象先验提供独立贡献。


## 7. 机器编码约定（原型实现）

原型代码 `prototype/yixiang_encoding.py` 固定如下约定：
- 阳爻编码为 1，阴爻编码为 0；
- 爻数组按自下而上排列；
- 下卦取前三位，上卦取后三位；
- 六位二进制 ID 仅用于程序索引，不等同于文王卦序；
- 动爻索引从 0 开始，索引 0 表示初爻，索引 5 表示上爻。

八卦三位编码表（自下而上）：
| 二进制 | 卦名 |
|---|---|
| 111 | 乾 |
| 110 | 兑 |
| 101 | 离 |
| 100 | 震 |
| 011 | 巽 |

该表只定义稳定编码，不赋予机器学习任务之外的固定预测语义。若将来需要展示文王卦序，必须另建独立的、经过校对的映射表，不能把二进制 ID 误当作文王序号。
