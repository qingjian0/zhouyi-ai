# E10-A：无目标标签的结构化概念形成

状态：原型已提交，等待 CI；仅为有限合成数据上的结构归纳，不代表开放世界概念学习。  
代码：`prototype/e10_structural_concepts.py`  
测试：`tests/test_e10_structural_concepts.py`

## 1. 问题定义

E10-A 检验一个比 E09 更上游的问题：系统能否在没有目标概念名称、类别标签或目标规则表达式的情况下，从对象观测中找出重复出现的属性束与角色条件属性束。

输入仅包括：
- 不透明对象 ID（仅用于追踪支持证据，不参与候选特征）；
- 无序属性集合；
- 可选的角色槽位及其属性集合。

学习器不接收概念标签、潜在类别 ID 或生成器的隐藏结构名称。

## 2. 最小原型

`StructuralConceptLearner` 枚举每条观测中的属性子集，形成候选属性束；对角色槽位分别形成角色条件属性束。候选支持度按不同对象 ID 计数，并由最小支持阈值过滤。候选枚举有最大候选预算，避免无界组合爆炸。

候选不是语义概念真值。它们只是可审计的重复结构假设，后续必须通过区分性测试、跨环境迁移和反例验证。

## 3. 数据与反泄漏设计

合成生成器包含两组重复的三属性结构，以及仅共享部分属性的近似负例。学习器没有得到这两组结构的名称。

测试覆盖：
1. 恢复重复出现的三属性束；
2. 两项相似但不完整的近似负例不应被误当成完整三项结构；
3. 对象 ID 重命名、行顺序变化和角色顺序变化不改变发现的模式及支持度；
4. 重复对象 ID 被拒绝；
5. 候选预算必须生效；
6. 支持度按不同对象计数。

注意：当前合成任务仍由研究者设计了重复模式，因此它只证明原型能从观测中挖掘模式，不能证明系统能自主决定哪些模式在真实世界中有意义。

## 4. 运行

```bash
python -m unittest tests.test_e10_structural_concepts -v
python -m prototype.e10_structural_concepts --json
```

## 5. 当前边界

- 输入属性符号和角色槽位是预先可观察的；尚未解决从原始多模态数据形成属性。
- 只发现频繁结构，不识别因果、功能或语义。
- 目前采用有界枚举，不是高效的通用结构搜索算法。
- 没有证明易象先验带来收益；E10-E 才会比较无先验、随机先验和不同易象先验。
- 没有与梯度模型进行同预算比较。

## 6. 下一阶段验收

E10-B 不应直接把本轮高支持度候选当作真实概念。它需要构造跨域对象重命名、表面属性置换、结构保持映射与结构破坏硬负例，测量有效迁移率、错误类比接受率和拒答质量。若映射只依赖词面重合，则判定失败。
