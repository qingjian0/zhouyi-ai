# 易象概念本体与层次规范 v0.1

## 1. 目的与边界

本文定义 Zhouyi-AI 内部可计算概念的分层边界，避免把经典术语、数据结构、算法变量和现代研究假设混为一谈。它是工程本体草案，不宣称穷尽历代易学，也不把某一注本或流派解释设为唯一标准。

核心约束：

1. **经典对象与现实对象分层**：卦、爻、卦位是易学结构对象；现实世界的实体、事件、属性是观测对象。二者之间的映射必须显式记录，不能直接把现实对象编码成某卦并视为事实。
2. **结构与解释分层**：卦画、阴阳爻值、上下卦、爻位属于可核验结构；卦德、象义、吉凶判断属于带来源的解释。
3. **版本与学派并存**：解释必须携带来源、版本、时代/传承信息及适用范围；冲突解释并列保存。
4. **可计算定义与传统义理分开**：算法采用的操作定义必须标记为本项目定义，不得伪装成经典原义。
5. **不从编码直接推出语义**：二进制索引只用于计算和寻址，不能自动解释为卦序、卦义、吉凶或预测。

## 2. 概念分层

### 2.1 易学结构层

- **爻（line）**：构成卦的基本结构单元。数据层记录阴/阳状态、位置、是否动爻及其来源约定。爻值与爻位是两个不同字段。
- **爻位（line position）**：爻在六爻结构中的位置，通常以初、二、三、四、五、上表达。程序内部可用自下而上的 0–5 索引，但必须显式声明换算。
- **卦（hexagram）**：六个爻按自下而上的次序组成的结构对象。卦画结构不等同于卦名、卦序或卦辞。
- **上下卦（lower/upper trigram）**：六爻结构下三爻与上三爻形成的两个三爻结构。必须保留上下位置，不得无说明地交换。
- **卦变（hexagram transition）**：一个或多个爻状态改变所形成的结构转移。至少保存变前状态、变后状态、动爻位置和采用的规则版本。
- **卦序（sequence system）**：为卦集合指定的排序体系。先天序、后天序、通行文王序及程序二进制索引是不同命名空间，不可共用一个整数值冒充彼此。

### 2.2 象与类的认知层

- **象（image/pattern）**：在特定语境中被观察、选择或组织出来的可表征模式。它既可能来自卦爻结构，也可能来自自然、社会、器物、行为或过程；必须记录观察语境。
- **物象（observed entity/image）**：观测到的对象或现象及其属性、关系、时空条件。物象记录的是证据，不等同于对它的解释。
- **卦象（hexagram image）**：由卦体结构及其上下、爻位、动静等关系形成的易学结构象。结构字段与解释字段分离。
- **爻象（line image）**：爻值、爻位、邻比、承乘应等关系所形成的局部结构信息。任何关系术语的具体操作化都要附上所采用的传统定义或项目定义。
- **类（category/kind）**：用于组织对象或模式的分类概念。类标签是索引，不构成类象成立的证据。
- **象类（image class）**：在指定维度和范围内具有可说明共同结构的一组象。成员资格需要特征/关系依据和反例边界。
- **取象（image selection）**：从复杂观测中选择与当前问题相关的对象、属性、关系或过程。应记录选择依据、遗漏信息及观察者/模型的不确定性。
- **比类（analogical comparison）**：在两个对象域或模式域之间提出可比较的维度和对应关系。比类是提出候选，不等于验证成功。
- **类象（validated analogy）**：经显式映射、关系保持检查、适用条件和证据审查后，在有限范围内成立的对应。类象应允许部分成立、条件成立、失效和撤销。
- **应象（correspondence/manifestation）**：在给定理论或案例框架下，对某种对应关系的观察或解释。必须区分观测到的对应、理论预期和事后解释，不得将时间相关性直接写成因果。
- **变象（transformed image）**：对象、关系或整体模式发生变化后形成的新象。应保存变前/变后、触发条件、变化路径和不变部分。

### 2.3 时位势变层

- **时（time/stage）**：时间点、时间区间、阶段或周期位置；不能只用无单位的序号替代真实时间语义。
- **位（position/context）**：对象在结构、空间、组织或关系网络中的位置。不同理论传统对“位”的解释可能不同，具体模型需声明。
- **势（potential/tendency）**：由当前状态、关系、约束和环境共同表征的趋势或潜在变化方向。势是模型变量或解释性判断时必须标明其证据来源。
- **变（change）**：状态、关系、位置或条件的变化。记录离散变化、连续变化或阶段转换的具体定义。
- **时位势变（time-position-potential-change）**：对时间阶段、结构位置、趋势状态和变化路径的联合描述。它是研究接口，不是已被证明的单一传统术语体系。

### 2.4 体用与关系层

- **体（basis/subject）**与**用（function/application）**：作为一组关系性概念保存，具体解释必须注明来源和语境。不能在全项目中硬编码为固定的“静态实体/动态功能”二分。
- **关系（relation）**：实体或象之间的可类型化连接，必须记录方向、角色、条件、时间有效区间及来源。
- **承、乘、比、应等关系**：作为有来源的易学关系词条建模；各自的传统定义、位置约束与流派差异由概念条目管理，计算模块只能调用明确版本的操作定义。

## 3. 类象计算记录的最低结构

每条类象记录至少包含：稳定标识、记录版本、审核状态；源域/目标域及其实体、事件和观测快照；显式实体映射及映射类型；一个或多个类象维度；被保持、被改变或不保持的关系；适用条件、有效范围、时间边界和环境约束；支持证据、反例、未决冲突及其出处；解释来源、经典/注本版本、版权许可和标注者；置信度、校准方法及其含义。

**结构相似 ≠ 语义等价 ≠ 因果等价。** 迁移模块必须声明它迁移的是哪些关系或约束，并在目标域重新验证。

## 4. 易象状态编码约定

当前原型 prototype/yixiang_encoding.py 采用以下纯计算约定：

- 0 = 阴，1 = 阳；
- 三爻和六爻数组均按自下而上排列；
- 六爻数组索引 0..5 对应初爻至上爻；
- binary_id 是将第 i 爻放在第 i 个二进制位得到的 0–63 计算索引；
- 下卦取前三爻，上卦取后三爻；
- binary_id 不是先天序、后天序或文王卦序；
- 动爻索引必须唯一，重复翻转同一爻不允许；
- transition_hexagram 只计算结构变化，不自动生成卦辞、爻辞或吉凶结论。

此约定只服务于当前代码接口。未来如需支持其他编码或卦序，应新增命名空间和转换表，不得改变旧字段含义。

## 5. 数据来源与校勘

经典原文、传文、注疏、现代研究和模型生成内容必须分开标识。建议来源类别：

- classical_text：经、传原文；
- historical_commentary：历史注疏；
- modern_scholarship：现代学术研究；
- field_observation：现实观测/案例；
- research_hypothesis：研究假设；
- synthetic_fixture：合成测试样本；
- model_generated：模型生成内容，默认不得作为独立证据。

每条引文保存书名、篇章、版本、整理者/出版信息、页码或段落定位、原文/转录状态和许可。现代整理本、译注和数据库可能受版权保护；只记录必要元数据与合规短引，不批量复制受保护注释。

异文、训诂分歧、卦序差异和流派差异应以并列观点或争议记录表示。没有可靠来源时标记 unverified，不补造出处。

## 6. 研究与实现门禁

1. 每个概念条目区分传统来源、现代解释、项目操作定义。
2. 每个编码约定有正反例、边界测试和版本号。
3. 每种关系规则有适用条件、反例和撤销策略。
4. 每种类象模型有独立 OOD 测试，且按来源/模板分组防止数据泄漏。
5. 经典知识正确性与跨域迁移能力分别评估，不能互相替代。
6. 传统解释差异不应被压缩成单一标签；模型需要输出来源或保留不确定性。
7. 研究假设只有经过独立数据和对照实验验证后，才能升级为经验结论。

## 7. 尚未解决的研究问题

- 不同易学文献中“象”“类”“应”“体用”等术语的语义范围如何做版本化而不失真？
- 类象的“关系保持”在何种情形允许角色置换、尺度变换或多对多映射？
- 象的抽取如何区分观察者选择偏差与对象自身稳定结构？
- 时位势变如何避免把事后叙事误当作前瞻预测？
- 经典象数结构如何与现实案例建立可证伪映射，而不只是事后套合？
- 如何构造由独立专家标注、带争议标签和反例的评估集？

这些问题在得到可靠来源与实验支持前保持开放。
