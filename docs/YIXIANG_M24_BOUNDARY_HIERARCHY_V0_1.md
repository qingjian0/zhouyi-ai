# M24：多重归属、类别层级与动态边界 v0.1

## 1. 研究目标

M23 审计观象—取象—立类的来源链。M24 研究类别形成后的结构：一个对象可否多重归属、类别之间如何形成层级、边界案例如何保留，以及类别何时需要修订、拆分或废弃。

M24 不把类别视为天然互斥的固定集合，也不把所有相似性压缩成一个分数。类别归属必须绑定分类轴、判准、情境版本、特征和证据。

## 2. 原典对读与命题边界

### 2.1 《说卦传》：多轴取象，不等于单一分类树

《说卦传》对八卦分别列举自然、动物、身体、家族等象例。研究上可提出“多轴归属”的假设：同一卦象在不同关系域中可以有不同对应。但这些条目不能直接解释为现代本体工程中的严格类型系统，也不能未经版本校勘就假定所有条目属于同一时代、同一层次。

### 2.2 《荀子·正名》：同异、分辨与约定

《正名》强调辨同异、制名指实以及约定俗成。对 M24 的启发是：分类需要明确判准，名称约定不能代替证据；分类粒度也应作为显式决策，而不是隐藏在标签名称中。

### 2.3 《墨子·小取》：结果相同不保证所以然相同

“其然也同，其所以然不必同”要求系统区分表面同类与形成机制同类。两个对象可以在某一分类轴上同类，却在机制轴上不同；因此类别关系必须带轴，不可把局部相似推成全局同一。

### 2.4 《庄子·齐物论》：视角相关，但不取消证据约束

分类依赖观察立场、比较范围和语言区分。工程上允许保留竞争分类，但每个分类仍需独立判准、证据和适用域。视角差异不意味着所有判断等价。

### 2.5 《淮南子·说林训》：同物异势，边界随条件改变

对象在不同姿态、位置、用途和情境中可能呈现不同效用。M24 因而把 context_id 与 context_version 纳入归属记录：情境变化产生新判断，不覆盖旧判断；旧记录仍可追溯。

## 3. M24 的概念模型

- **CategoryDefinition**：类别名称、分类轴、判准、父类、生命周期和后继类别。
- **CategoryMembership**：对象、类别、情境版本、归属状态、特征引用、证据引用和理由。
- **BoundaryCase**：纳入、排除或未决的边界案例；保留判准、证据与理由。
- **Multi-membership**：同一对象在同一情境下可以同时归入多个类别；系统只报告多重归属，不推断这些类别彼此等价。
- **Hierarchy**：父子关系允许多父节点，但必须拒绝循环和悬空父类引用。
- **Lifecycle**：类别可处于 provisional、active、deprecated；废弃类别必须指向至少一个后继类别，且不得继续产生新的有效归属。

## 4. 工程实现边界

`prototype/yixiang_boundary.py` 只审计声明结构和证据引用：
- 不自动发现类别；
- 不自动决定成员资格；
- 不自动合并或拆分类别；
- 不从多重归属推断因果或本体同一；
- 不把未决边界强制转为纳入/排除；
- 不证明传统类象理论真值，也不证明优于 Transformer。

## 5. 测试覆盖

专项测试覆盖多重归属、层级合法性、父类缺失、层级循环、判准缺失、成员证据缺失、特征引用、情境隔离、未决归属、排除案例保留、类别废弃与后继类别、重复 ID、未知类别和无效情境版本。

## 6. 后续可证伪研究

1. 在同一对象多轴分类任务中，比较单标签、独立多标签和带轴多标签方案。
2. 在情境变化任务中，比较覆盖旧判断与版本化判断对历史一致性的影响。
3. 对边界样本比较强制二分类、拒绝/未决和多解释保留的错误类型。
4. 用机制不同但表象相似的反例，检验系统是否把结果相同误判为原因相同。
5. 采用独立人工标注、双人一致性和盲测留出集；报告各分类轴指标，不只报告总体准确率。
