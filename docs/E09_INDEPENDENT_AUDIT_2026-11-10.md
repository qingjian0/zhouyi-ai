## 1. 总结判断

E09 已从研究协议推进到一套可读的符号学习原型：有限 DSL 候选搜索、反例排除、追加式证据账本、冲突隔离、环境条件规则和少样本新环境适应均已有实现。

但目前没有足够证据证明 E09 的正式实验通过，更不能证明开放规则语言发现或通用自主学习。代码本身也暴露出预算统计、统计汇总和实验对照公平性问题。建议先做审计修正，再启动更大规模实验。

## 2. 代码级发现

### F-01（高）：E09-B 的候选预算低估实际计算量

`CounterexampleRuleLearner.fit` 将 `pattern_count × label_count` 作为候选评估预算；但每个候选模式还会遍历正例和反例样本，执行逐样本匹配。当前报告中的 `candidate_patterns_evaluated` 实际是候选假设数，不是完整匹配操作数。

建议拆分报告：
- `candidate_hypotheses_generated`
- `candidate_label_pairs`
- `example_match_checks`
- `counterexample_checks`
- wall-clock time / peak memory

硬预算应同时约束候选数和匹配操作数，避免把算法复杂度低估。

### F-02（高）：E09-C 的 selective accuracy 汇总分母不正确

`run_sweep` 使用 `r["selective_accuracy"] or 0.0`，再除以全部 seeds。零覆盖率时 selective accuracy 是未定义值，不应自动按 0 计入均值。

建议只对定义明确的 seed 求均值，同时报告：
- 有定义的 seed 数；
- 无预测 / 零覆盖 seed 数；
- selective accuracy 均值与区间；
- coverage 与 overall correct rate。

### F-03（高）：E09-D2 是联合数据重新拟合，不是增量持续学习

当前 `adapted = _fit(initial_train + novel_support)` 会重新从头拟合全部数据。它没有把初始模型状态作为更新起点，也没有检验旧结构的保留、修改或遗忘过程。

因此当前实验可以称为“新环境少样本监督重拟合”，不能称为已验证的持续学习或自主适应。

建议至少比较：
1. 从头联合重训（当前基线）；
2. 在旧模型上增量更新；
3. 增量更新 + 旧环境回放；
4. 冻结旧规则，仅新增环境条件规则；
5. 只用新环境支持样本重训（遗忘压力对照）。

记录每一步结构差异、旧环境性能变化、适应样本数和计算成本。

### F-04（中高）：E09-D1 的 contextual / context-blind 搜索预算不匹配

Contextual learner 搜索四变量 DSL，context-blind learner 搜索三变量 DSL；候选空间和匹配成本不同。当前实验可用于展示“提供环境字段后可表达条件规则”，但不能将两者性能差异直接归因于环境信息本身。

建议报告两臂的候选数、匹配次数和运行成本，并增加预算匹配的 context-aware / context-blind 基线；同时保留一个无条件关系控制任务。

### F-05（中）：E09-B 的规则支持计数语义不清

贪心覆盖每次选择 clause 时将 `support_count=len(new)`，记录的是本轮新覆盖的正例数，而不是该 clause 匹配的全部正例数。字段名称容易被误解为规则总支持度。

建议分别记录 `total_positive_coverage` 与 `newly_covered_positive_count`，并避免把贪心分配数当作统计独立支持。

### F-06（中）：E09-C 单次观测无法识别独立标签噪声

E09-C 每个基础输入只产生一次训练标签。标签翻转会表现为规则反例，但系统无法仅凭一次观察知道它是噪声、概念例外还是目标规则本身。

建议增加同一输入的重复独立观测、来源可信度分层和可控噪声率，并分别测试：
- 独立随机标签翻转；
- 单来源系统性错误；
- 多来源相关错误；
- 输入缺失和标签冲突。

source_id 是调用方声明的字符串，不是身份认证；不能把不同 source_id 当作真实独立主体的证明。

### F-07（中）：E09-D0 仍是人工提案桥接，不是自主超边发现

桥接函数由调用方提供成员、角色、关系类型和 validation_gain。它只把账本证据整理成 E02-C 的 EdgeProposal，不能证明系统自己发现了节点、成员或关系。

未来端到端实验必须将候选生成器与桥接接口分开审计，并确保 validation_gain 来自独立保留集。

## 3. 实验设计层面的缺口

1. E09-B 的规则语言、变量域和离散取值预先给定；当前结果只能支持“在有限 DSL 内归纳规则”。
2. E09-C 的测试样本来自同一有限规则族，不是规则族 OOD。
3. E09-D1 的环境字段直接提供给学习器，不测试环境概念的自主发现。
4. E09-D2 的 novel context 虽在初始训练中隐藏，但规则仍来自预定义合成规则族。
5. 当前协议中的 5 seeds 只能作为初步回归；正式结论应增加 seed 数、报告逐 seed 结果和置信区间。
6. 必须与精确查表、最近样本、有限假设枚举、固定规则、梯度学习器及静态结构基线比较；同时匹配样本预算、候选评估预算和总计算成本。

## 4. 下一轮建议顺序

### P0：修正度量与预算

- 修复 F-01、F-02、F-05。
- 为所有实验输出机器可读 JSON、逐 seed 明细和运行配置。
- 增加预算边界测试，确保超预算时 fail closed。

### P1：让 E09-D2 真正检验增量适应

- 增加模型状态更新接口，而不只是重新 fit 全量数据。
- 对比增量更新、回放、冻结旧结构和联合重训。
- 报告新环境收益、旧环境遗忘、结构改动和单位样本成本。

### P2：增强 E09-C 证据质量实验

- 增加重复观测与多来源相关性。
- 把标签噪声、概念变化、来源故障分开生成。
- 测量误删真规则、保留假规则和拒答校准。

### P3：开放规则语言测试

- 将训练/测试按规则族隔离，而不是只按输入组合隔离。
- 引入组合 DSL 外规则作为 OOD 负控。
- 允许系统提出候选新原语，但由独立验证器审查。
- 对比“研究者预设 DSL”与“学习器提出 DSL”的结果。
