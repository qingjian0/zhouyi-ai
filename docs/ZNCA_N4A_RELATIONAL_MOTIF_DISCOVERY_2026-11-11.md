# ZNCA N4-A：有界关系类象发现

日期：2026-11-11  
状态：研究原型；Draft PR；基于 N3-D；未合并 main。

## 研究问题

N3-A～N3-D 建立了受预算约束的状态更新、假设隔离、事件持久化与反事实分支。下一阶段必须从“管理认知状态”转向“发现可复用的关系结构”。

N4-A 的问题是：不同领域中，是否反复出现具有相同抽象角色与关系拓扑的局部结构？如果出现，这种结构是否对某类结果具有超出基线的预测价值？

## 设计：不是八卦标签分类器

类象在本原型中被操作化为**关系结构同构候选**：

- 节点表面类型：记录领域对象是什么，仅保留来源，不参与跨领域匹配。
- 抽象角色特征：描述节点在关系结构中承担的功能，由数据标注/上游表示提供。
- 关系族：描述边的抽象作用，由数据标注/上游表示提供。
- 结构签名：对有向关系图做节点 ID 不变的规范化编码。
- 作用域 scope：限制在哪类问题或情境中比较，避免跨任务误合并。

例如，不同领域的“热源—传递介质—受影响对象”与“信息源—传播渠道—接收对象”，如果抽象角色和关系族被编码为一致结构，系统可以提出一个跨域结构类象候选。该候选只是待检验的映射，不意味着两个领域的实体或因果规律相同。

## 计算流程

1. 输入带有明确 train/validation 分区的关系案例。
2. 枚举每个案例中大小不超过 max_nodes 的连通子图。
3. 通过角色特征、关系族和有向拓扑构造节点 ID 不变的规范签名。
4. 每个案例对同一签名最多计一次，避免重复子图膨胀支持数。
5. 分别累计训练正例、训练反例、验证正例、验证反例。
6. 训练支持达到门槛后，计算验证精确率与验证基线率差值（validation lift）。
7. 只有验证正例数与 lift 达标的结构才输出候选。
8. 输出支持证据、反例、跨域案例和每个实例的角色节点映射，交由 N3-D 分支继续比较。

## 复杂度与预算

对每个案例，枚举节点子集的组合数上界为：

sum(C(n, k), k=2..min(max_nodes,n))

每个子集规范化需要最多 max_nodes! 次角色顺序比较。通过 max_nodes、max_subsets_per_case 和 max_candidates 三个预算显式限制最坏开销。预算耗尽会在结果中报告，并丢弃该案例的全部部分枚举结果，不得把部分枚举伪装成完整发现。

## 证据纪律

- 训练集用于提出结构候选；验证集只用于筛选，不回流训练支持数。
- 同一个案例中的重复子图不重复计票。
- 负例保留为 counterexample，不允许只展示正例。
- scope 隔离不同任务上下文。
- role_features 和 relation_family 当前由输入数据提供；N4-A 不会从原始文本自动理解或学习它们。
- 表面实体名称不参与跨域匹配；这降低了词面依赖，但也使抽象角色标注质量成为关键风险。
- 对称结构可能存在多个同样合法的角色对齐；实例会显式标记 mapping_ambiguous，不能将任意选出的一个排列当成唯一语义映射。
- 当前 validation lift 是有限样本的描述统计，不是显著性检验或因果效应。
- 候选不自动写入 canonical state，也不自动晋升为知识。

## 当前能力边界

N4-A 是有界关系子图枚举与证据门控原型，不是神经网络，不是完整类象学习算法，也不是 Transformer 替代品。它还没有解决：
- 从原始语言/感知数据学习抽象角色；
- 关系族的自动归纳与动态重命名；
- 图结构的概率不确定性和部分观测；
- 大图上的增量 motif 索引；
- 自动反例生成与干预式因果验证；
- 与 N3-D 分支晋升流程的运行时集成。

## 下一轮研究

1. 角色特征从人工标签推进到可学习的软角色分布。
2. 用角色映射不确定度处理对称图中的多种合法对齐。
3. 增加关系方向反转、缺失边、跨步跳跃和高阶超边的类象变换。
4. 建立合成可控任务和真实跨领域任务，比较 pairwise、motif、hypergraph 和 NAR iterative refinement 基线。
5. 测量 CPU、峰值 RSS、枚举预算耗尽率和增量更新成本。
