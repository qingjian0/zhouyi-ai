# 古典“类”四种论证用途与行动结果账本 v0.1

## 研究结论

古典文献中的“类”不能被统一压缩成相似度或单一类比算子。结合《墨子·小取》《荀子·正名》《淮南子·说林训》《吕氏春秋·别类》《吕氏春秋·安死》及《论衡·感类篇》，当前项目至少需要分开记录四种用途：

1. **类属/属性相似（taxonomic similarity）**：对象是否共享属性、名类或可辨识特征。
2. **论证性推类（argumentative analogy）**：一个案例是否为另一个命题提供理由；需明确共享根据、关键差异和推论范围。
3. **行动—结果关系（action-outcome relation）**：主体意图、行动方法、作用条件和实际结果之间如何关联。
4. **实践效用（practical utility）**：某种做法是否在明确目标、评价标准和时间跨度下真正有用。

四者可在同一段古文中同时出现，但不能互相替代。比如“得鱼一也”首先支持结果目标相同，不足以证明捕捞机制相同；高阳应造屋故事则提醒局部推理链成立并不保证长期整体结果良好；《安死》的“邻类”可引导研究行动方法与后果，但古代文本提出的因果主张仍需作为文本主张保存，不能自动升级为现代因果事实。

## 证据层级

- 原典陈述：记录古人提出了什么主张。
- 注疏解释：记录后世如何解释原典。
- 现代研究：记录学术解释及其论证。
- 观察：记录可追溯的实际观测。
- 干预/识别证据：记录设计、比较组、假设和结果，仍须独立审查。
- 模型输出：只能作为待检验候选，不能为自身提供证据认证。

## 工程模型

新增 `prototype/yixiang_lei_claims.py` 与测试，提供四种 claim kind 和保守门禁：

- 缺少共享根据：拒绝（REFUSE）。
- 缺少适用条件或来源：暂缓（ABSTAIN）。
- 行动—结果记录必须分开填写意图、行动方法、作用条件和观测结果。
- 即使行动—结果字段齐全，也不能仅凭记录完整就宣布因果成立。
- 实践效用需要评价标准、即时结果和延迟结果；缺少延迟结果时不得判为效用已确认。
- 模型生成证据不得认证模型自己的类象判断。

`SCOPE_RECORDED` 仅表示记录字段达到当前门槛，不代表结论为真，不代表因果关系成立。

## 核心测试场景

| 文献启发 | 易错推断 | 正确门禁 |
|---|---|---|
| 《淮南子·说林训》多种渔法得鱼 | 结果相同 ⇒ 机制相同 | 分离目标/结果与过程 |
| 《淮南子·说林训》同物异用 | 对象相同 ⇒ 用途相同 | 主体与任务条件必须显式 |
| 《吕氏春秋·安死》邻类 | 动机良善 ⇒ 行动有效 | 意图、方法、条件、结果分栏 |
| 《吕氏春秋·别类》高阳应造屋 | 局部趋势 ⇒ 长期整体成功 | 增加系统交互与延迟结果 |
| 《论衡·感类篇》 | 时间相继 ⇒ 天人因果 | 区分文本主张、相关与因果识别 |

## 尚未解决的问题

1. 逐条核对《安死》《别类》《说林训》各版本见证与异文，当前数字转录候选仍未完成影印校勘。
2. 为“实践效用”增加可比较的损失函数与多目标冲突记录，避免把效用简化为单一结果。
3. 增加跨时间阶段的结果轨迹，而非只存一个“即时/延迟”标签。
4. 在 M8 中增加四种 claim kind 的分层评估，报告各类错误率，不合并为一个总分。
5. 对干预证据引入预注册、混杂因素、选择偏差和反事实识别审查。

## 研究边界

这是现代工程操作化，不是对古代“类”概念的唯一训诂，也不是已验证的类象智能能力。古籍文本、注疏、现代研究与项目假设必须保持来源分层。
