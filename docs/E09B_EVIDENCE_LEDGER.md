# E09-B2：追加式证据账本与冲突隔离

状态：实现已提交；尚待运行测试。  
分支：`research/e09-nongradient-learning-2026-11-10`

## 为什么增加账本

第一版 E09-B 的 `fit(examples)` 是无状态批处理：调用方必须重放全部样本；相同输入的矛盾标签会使拟合直接失败。持续学习需要保留证据历史，且不能让后到样本静默覆盖先前观察。

## 规则

- 每条观察必须有稳定的 `sample_id`；同 ID、同内容的重放是幂等操作。
- 同 ID、不同内容属于账本完整性错误，拒绝追加。
- 同一输入出现多个不同标签时，标记为 contested，并从训练集隔离；保留全部原始记录供审计。
- 同一输入重复出现相同标签时，保留全部记录，但训练时按输入去重，避免重复采样伪造独立支持。
- 只有无冲突的唯一输入进入学习器。
- 没有可用训练证据时拒绝拟合。

## 当前限制

账本目前是内存实现，不具备进程重启后的持久化、并发写入锁、签名来源验证或人工裁决接口。冲突隔离是保守策略，不等于判定哪一条观察为真。若任务本身允许同一输入产生随机标签，需扩展为概率/分布式标签模型，不能直接使用当前确定性分类器。

## 测试覆盖

新增 5 项测试：幂等追加、样本 ID 不可变、矛盾证据隔离、同标签重复去重、与 E09-B 学习器集成。测试执行结果待 CI/本地运行确认。
