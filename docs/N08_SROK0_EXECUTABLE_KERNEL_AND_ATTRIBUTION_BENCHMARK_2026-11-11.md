日期：2026-11-11

## 1. 为什么 N0.8 改变推进方式

检查 N0.7 研究分支后，发现仓库已经有多个实验原型：E01 稀疏组合、E02 高阶关系和生命周期、E13 类象结构发现、CSG-GCR 候选结构生成、ZPCM 存储及 ZNCA 核心。

因此，继续另写一套“全新 SROK”会造成重复。N0.8 采取两条并行路径：

1. 复用 E01/E02/E13/CSG-GCR 的已有实验与数据契约；
2. 新增最小独立 SROK-0 内核，验证类型角色路由、非相邻多元组合、预算控制和可审计输出。

实现 PR 基于 main，只包含可独立审查的原型和测试；研究 PR #177/#178 保持 Draft，不合并。

## 2. 本轮研究的新约束：证明高阶信息真的有贡献

2026 年 Bu 等人的 *Do Higher-Order Models Win for Higher-Order Reasons?* 提出高阶信息归因问题：模型表现更好，并不能证明它利用了高阶信息。作者通过扰动高阶信息、保留加权二元投影，在 25 个常用超图基准上发现，许多高阶模型的优势在扰动后仍大部分保留；更强的二元权重、更多传播步和归一化也能缩小部分差距。

来源：https://arxiv.org/abs/2610.07981

这要求 Zhouyi-AI 增加一个强制实验门：

**高阶结构的优势必须在保留低阶信息的对照干预下仍有可归因的增益。**

不能只做 Pairwise Graph vs Hypergraph 的普通准确率比较。

### 2.1 配对视图实验

对同一底层样本生成：

- H0：原始有角色超边；
- H1：保留全部节点、特征和加权二元投影，但破坏原始高阶分组/角色绑定；
- H2：强二元基线，使用与 H0 匹配的边权、传播轮数、归一化和参数预算；
- H3：随机高阶重连，保持节点度/超边阶数分布；
- H4：角色置换或角色错配，保持成员集合但改变角色；
- H5：oracle 真实结构，仅作上界，不参与训练。

如果 H0 优于 H1/H2/H3/H4，才有证据表明高阶分组或角色结构对任务有独立贡献。若差距消失，必须承认收益可由低阶特征解释。

### 2.2 两种任务必须分开

- 高阶冗余任务：答案可以从二元信息恢复。高阶模型不应被要求优于强二元基线。
- 高阶必要任务：任何单一二元投影都不足以区分正负样本，只有正确的多元角色组合可识别目标。

必要任务需构造严格 hard negatives：它们与正样本具有相同或高度匹配的成对关系统计，但整体超边分组/角色约束不同。

## 3. 非路径型组合基准

NeurIPS 2025 NoRA 指出，传统关系推理基准往往把推理简化为路径组合，无法覆盖离路径信息、歧义消解和多关系推理。

来源：https://proceedings.neurips.cc/paper_files/paper/2025/hash/167856a2bb094d44872c4a992bad49d0-Abstract-Datasets_and_Benchmarks_Track.html

N0.8 必须区分：
- 路径型：目标可由一条关系路径推导；
- 多路径型：需要合并多条证据路径；
- 离路径型：关键约束位于目标路径之外；
- 高阶联合型：必须同时绑定多个角色；
- 反事实型：改变一个关键成员/角色后结论必须改变；
- 欠定型：现有证据无法唯一确定答案。

## 4. SROK-0 最小原型边界

新增 `prototype/srok0_kernel.py`，定义：
- Node：带类型、标签、基础分数和 evidence IDs 的节点；
- RoleSpec：角色允许的类型与必要标签；
- OperatorSpec：关系类型、角色签名、每角色候选上限和最大扩展次数；
- SparseRoleComposer：类型/标签倒排索引、每角色稀疏候选池、最佳优先笛卡尔枚举；
- HardConstraint：完整候选的确定性硬约束；
- JointScorer：完整多元结构的联合评分；
- SearchReport：候选池大小、扩展次数、有效组合数和预算耗尽标记。

该原型是透明确定性基线，不是神经网络，不会自行学习类象，不会推断自然语言，也不维护持久认知。其价值是提供可测量、可替换的算法基线。

### 4.1 搜索保证与限制

每个角色先通过类型和标签倒排索引得到候选池，再按节点基础分数排序。堆搜索以基础分数总和为优先级，按预算扩展角色索引向量。

必须明确：
- 候选池上限会造成召回损失；
- 最大扩展数会造成搜索截断；
- 任意联合评分器可能改变完整组合排序；
- 因此本原型不声称对任意联合分数全局最优；
- 报告 pool sizes、expanded assignments、budget_exhausted，不能只报告最终答案。

后续若需要对任意高阶能量获得最优性保证，应研究 admissible upper bounds、branch-and-bound、约束传播或精确求解器，而不是把当前堆顺序误称为全局最优搜索。

## 6. SROK-0 的验收门

1. 角色类型不兼容的节点不能进入候选池；
2. required tags 必须全部满足；
3. 支持非相邻成员选择；
4. 一个节点不能同时占据两个互斥角色；
5. 硬约束拒绝后不得由联合分数覆盖；
6. 证据 ID 去重且顺序确定；
7. 候选排序稳定、可重放；
8. 达到预算时明确报告截断；
9. 候选池为空时安全返回空结果；
10. 重复节点 ID 和非法预算被拒绝；
11. 联合评分只作用于完整组合；
12. 明确声明该搜索不保证任意联合分数的全局最优。

对应单元测试位于 `tests/test_srok0_kernel.py`。CI 必须在 GitHub Actions 实际运行后才能标记通过。

## 7. 下一轮基准设计

### B1：候选召回与预算曲线
变化角色候选池大小、每角色上限和扩展预算，测量：
- 正确结构 recall@budget；
- 候选池召回；
- 扩展数；
- 峰值 RSS；
- 首个有效结构延迟。

### B2：高阶信息归因
对 H0–H4 配对视图做消融，分别报告性能差、置信区间和扰动后优势保留率。

### B3：非路径推理
构造离路径约束和多路径合并任务，与 NoRA 风格任务区分报告。

### B4：组合 OOD
训练/测试按关系模板、角色绑定和算子组合隔离，不允许只换实体 ID。

### B5：类象先验消融
比较无先验、随机先验、通用结构先验、易象算子先验和反向/错配先验。所有组匹配参数量、候选预算、训练数据和搜索预算。

### B6：增量修订
新增证据后只更新受影响候选和分支，报告局部重算比例、正确性和状态一致性。

## 8. 数据生成与泄漏防范

- 训练、验证、测试按规则族和结构模板分组，而不是随机拆分样本；
- 使用独立 evaluator 计算正确结构；
- 在训练完成后在线生成全新测试实例；
- 将生成器种子、规则版本、数据版本和代码 commit 写入结果；
- 保留失败样本、候选池遗漏和预算耗尽样本；
- 任何模型不得同时生成候选、生成 ground truth 并担任唯一评估器。

2026 年 ClosureBench 的预印本提出按程序执行生成新测试实例，以减少固定测试集记忆带来的污染风险。可借鉴这种可执行 ground-truth 思路，但不能直接把其结果外推到我们的任务。

来源：https://arxiv.org/abs/2608.18242

## 10. 本轮结论

N0.8 的研发策略是：**不再扩张抽象层，而是让现有理论进入可运行、可测量、可证伪的计算内核。**

先建立可靠的确定性基线，再用可学习路由、类象算子和连续潜在状态替换局部组件。每次替换都保留旧基线，采用同一数据、同一预算和同一评估器做配对比较。

只有证明：
- 非路径结构推理确有增益；
- 高阶信息具有独立贡献；
- 新组合可以迁移；
- 证据和反例能正确约束候选；
- 内存与计算成本可接受；

才值得进入更大规模的神经训练。
