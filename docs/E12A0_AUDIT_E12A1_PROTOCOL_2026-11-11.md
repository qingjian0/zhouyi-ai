## 1. 审查结论

E12-A0 是一个有限候选语法上的可辨识性与数据边界测试。它验证了：当两个候选谓词在当前 Support 上等价时，推断器应保留 AMBIGUOUS；当加入区分性观测后，可以在已知候选集合中唯一选择；当没有任何可用测量能够区分时，歧义必须保留。

它没有验证开放式基元发现，也没有验证自主选择实验、结构演化或通用智能。

### 已有实现的有效部分

- LearnerView 与 EvaluatorTruth 使用不同的数据结构，推断函数 infer 只接收 LearnerView。
- IDENTIFIABLE、AMBIGUOUS、INCONSISTENT、BUDGET_EXHAUSTED 四种状态均有明确返回路径。
- intervention_pending 场景先保持歧义，再由环境执行允许的 probe 并返回新观测。
- 测试覆盖真值变更不影响相同学习器视图的输出、未授权 probe 被拒绝、不可观测世界保持歧义。
- 语法、种子和输出范围足够小，适合作为协议单元测试。

### 当前边界与缺口

1. **候选谓词是手工给定的。** PRIMITIVES 只有 ge2 与 eq2，推断器执行的是枚举筛选，不是谓词归纳。
2. **干预不是学习器自主选择的。** allowed_probe_values 由环境直接给出；当前没有区分性价值评估、动作成本或主动测量策略。
3. **评估器隔离不是安全边界。** make_episode 在同一进程中返回 LearnerView 与 EvaluatorTruth。不同对象可以防止函数签名层面的误用，但不能防止进程内窥探。
4. **预算模型过于粗糙。** candidate_budget 只检查是否小于候选总数，没有逐候选计费、早停或报告已检查候选数。
5. **结果报告不完整。** run_suite 报告状态计数和干预恢复率，但没有逐 episode 预测、候选集合、覆盖率、错误自信率、计算成本和可复核清单。
6. **随机目标只用于构造场景。** 当前成功主要来自预先定义的有限语法与可区分观测，不能据此宣称模型学会了新语义。
7. **干预语义仅是标签查询。** 这不是因果发现；只有当动作改变环境或测量机制并观察到结果时，才可进一步讨论干预效应。

## 2. E12-A1 的目标

把“从已知两个谓词中选一个”推进到“从原始观测提出可执行候选谓词，并判断哪些候选具有可复用价值”。

E12-A1 仍使用有限、公开声明的候选 DSL，以便严格审计。它的创新验证目标不是开放宇宙中凭空创造意义，而是验证候选生成器能否从观测和任务反馈中提出训练前未被直接提供为标签的可执行谓词。

## 3. 最小世界生成器

每个 episode 由环境进程生成，包含：

- 原始观测通道：整数、二元向量、短序列和简单关系记录；
- 隐藏生成机制：谓词族、参数、组合方式及噪声；
- Support：学习器可见的观测与任务反馈；
- Gate：独立选择候选的验证样本；
- Locked Test：候选冻结后才可评分的样本；
- 可选 Action：允许执行的测量或干预及其成本；
- EvaluatorTruth：只保存在环境/评估进程中的真值。

生成器应支持 train/gate/test 的世界种子隔离，并导出不可变 manifest。不得把世界 ID、随机种子、真实谓词 ID、规则 ID或 Test 样本交给学习器。

## 4. 候选谓词 DSL v0

先限制为可解释、可执行的有限语法：

- Unary：阈值比较、相等、奇偶、区间、秩/分位；
- Boolean：AND、OR、NOT；
- Temporal：上升/下降、先后、持续时间、窗口变化；
- Relational：相等关系、差值范围、共同变化、简单角色约束；
- Contrastive：在正例与 hard-negative 之间形成最小可区分谓词。

每个候选必须携带：
- canonical expression 与 grammar_version；
- 输入类型、输出类型和适用范围；
- source_observation_ids；
- proposal_family 与 proposal_cost；
- 参数与不确定性；
- 训练支持、反例和失效上下文；
- candidate_version 与父版本。

语法枚举只作为透明候选生成控制组。后续才评估统计、时间、关系、对比式提议器能否在相同预算下减少搜索成本或提高发现质量。

## 5. E12-A1 对照组

A. Memorization：查表/最近邻。  
B. Fixed features：固定原始通道与手工特征，不创建谓词。  
C. Exhaustive DSL：在小语法中穷举，作为可解释搜索基线。  
D. Random proposals：相同候选预算下随机提议。  
E. Data-driven proposals：从 Support 生成候选谓词。  
F. Oracle grammar：使用生成器真实谓词，仅作上界，不计入可部署系统。

所有组共享相同 Support、Gate、Locked Test、动作预算与总计算预算。不能让某一组获得额外标签或环境元数据。

## 6. 主任务与指标

### T1 候选有效性
候选在 Gate 上的预测/压缩贡献是否超过固定特征、随机候选和简单基线。报告候选精确率、假发现率、复杂度和计算成本。

### T2 可辨识性
对 observationally equivalent 的候选结构，输出等价类和 AMBIGUOUS；只有在声明的测量分辨率下唯一时才输出 IDENTIFIABLE。

### T3 区分性测量选择
当存在多个可选 probe 时，学习器依据预期信息增益与成本选择测量。与随机 probe、固定 probe 顺序及 oracle probe 比较。若没有可区分 probe，应明确报告不可辨识，不得编造动作。

### T4 组合迁移
将已接受谓词用于训练中未出现的组合。分别报告已知谓词新组合与未见谓词族，禁止混为一个 OOD 指标。

### T5 反例稳健性
加入 hard negative 后，测量候选是否被拒绝、修订或缩小适用范围；同时统计无关候选被误改的比例。

必须同时报告覆盖率、选择性风险、错误自信率、候选数量、运行时间/操作数、峰值内存（若可测）及按 world seed 聚类的区间。

## 7. 主动测量选择

对每个允许动作 a，候选集合 C 在观测 o 下形成后验/权重分布。可先使用透明的离散版本：

- 计算动作执行前候选等价类的熵 H(C | D)；
- 对动作可能结果 r 估计 H(C | D, a, r)；
- 计算 expected_information_gain(a)；
- 按 information_gain / (cost + epsilon) 排序；
- 受总动作预算约束执行；
- 环境返回新观测，学习器重新归纳。

如果没有可信概率模型，先使用候选等价类分裂数量作为非概率启发式，并明确标注不是校准后的信息增益。禁止将启发式分数称为统计置信度。

## 8. 评估器隔离与泄漏测试

E12-A1 至少拆成两个进程/命令：

- environment/evaluator：生成世界、保存 oracle、执行动作、评分；
- learner：只通过序列化协议接收当前允许的 Observation、Action affordances 和预算。

必需回归测试：

1. 修改 oracle 真值但保持 learner 输入字节完全相同，输出必须一致。
2. 修改 Locked Test，不得影响 proposal 或 Gate 选择。
3. 在 learner payload 中递归扫描禁止字段和 canary 值。
4. 重排输入证据后，canonical 输出应稳定。
5. 同一来源重复证据不得被当作独立样本重复计数。
6. 删除关键观测通道后，系统应降低确定性或返回 AMBIGUOUS。
7. 不存在区分性动作时，不得报告已识别隐藏机制。
8. 预算耗尽必须返回 BUDGET_EXHAUSTED，并保留已检查候选数量。
9. 所有预测必须先于标签/结果揭示；反馈之后只能追加不可变证据记录。

对象分离是接口设计；进程隔离与序列化审计才是本阶段要求的边界。

## 9. 易象先验的接入时机

E12-A1 主实验先不使用易象先验，避免候选生成、学习算法和先验同时变化。

后续单独建立消融：
- 无先验；
- 通用二元互补/分区先验；
- 易象启发的二元/层级/状态转移先验；
- 容量匹配的随机编码或随机置换；
- 可学习先验。

易象先验必须能被数据拒绝。只有跨多个非同构生成器、严格预算匹配和独立种子复现后，才讨论其泛化增益。

## 10. 进入 E12-A1 实现的验收门槛

- [ ] 生成器、Support/Gate/Test 和 oracle 边界有版本化 schema。
- [ ] 至少 4 个谓词家族，且含噪声、缺失和 hard negatives。
- [ ] Learner 不接收真值、种子、世界 ID 或 Locked Test。
- [ ] 有 Memorization、Fixed-feature、Random-proposal 和 Exhaustive-DSL 对照。
- [ ] 可辨识、歧义、不一致、预算耗尽均有测试。
- [ ] 主动测量与随机测量在相同成本预算下比较。
- [ ] 至少 5 个种子先跑通协议；关键结论扩展到 20 个以上。
- [ ] 结果包括原始逐 episode JSONL、配置、代码 commit 和汇总报告。
- [ ] 没有把合成任务结果外推为自然语言理解、因果发现或通用智能。

**结论：** E12-A0 已经为“知道自己不知道”建立了一个很小的程序检查。E12-A1 的真正挑战，是让系统从观测提出新谓词，并用独立证据决定是否接受，同时能主动寻找区分证据。只有完成这一步，项目才开始触及原始基元归纳。
