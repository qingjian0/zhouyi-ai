# M27：统一类象声明图与跨模块失效传播 v0.1

## 1. 研究目标

M23—M26 分别审计观察形成链、类别边界、类间关系/推论权限和组合/涌现主张。它们的独立审计不能回答系统级问题：一个底层观察、文本见证、证据或情境版本被修订后，哪些上层声明因此失去依据？哪些仅需重新审查？哪些完全不受影响？

M27 定义统一的有向依赖图。节点表示观察、特征、类别、关系、映射、组合、主张、证据或情境；边表示某节点依赖另一节点。修订事件触发选择性传播，而非全图清空。

这是依赖账本和失效传播原型，不是语义真值判定器。

## 2. 古典理论边界

### 2.1 《墨子·小取》：推类链必须审查中间根据

《小取》不仅提出“以类取，以类予”，还区分辟、侔、援、推，并警告推类“远而失，流而离本”。同一结果并不保证所以然相同。M27 将其转为一个工程问题：推论链上的每个中间依据都必须显式可追溯；链条某处被撤销，依赖该处的后继主张不能继续无条件有效。

这只是现代工程映射，不等于《小取》提出了软件依赖图。网页转录与后世校勘材料须分层使用。

### 2.2 《周易·系辞上传》：变与成象的过程性

“参伍以变，错综其数。通其变，遂成天地之文；极其数，遂定天下之象。”其上下文处于蓍筮变数与成卦论述。可启发对状态变化、组合过程和结果之间关系的研究，但不应把“参伍/错综”直接训成现代图算法、数据库事务或依赖失效传播。

### 2.3 《荀子·正名》：名实、同异和约定标准

《正名》关于同状异所、异状同所，以及名实核验的讨论提醒我们：图中节点 ID、名称、分类轴与语义对象不是同一层次。节点重命名不能自动视为对象改变；对象证据改变也不能只改标签而不重审下游主张。

### 2.4 《淮南子》情境材料

先秦两汉类推材料多次显示同一对象随时、位、势、用而产生不同判断。M27 因此将 context_id 与 context_version 作为依赖条件。情境版本变化时，旧版本节点会成为失效种子；新版本节点不会因为共享 context_id 就自动继承旧判断。

## 3. 统一声明图数据模型

节点类型：
- observation / feature
- category
- relation / mapping
- composition
- claim
- evidence
- context

依赖边方向统一为 prerequisite → dependent。每条边声明：
- dependency_id
- source_id / target_id
- strength：HARD 或 SOFT
- relation：例如 derived_from、uses_evidence、uses_context、uses_relation、uses_composition

HARD 表示上游依据失效会使下游声明失效；SOFT 表示只要求重新审查，不自动判定失效。

## 4. 修订事件与传播规则

RevisionEvent 登记：
- 显式变更节点；
- 被撤销的证据引用；
- 情境旧版本到新版本的变化；
- 已完成重新审查的节点；
- 变更原因。

传播：
1. 显式变更节点、引用被撤销证据的节点、依赖旧情境版本的节点成为种子。
2. HARD 边传播 STALE。
3. SOFT 边传播 REVIEW，不继续自动扩散。
4. 同一节点经多条路径到达时，STALE 优先于 REVIEW。
5. 明确重新验证的节点成为传播屏障，表示它已基于新输入重新审查；其下游不应仅因旧路径继续被自动污染。
6. 未受影响的分支保留 UNAFFECTED。
7. 依赖图有环时拒绝传播，避免循环依赖造成不确定传播。

传播结果只是账本状态。REVIEW 不代表错误；STALE 不代表主张已被证伪，只表示当前依赖版本不再足以支持它。

## 5. 关键区别：证据失效、主张失效、语义反驳

- 证据撤销：来源、版本或可用性发生变化。
- 主张失效：主张依赖的必要前提不再满足。
- 语义反驳：有新证据支持相反解释。

三者不能混为一谈。M27 只实现前两类的依赖状态传播，不自动推断第三类。

## 6. 与 M14/M22/M23/M24/M25/M26 的连接

- M14 提供文本见证谱系与证据引用；M27 接收证据引用变化，不替代来源真实性审查。
- M22 提供情境版本修订账本；M27 把旧版本节点标记为失效种子。
- M23 的观察—特征—类别形成链映射为依赖路径。
- M24 类别定义/成员归属成为类别与成员节点。
- M25 关系、跨轴映射、推论权限成为关系/映射/主张节点。
- M26 组合与涌现主张成为组合/主张节点。

本版暂未实现从六个模块原始 dataclass 自动导入统一图；需要下一版增加显式适配器并保留原始对象 ID，禁止仅凭字段名猜测语义。

## 8. 下一步可证伪实验

构造有 gold dependency graph 的合成图与人工审定案例：
1. 单节点修订：比较系统传播集合与人工裁决集合。
2. 多路径依赖：验证 HARD/SOFT 混合路径的状态优先级。
3. 情境版本切换：验证旧版节点失效、新版节点不被误伤。
4. 证据谱系共享：撤销共同祖先见证，检查所有依赖它的证据/主张；仅共享派生文本的证据不得被错误计为独立来源。
5. 重新验证屏障：验证重审后的节点切断旧失效传播。
6. 局部恢复：新证据补入后，要求显式 revalidation，不允许系统自动把 STALE 改回有效。

指标：失效传播 precision/recall、误伤率、漏传播率、重审负担、传播延迟、版本错配率、循环检测率。应报告节点类型与边类型分层结果，不能只报总体准确率。

## 9. 不能宣称的结论

M27 结构审计通过不代表：
- 依赖边语义真实；
- 原典解释正确；
- 被标记 STALE 的主张为假；
- 被标记 UNAFFECTED 的主张为真；
- 该架构优于 Transformer；
- 图传播能替代人工文本校勘、标注和实验。
